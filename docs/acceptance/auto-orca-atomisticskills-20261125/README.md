## 评测设计

从官方 31 道题中，在评分前选定与技能说明重合的三个主题。IR 题要求识别实验谱并给出完整候选排序。构象题要求用 MACE-OFF23-small 松弛阿司匹林、几何去重，提交 298.15 K 布居及排序后的 SDF。热化学题要求用同一势的能量和振动，在指定温度计算气相反应的焓变、熵变、自由能变和平衡常数。其余 28 题未运行。[官方仓库与题目目录](https://github.com/learningmatter-mit/AtomisticSkillsBenchmark/tree/db6116c1833f30cccb65ff78cda175510c3107b6)

两组都使用同一版本的 Codex CLI、`gpt-6.2-sol`、medium 推理强度，每题每组各一次，串行执行。每次启动新模型会话和新任务容器。两组均显式关闭宿主的 `auto-orca` 条目，关闭宿主终端与网页搜索。带技能组额外获得七个冻结文件，并按用户点名技能的方式要求先读 `SKILL.md`。对照组只收到题面及相同的终端操作说明。题目固定的方法和温度在两组中相同。该设计检验显式选择技能后的表现，未测试自动发现技能的能力。

作答由宿主 Codex 通过限定到单个容器的终端完成。容器使用上游 Dockerfile 构建，断网，按题目设置 CPU、内存和总时限。工具记录保留在本地。每次提交后先冻结文件并计算 SHA-256，再将副本交给通过上游 Dockerfile 构建的独立评分容器，运行原版 `/tests/test.sh`。三个评分镜像都用空提交做过负对照。六次作答使用自建驱动。带技能组的 IR 答案另通过原生 Harbor 0.27.0 的产物收集和独立评分流程复核，其文件哈希与直接评分结果均一致。

## 从作答和评分日志看到的行为

IR 两组提交文件的 SHA-256 相同，首选物与完整排序两项检查均通过。两组都比较了题面提供的实验谱，带技能组还用 InChIKey 和规范 SMILES 核对了候选身份。热化学两组都在 CPU 上用 MACE 能量和 Hessian 完成了 650 K、1 bar 理想气体的刚性转子与谐振子计算，独立评分均通过。带技能组在结果中显式检查了内部振动频率。IR 和热化学的带技能组都读了技能正文和化学参考，但这两题的终端记录中没有运行技能附带的 Python 脚本。

构象题的带技能组实际调用了 `prepare_structure.py` 生成候选。它随后用 MACE 松弛并自行选择 0.065 Å 作为最终去重的 RMSD 阈值，比较重原子和羧基氢，同时保留镜像构象。它提交了 22 个结构。官方评分首先在构象数上限 5 的断言处失败。布居排序的内部一致性，以及 SDF 与 JSON 的一致性，两项检查均通过。0.065 Å 出现在模型为本题编写的后处理脚本中。技能的准备脚本在这次调用中使用的是 0.10 Å 的候选初筛阈值。

无技能组从 436 个初始几何出发，也将镜像极小点分别计数，最终同样提交了 22 个结构。两组最低能量均已通过摘要测试中先执行的参考能量断言。两组给出的前四个构象布居之和均约为 99.12%。上游记录说明，其参考搜索的嵌入剪枝会限制候选数，更广的采样可能找到额外极小点，因此官方保留了 2 至 5 的计数范围。本题能定位交付集合与参考范围的差异。进一步判定每个额外结构的物理等价性仍需独立的结构审查。[上游构象参考说明](https://github.com/learningmatter-mit/AtomisticSkillsBenchmark/blob/db6116c1833f30cccb65ff78cda175510c3107b6/tasks/chemistry/conformer-boltzmann-ranking/README.md)

## 证据与适用范围

七个技能文件的 SHA-256 均与本机安装版本一致。机器可读记录列出每次作答的镜像、提交文件、评分回执和终端记录哈希，并保留 token 用量与用时。模型服务未返回实付金额。原始作答、模型轨迹、官方 pytest 日志和评分回执位于评测机器的 `output/auto-orca-atomisticskills-20261125/jobs/<题名>/<with-skill 或 no-skill>/paired/`。[逐次运行记录](results.json)

预跑中有四个会话因终端配置未能执行命令。修复后另有三个试跑使用了可能显示技能一句话简介的宿主目录配置。正式两组统一显式禁用该目录条目，中性提示审计已验证简介消失。七个预跑全部单列，模型未收到预跑分数或评分器内容。项目配置的 DeepSeek 端点在连通性检查返回 HTTP 402，因此正式两组使用同一已登录的 Codex 模型。
