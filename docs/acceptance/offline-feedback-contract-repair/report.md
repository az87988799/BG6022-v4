## 真实 ORCA 结果

使用原固定 Linux 镜像、原共享环境租约，4 核、1024 MB 总内存、每进程 MaxCore 192 MB、环境并发 1。任务超时、脚本超时及每个 Run 的调用预算在 [运行前矩阵](validation-plan.json) 中记录。模型 profile=disabled、模型许可=false、调用/token 预算=0；测试子进程移除模型 API key，pytest 禁止外部网络。

| 开发者探针 | 实际结果 |
| --- | --- |
| HCN 原生 NMR 错误输入→同 logical 修复 | 非法 `%elprop Nuclei=all` 被 ORCA 拒绝；在同一 Run 原预算内换正确输入，完成 PBE0/def2-TZVP 计算并读取 3 个有限屏蔽张量。原 Attempt、Request 和失败计费不变。 |
| TDDFT 真实格式解析 | 1 次 PBE0/def2-SVP 计算正常结束，受管任务 Python 从真实 stdout 解析 5 个 `0-1A -> n-1A` 跃迁行。 |
| 极化率张量旋转 | 2 次独立 HF/def2-SVP 计算正常结束；主动旋转 37° 后，张量协变最大误差 **5.8062167×10⁻⁵ au**，另通过特征值及各向同性值只读复核。 |
| 构象 ID 与几何绑定 | RDKit 生成并保存 6 个候选，使用真实 conformer ID；2 次 HF/STO-3G 单点正常结束，其余 4 个按开发探针范围明确排除，不声称全局最低点或完整 T2 通过。 |

累计 **7 次 ORCA 预约，6 次进程确认的实际启动且正常完成，1 次已停止的快速语法失败未被进程采样确认启动**。7 份原始 ORCA stdout 均保留；不能用程序 banner 把未确认的 actual=0 改成 1。真实 Python 执行 3 次，均完成；真实模型请求始终为 0。

首批 pytest 为 **3 通过、1 失败**：NMR 测试原先假定快速退出也必然被进程采样捕获，因此在修复输入执行前停止。随后确认可信回执已证明工作负载停止、容器终止且完整归档，新增窄修复门槛与拒绝反例；unknown、活动进程、缺字段、handle 不符、零/布尔退出码仍拒绝。按[追加计划](native-followup-plan.json)，只继续原 Run 剩余的 1 次新输入，补测 **1 通过**，没有重新提交错误输入或增加累计额度。

[首批稳定源码及日志](orca-validation.json)、[同 Run 修复的稳定源码及日志](orca-resume-validation.json)分别保留。两批间的局部修复没有被拼接成“同一冻结产品完成正式七题”的声明。

原始字节归档：[首批 503 个文件](evidence/initial/index.json)、[原生修复后 107 个文件](evidence/native-repair-followup/index.json)，总计约 2.07 MB；索引记录逐文件 SHA256、大小及未随仓库发布的二进制。首次失败快照保留，后续归档不覆盖它。只读审计曾因内部文件键使用 Artifact ID 而漏计 stdout，修正审计查找为读取注册文件名后重新核验，没有额外执行 ORCA。

[独立只读审计](real-orca-audit.json)核对同 Run/同 logical、历史 Attempt 不变、预算未超、0 模型调用、7 份 stdout、6 次正常终止及环境租约释放。累计已知 CPU 下界 **69.831228 秒**，受管工作负载已记录墙钟 **80.314 秒**；cgroup 采样和收集成本不完整，不能当作精确总成本。仍无每 Attempt 磁盘硬配额。
