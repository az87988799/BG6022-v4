# 首个自然语言开发任务的独立核验规则

本规则在首次真实模型运行前保存。产品只接收专项方案的原始中文用例；开发驱动不填写 Plan、ORCA 输入、Python 或参考答案。开发参考不进入模型上下文。

- 核对请求原文、自动选型的检索来源、配置默认、实际提交输入、原始输出中的方法、基组、电荷和电子态；输入准入不代替输出核对。不认识的输出方法表示未验证，不猜测等价。
- 核对生成代码、输入、初始几何、最终几何、stdout、Hessian、回执与观察来源的 hash；逐次保留模型请求、生成错误、修订、成本和原始尝试。
- 独立检查正常终止、SCF/响应收敛和五项最终优化判据。它们分别记录，不能仅凭退出码确认极小值。
- 使用开发辅助 `tests/helpers/analytic_oracle.py` 读取原始 stdout、Hessian 和最终 XYZ。按相同原子顺序进行保持手性的刚性对齐，并比较原子间距离；坐标容差为 `1e-5 Å`。
- 比较 stdout 与 Hessian 的完整 `3N` 频率表，并由原始 Hessian 矩阵、质量和六个刚性运动投影独立重算频率；容差为 `0.006 cm^-1`，覆盖 stdout 两位小数舍入。保留虚频、近零模式和数值限制。
- 检查模型交付的核心能量、频率及其单位是否与上述原始证据一致；模型生成解析器不作为独立参考。能量按原输出精度核对，频率采用同一 `0.006 cm^-1` 容差。
- 独立检查不写回生产科学资格；生产观察仍为 `unverified`，`QualifiedOutput` 必须为空。频率专用生产检查缺项和单一初始结构的搜索范围须出现在交付中。

首次开发者原生探针的旧 oracle 因绝对坐标原点差异拒绝同一几何；已保留这一失败并改为物理上等价的刚性对齐。容差未扩大，也未为该修正重复启动 ORCA。首次真实模型任务从修正后的规则开始。

整批开发最多预留 5 个自然语言 Run、120 次模型调用、600 万 token、10 次 ORCA 启动和 2000 个声明内部工作量单位。失败与未知消耗不回收额度；先前独立原生探针的 1 次 ORCA 单独列账。该开发上限不构成后续步骤或正式跨任务验收授权。
