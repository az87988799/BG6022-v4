## 当前代码中还可简化的流程安排

- 新 SDK Python 计划要求初始几何已经准备/登记，不能仅凭一个尚未执行的结构准备依赖批准 SDK 步骤。这解决了执行到一半才发现缺几何的问题，但可能增加拆分计划的往返。可允许明确的准备依赖先入 Plan，在实际执行前检查结构已就绪。此处是代码审查发现的安排，不宣称已在新版本真实模型中复现失败。
- 最后一调用/决策轮自动收尾已修复；token/time 不足时仍使用保守预留和拒绝，尚未扩展为主动切换到较小的终局交付。
- 已讨论的上下文筛选不足及 4 个旧 12K 容量失败仍保留；完整存档与本轮发送给模型的信息应分开。

对应实现为 `tools/registry.py`、`semantic.py`、`proposals.py`、`planning.py`、`model_usage.py` 与 `context.py`；本次未同时修改这些约束。

## 不属于“约束太多”的失败

T2 的 `Bad Conformer Id`、T4 解析器没有匹配实际 ORCA 跃迁表、H1 的非法 ORCA 关键字均是真实生成代码/输入错误。取消协议约束不能使这些输入自动正确，仍需有效反馈和有界修复。

首轮准入版本与预约不一致、输入角色校验时点错误，以及后续误判几何条件、失败仍显示 ready、原生修复受阻等属于实现错误；已有修复，不能继续列作当前未修限制。

本审查没有运行真实模型、查询外部数据库或新增科学计算。建议实施后仍须分别验证流程可执行、结果完整性与科学检查覆盖。
