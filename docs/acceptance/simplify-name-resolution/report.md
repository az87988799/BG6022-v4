# 名称查询简化与额外约束审查

日期：2026-10-20。用户明确取消原名同义词/交叉引用精确匹配步骤，要求优先简化、跑通流程，并询问其他因约束过多导致的失败。

## 本次改动

新名称请求使用 `general-identity-3`。`structure.resolve` 只做一次受控 PubChem 性质查询；唯一候选及其 SMILES、分子式、形式电荷自洽，并通过明确附带分子式检查后，即可绑定身份输入和进入原有结构准备流程。不再请求 PubChem 同义词或 Wikidata。

用户原名、实际查询名和推断来源照常记录，`name_mapping_independently_verified=false` 明确表示没有执行额外名称认证，不伪造 `alias_verified=true`。结构准备检查实际原子、坐标和相关立体化学，仍不宣称生成的是优化结构或电子基态。

既有 v1/v2 身份契约继续走原规则，失败、检查、来源和预算不变；尚无身份契约的首次归一化采用当前 v3。不增加新的配置开关或分子白名单。工具定义、输入版本选择、模型可见规则与新默认保持一致，提示版本为 v75。

依据：[0054](../../decisions/0054-simplify-name-resolution.md)，现行总蓝图和 Code as Tools 方案已同步。
