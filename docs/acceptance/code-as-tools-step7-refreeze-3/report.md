### 已完成的计算与未完成的目标

T3 的首次 Python 因 ORCA `%maxcore` 与 Python `%` 字符串格式化冲突而失败；模型在同一逻辑步骤修复，第二次 Python 和六次内部 ORCA 均完成，内部证据收集无错误。最终七条观察的来源绑定检查通过，但仍为未获科学资格的观察。

六点完成后，下一次模型请求构建触发 `ContextLimitError`。具体被拒上下文大小和分段大小未持久化，本次未重建测量，不能精确归因到某一段。另一个独立问题是模型用 `repair_of` 简短修订且省略 `goal_map` 时，程序跳过被替换 Step 的旧绑定，再把七个目标补成 gap；模型没有明确删除这些路线。

即使修复上述两处，T3 也尚未完成整题：脚本自设 `TIME_BUDGET_S=950`，跳过 +180°，不是达到冻结父期限 1200 秒或 ORCA 总额度；加密候选 `[40.0]` 留待主循环决定但没有后续决定或计算；有相对能量数据而无曲线图。脚本报告的实际角与目标角不一致尚未独立重算，不能将来源绑定通过当作约束角或完整扫描科学通过。本轮没有真实超时收集边界的验证。

H1 的最终实际输入使用 `NMR` 简单关键词，`%eprnmr` 内没有先前出错的 `Nuclei` 指令，ORCA 正常结束并给出 C/N/H 三核总屏蔽张量和各向同性摘要。程序补入 `%pal nprocs 4 end` 的实际输入已被执行，原稿/执行稿及七个归档文件 hash 已核对。其余提取和交付目标仍缺证据，没有独立数值参考；不能把正常输出等同完整任务通过。

### 仍需修复的流程问题

1. **同一来源的重复表示仍过严。** T1/T3/T5/H2 中，正确的短引文和整段引用同时填写会被当作冲突。T1 还暴露通用 schema 与仅允许环境使用 `value_basis` 的运行时规则不一致。T2/H2 的特定措辞、位置或标签要求阻断了实际清楚的用户要求。T2 首次和 H2 首次的响应封装错误则属于真实模型格式错误，不能全部归因于约束。
2. **目标条件没有贯通后续流程。** T5 两个能量 Goal 已分别包含电荷 0、多重度 1、气相和 `CPCM(water)`、固定同一初始几何；后续条件消费却不从 Goal 补充空的 Request/system 条件，并要求几何准备 Goal 也满足条件完整性，导致可执行任务被路由到澄清/停止。
3. **修复没有自动保留原目标路线。** T3 的原路线属于同一个被修复的逻辑计算，但程序将其变成缺口，阻断已有结果满足目标。应保留原目标语义；不能通过减少目标来使修复通过。
4. **结果返回后的上下文仍过大。** T3/T4/H1 都发生实际输入容量失败，且总调用和总 token 预算尚有余量。不是供应商空输出截断，也不是 ORCA 算力不足。精确超限请求未发送、未保存，因此不能声称已经测得各区段占比。
5. **错误证据发现仍有多余往返。** T4 的 ORCA 输出明确报 `TDDFT` 输入错误，Python 未先检查失败回执而报解析错误。两次 `evidence.list` 原 Result 各列出 33 文件，但后续提示只展示前 18 项，真实内部 stdout 在省略部分；原始列表“完整”的标记与上下文分页标记并存。模型两次都请求 offset 0，还读了几何文件和结构准备回执，十次读取后未找到根因。修复入口存在，不能表述为程序没有修复能力或模型看见真实错误后无视。

本轮确实覆盖了四核输入补全、一次 Python 自主修复、六次连续内部计算的完整归档、一次直接原生 NMR 正常执行。它们是这些路径的真实证据，不能抵消规范化退步或替代完整自主成功。对新失败没有在本批中途改码或补跑。
