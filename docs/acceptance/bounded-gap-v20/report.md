## 修复范围

r2 真实 N06 暴露两个程序缺口：明确要求的电子能未形成 `energy` Goal，程序却接受仅有 `optimized_geometry` 的候选；登记通知被当成必须答复的缺项，导致 questions 为空而 Run 等待用户。[原始失败报告](../bounded-gap-r2/report.md)保留实际模型提案、Request 修订、独立审查及费用。

语义提交现在以可信用户原文的完整命题核对明确电子能要求，要求实际 `energy` 端口、必需状态、相应体系和已明确的几何关系。Goal 名称、reason、局部引用或几何端口不能替代物理量；漏项候选在 Request 激活前拒绝，程序不代写目标。仅要求优化后的能量时可以只保留 energy Goal 加 optimized 关系，不强制用户另要一个结构输出。

登记待答状态按规范 Request 的实际未知身份、关键字段及缺项导出。已知不支持、无几何和未指定显示单位仍作为事实告知；自由文本 `system:` 前缀不能自行制造等待。确需答复的登记缺项必须有合法关联问题，否则拒绝候选；已经声明的执行许可不因此改变。

同一覆盖检查处理否定、疑问、目标与溶剂角色、多个消息、明确撤回和目标替换。多个体系的模糊代词撤回不能删除全部要求；条件更改不能充当替换目标的授权，否定撤回也不能丢失既有目标。合法 N09 替换与保留目标路径均继续通过。规则是针对已复现表达的有限中英检查，不是通用自然语言理解保证，也不扩展科学范围。

新增端口说明只进入登记提示，提示版本为 `agent-json-v20`。N06 派生上下文配对构建的保守输入上界为 11032→11117，仍在 12000 内；新增说明为 85 个 UTF-8 字节。这不是模型实际 token 使用量。V06 终止上下文正文和 schema 未改，真实派生回放最高仍为 11983，仅余 17，不能推广为任意轨迹的容量保证。决策与替代方案见 [0015](../../decisions/0015-grounded-request-and-current-evidence.md)。
