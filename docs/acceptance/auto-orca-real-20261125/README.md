## 这次测了什么

本次在同一台机器上用 `gpt-6.2-sol`、medium 推理强度和 Windows ORCA 6.1.1 完成 3 道自选题。每题启用、关闭技能各运行 3 次，共 18 个新模型会话。每次从新的工作目录和同一份初始坐标开始。三次重复轮换题序，交替安排带技能组与对照组先作答。题面、输入、判分规则与运行顺序均在正式作答前冻结。技能只读，七个源文件与本机安装逐一核对哈希。[冻结协议](protocol.json)

| 题目 | 要交付的科学证据 |
| --- | --- |
| [水的固定几何能量差](tasks/energy/instruction.md) | 两次独立气相单点的 SCF 收敛、正常终止和电子能，给出带符号的 E(B) − E(A) 及单位换算。 |
| [甲醛优化、频率和红外归属](tasks/ir/instruction.md) | 从给定初始结构优化，在最终几何上做频率计算，判断局部极小点，用模式位移的 C–O 键轴投影确定羰基伸缩，并读出 IR 强度。 |
| [甲醛垂直激发态](tasks/excited/instruction.md) | 在另一份固定几何上算 6 个单重 TDA 根，逐根读取跃迁能和长度形式振子强度，区分最低能、最亮和近暗态。 |

每个 ORCA 作业使用 1 核，进程树内存上限 1 GiB，题设 `%maxcore 192` MB。模型会话上限为 720 秒，包含工具执行和允许的会话内修复。操作系统为每次工具调用建立独立 JobObject，记录实际映像、进程身份和成员关系。基准用四份原生 ORCA 输入独立计算参考值。自动评分同时核对原始文件、参考值和正式作答中实际出现的 ORCA 主进程。能量题要求两个主进程，另外两题至少各一个。终端和模型都收不到评分反馈。

两组使用同一隔离 Windows Python 工具，通过 `ORCA_EXE` 调用同一个原生驱动。LPAC 隔离下直接用绝对程序名启动时，ORCA 无法启动部分辅助模块。共同入口保持可执行映像为绝对路径，同时将传给 ORCA 的程序名改为相对路径，继承原始参数、工作目录、输出流和退出码。两种条件均用氦原子单点验证了这一入口。正式模型收到的唯一区别是带技能组获准读取并被要求使用 `auto-orca`。对照组无法读取技能文件、参考输出或其他作答，宿主提示也已检查不含技能简介。这项测试覆盖显式点名技能的情形。

完整通过要求科学检查、真实执行和交付均通过，并且另一位模型评审在隐藏组别的答复及证据副本中确认所要求的科学解释和引用。用时为该次 Codex 启动至退出的墙钟时间，含模型思考、读写文件、ORCA 计算与会话内修复。参考计算、环境准备及评分单独计量。九次汇总来自三个固定小分子任务，每题仅三次重复。

18 份答复的解释及证据均通过盲评。有一份答复主动提到技能脚本，遮蔽不完整。每组都有四份答复含指向临时模型目录的链接，审阅者通过交付的 `result.json` 相对路径核对了原始行。表中通过率衡量科学正确性和可追溯性，单击答复中每一个链接的体验没有单独计分。原始工作目录、输入和输出保存在本地 `output/auto-orca-real-20261125/jobs/<题目>/<with 或 without>/r<轮次>/`。本地 `evidence-18.zip` 汇集了 18 次作答和相应的原始文件及进程回执。

## 哪些步骤用到了技能

- **IR 归属。** 带技能的三次都实际执行了 `bond_modes.py`，在六个内部振动中找到 C–O 键轴投影最大的模式 9，波数为 1896.68 cm⁻¹，IR 强度为 114.78 km/mol。三次对照都现场编写了分析代码，得到相同归属。技能为这一步提供了现成的位移分析实现。第一次调用时模型给出了从 0 开始的原子编号，脚本拒绝后，模型改用从 1 开始的编号并完成分析。
- **固定几何。** 带技能的三次都读取了技能文档，最后都直接构造原生输入、调用 ORCA 并从原始能量计算差值。三个对照也算对了方向和大小。带技能组在此题没有执行附带的 Python 脚本。
- **激发态。** 三次带技能作答中，一次用 `orca_job.py` 启动作业，另两次直接调用原生 ORCA。六次作答都找到了最低能的近暗根 1，以及六根中长度形式振子强度最大的根 2。第一次带技能作答采用了脚本帮助声明可接受的 `singlets true`。ORCA 6.1.1 在 CIS 输入解析阶段报 `Unknown identifier`，终止于 `SINGLETS`。模型移除该行、保留 `TDA true` 和单重态条件，第二次成功。原始诊断在本地证据包中的 `jobs/excited/with/r1/work/jobs/attempt-1/job.out` 第 177–181 行。

组内实际读到技能正文的会话为 9/9，对照为 0/9。9 次带技能作答中有 4 次实际执行了至少一个附带脚本。Windows 捕获到两组的 ORCA 主进程数分别为 14 和 12。除激发态重试外，带技能组的第三次 IR 作答又启动了一次 ORCA，以在输入中显式写出 `TightSCF`。前一次 XYZ 模板作业已正常结束，两份输出里的 SCF 收敛阈值、归属波数和 IR 强度均一致。该次重复计算计入用时。对照组的 12 个已记录主进程达到三题所需的最低调用数，原始输出未见异常终止。

两组的隔离 Python 工具调用总数分别为 52 和 33。Codex 累计报告带技能组输入 1,999,315 token，其中缓存输入 1,788,928，输出 24,241。对照组输入 1,255,099，其中缓存输入 1,147,904，输出 17,598。输入累计包含工具交互中反复送入的上下文。接口未返回实际扣费金额。
