日期：2026-10-21（Asia/Hong_Kong）。依据用户本次“最根源最底层的修复、简化流程、删除冲突规则”的授权执行，[决定 0057](../../decisions/0057-repair-evidence-driven-workflow.md) 与总蓝图、专项方案已同步。

本次范围是修复 [refreeze-3](../code-as-tools-step7-refreeze-3/report.md) 暴露的通用生产链路，不改写原七项要求和原始失败。本文记录代码与离线回放证据；用户后续明确要求修复后进行真实 LLM 测试，因此另行冻结候选执行原七项各一次。修复验证阶段没有模型或 ORCA 调用，不将历史正常计算或本次回放记为新候选自主完成。

## 根因与修复

| 真实失败 | 根因与本次处理 |
| --- | --- |
| T1/T2/H2 来源与字段拒绝 | 同源片段与短引文可以共同定位；字段短引文继续约束数值，防止整段无关数字误认证。显式条件统一接受并验证 `value_basis`；精确 quantity 可补齐重复引文。移除计算与交付短语必须处在同一字符位置、派生几何必须套用单初始几何标签的门槛。 |
| T1/T2/H2 响应格式 | 仅归一明确的 `type=json_object` 元数据及裸 `request-semantics-3` 候选封装；未知执行字段仍拒绝，原响应保留。 |
| 小数条件误切分 | 分句器保留数字内部小数点，不再把 `298.15` 拆成两个来源片段。 |
| T5 条件正确但只能澄清/停止 | 统一解析目标、体系和请求条件；几何准备只取一致的电荷/自旋，非计算交付不要求六项电子结构条件。气相/水环境按各目标保留，执行必须匹配对应条件。 |
| T3 修复丢掉七条目标路线 | 同逻辑 `repair_of` 省略 `goal_map` 时继承原路线；保留端口和证据规则，使用新生产者，绝不把旧失败 Result 作为新结果。 |
| T3/T4/H1 上下文超限 | 完整请求包含消息封装一起测量；去重 schema 和观察来源，保留当前反馈、全部目标与原始记录的可查询引用。无法容纳时持久化各候选的分段大小和冻结上限。 |
| T4 Python 解析异常遮住 ORCA 输入错误 | 显式收集阶段将内部已结算失败、经归属/hash 校验的日志尾部和原 Artifact 引用加入父 Result。目录和分页显示实际遗漏及下一读取位置。 |

独立审查推动补充了三类边界验证：通用 Goal 路线不能借用另一体系 Step 的条件；能量阈值、次数和误差不能代替电子能，明确要求的电子能及能量差也不能遗漏；父 Python 捕获异常或上下文进一步压缩后，内部失败的身份和有效错误窗口仍须保留。路径脱敏不会改写原日志字节窗口，普通诊断共享有限投影预算。

没有增加按题求解 Tool、科学解析器或解答脚本。来源、值、条件和实际程序失败仍需核验；删除的是重复表达和错误前置门槛，不是把失败改记成功。未知执行不自动重跑，历史预算和每次尝试保持独立。

## 验证记录

开发期间，来源规范化相关六个测试文件 **202 项通过**，含 T1/T2/H2 九份原始响应的离线回放及来源错绑、否定、错误数值、纯能量差/自由能替代、删目标、未知执行字段等反例。内部错误与容量落盘相关定向检查也已通过。各定向数量可能重叠，不相加为总数。

首次完整统一回归为 **4,130 通过、26 失败、3 跳过**，耗时 1,668.875 秒，源码前后 hash 一致；[记录](integration-final.json)、[日志](integration-final.log)和 [JUnit](integration-final.xml)均保留。三项跳过为 Windows 符号链接权限相关两项及未启用的真实 OPI 准备冒烟测试。

其中五项失败暴露同一个本次生产回归：能量义务检查把“ORCA C-PCM 水环境下”也当成物理量名称，拒绝了已在显式条件中准确记录环境的原 T5 提案。修复通过同源、已验证的显式条件解释修饰语，未知变换仍不能替代原量；五条原测试及历史响应不改。其余 21 项为旧测试漂移：过期私有函数名、schema 注解/共享引用、已归一的传输元数据、旧错误文案、诊断文件布局，以及缺少已要求的 Python 执行声明/预算。更新测试副本并保留原始归档、权限和科学反例；没有为了测试通过取消执行预算或来源检查。

该修复的独立反例还发现原句复抄可以绕开环境核对，以及全局显式条件被要求重复到 Goal 的问题。最终实现把原句与简写放在相同检查之后，并在目标构造后使用已认证的新请求视图，复用执行端 `effective_conditions` 的 Request/System/Goal 优先级；不新建条件链，也不拿被覆盖的全局证据替代局部冲突。

25 模块的第一次定向复验在 117.922 秒时主动中止，[记录](repair-final.json)与[日志](repair-final.log)保留，源码前后未变，已运行部分未报失败；不能记为整套通过。独立审查发现后置环境被识别为直接能量后会绕过仅用于字面义务的条件核对，因此将精确来源短语和条件检查统一到所有能量义务的共同入口，再启动新的稳定复验。

第二次定向复验在 73.422 秒时主动中止，[记录](repair-final-2.json)与[日志](repair-final-2.log)保留，源码稳定且已运行部分未报失败。原因仍来自原 T5：拆分“气相与水环境下的单点能”后，前一条件因没有重复量名而未建立义务，删除 `gas_energy` 目标仍能提交。补齐并列条件共享量名的解析，再验证任一原环境目标均不可遗漏；不把中止记录改成通过。

第三次稳定定向复验为 **669 通过、2 失败**，25 个模块、411.156 秒，源码前后 hash 一致；[记录](repair-final-3.json)、[日志](repair-final-3.log)、[JUnit](repair-final-3.xml)均保留。一个失败是新回放测试使用历史 Run 的真实期限，现实时间经过后正确转为停止，测试改为冻结到原决策记录时间，保留原期限和预算。另一个是新临时 Request 的“至少一个必需目标”校验先于能量覆盖检查，导致原本可供模型修复的具体错误退化为通用 ValidationError；恢复全 optional 候选的既有能量覆盖反馈顺序，原负向断言不变。

最终稳定定向复验 **292 项全部通过**，5 个模块、99.078 秒，源码前后 hash 一致；[记录](repair-final-4.json)、[日志](repair-final-4.log)、[JUnit](repair-final-4.xml)。范围为逐目标条件、能量义务、真实规范化回放、观察环境和语义条件选择，覆盖最后两处改动及其直接影响。独立审查另复核这两处修正，4 项通过，无阻断问题。完整首次回归及第三次复验不改记为通过，其他已完成回归不重复记数。修改文件 Ruff、差异空白和已知凭据扫描通过，见[静态检查](static-checks.json)。
