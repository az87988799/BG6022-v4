# 纯文本、身份证据和初始几何接入

日期：2026-10-08。对应缺口闭合方案批次四、五；范围由用户“完成后续所有批次”确定。实现边界见 [决定 0018](../../decisions/0018-structure-input-bindings.md)。状态：代码和离线验证，等待用户验收；真实分层证据另行登记。

## 实际实现

`ask --text` 和 `ask --stdin` 复用现有 Request/Run/语义候选入口，原 JSON bundle 仍可用。只有本地配置显式启用 text profile 才允许该入口；示例为仓库根目录 `config.text.example.toml`。许可、资源与预算由配置冻结，模型不授予许可。配置默认值逐字段披露；原文声明、未知和冲突不能被默认值覆盖。未声明 SP/优化关系的能量问题保留缺项，可信后续答案才解除。有限名称识别支持水、甲烷；其他分子保留要求和不支持事实。无手工 XYZ 时，输入获取意图不再被误报为必须由用户提供文件。

`structure.resolve` 经显式 Step/Call 查询官方 PubChem PUG REST，固定字段、端点和有限响应，保留原始字节、来源、hash、规则和失败。水/甲烷按连接图、显式氢、形式电荷、同位素、立体及组分检查，不能仅凭 CID 或分子式通过。返回内容是数据，无权限效力。

`structure.prepare` 只消费合格身份，经锁定 OPI 2.0.0 / RDKit 2025.9.6 的 `Structure.from_smiles` 生成初始 XYZ。电荷/多重度显式传入，先检查结构状态一致性；不承诺未暴露种子的生成可复现。合格端口为 `prepared_geometry`，不代表优化结构或科学目标完成。失败时保留候选文件，未知执行保留预约与全环境租约。

成功输入通过 Run 局部绑定接入既有科学执行链。绑定涵盖 Request 版本、体系、用途、固定 Call、Result、Artifact 和 hash，每次消费重新核对；原 Request 和许可白名单不被准备成功改写。用户改条件清除当前绑定，历史证据仍保存。首份科学 Plan 冻结科学基线，前置 Plan 的后续修订照常计费，追加科学工作仍受原规则约束。

## 离线证据

- `test_structure_tools.py`：65 项通过，包含查询边界、结构图、异常/失败、控制锁、回执、候选产物、恢复及资源验证。PubChem 响应 fixture 明确为 synthetic。
- `test_structure_input_chain.py`：生产 Store/规划/dispatch 的文本到准备结构链、首次科学预约、连续恢复、旧版本拒绝、篡改拒绝、未知占用，以及模拟模型动作下的同一反馈循环。科学预约测试没有真实启动；反馈测试在 ORCA 前停止。
- `test_input_binding_safety.py`：13 项通过，覆盖伪造、跨体系/版本、复用、hash 篡改、未知状态和跨数据目录全环境额度。
- `test_text_entry.py`：CLI 输入选择、profile、受限名称、默认/明确/未知条件、后续可信身份和几何关系回答、禁止执行与只登记。

合并后的定向结果、干净 Windows 检出全量结果和跳过分类统一记录于后续整合验收报告；上述用例之间存在覆盖重叠，不把分次运行数相加充当独立测试总数。

## 尚未由此证明的事项

本报告不把合成 HTTP、替代生成器或模拟模型动作当作真实 PubChem、OPI、模型、ORCA 证据。真实取证、首次生成、固定几何独立参考及模型/科学重复按批次六独立安排，消耗沿用原账本。原阶段 B 的采样、修复和正式矩阵仍需各自验收；本入口不扩展分子、方法、电子态或科学保证。
