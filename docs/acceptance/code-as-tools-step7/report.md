## 固定范围与执行方式

产品候选保持 `5e6e9e38c7e24a10180d474bf95068692b7f9cca`，评测清单 SHA256 为 `819bfbdec67e30a6584ea925fe964123d50432e297d87c8ebdef9ff0e48244ab`。逐任务使用冻结原文与种子 1701，由真实模型自行规范请求、选择条件、生成 Plan、代码和输入；开发助手不提供解题脚本或修复答案。产品的运行时仍是一个 Agent 决策主循环。

[本轮驱动](run_first_repetition.py)仅执行准备、唯一初始 Run 绑定、既有 `execute`、采证和结算。每槽在新 Python 进程中执行，前后另用新进程核验冻结与 Docker 身份。任务失败保留在原槽；未知执行、异常、资料 hash 变化或超支会停止后续启动。未修改生产源码、工具、提示、冻结配置或评分标准。

专用启动进程将 `LOCALAPPDATA` 恢复到冻结事件对应的原桌面进程路径，以继续使用原共享环境根和账本；没有改持久系统环境或另建计算租约根。完整原值/恢复值、驱动 hash、时间及各 Run ID 位于本地批次 `data/code-tools-formal-batch/first-repetition-evidence/`。

每项固定上限为 24 模型调用、1,200,000 tokens、12 ORCA 启动、10,000 内部工作单位、7,200 秒。七项总预约上限为 168 调用、8,400,000 tokens、84 ORCA 启动、70,000 工作单位、50,400 秒；这些不是实际消费或预期费用。同 Run 的自主修复占原额度，单项失败不换 ID 补跑。

本轮暴露的主要问题：

1. **直接原生输入的版本契约不一致。** T1 的准入记录为 `native-orca-input-3`，冻结 `store.reserve_native_workload` 只接受 `native-orca-input-2`，在启动前拒绝。详见[只读根因分析](review/t1-failure-analysis.md)。这不是当前驱动恢复环境路径造成的；也不能据此推断 SDK 内部调用一定有相同故障。
2. **复杂请求规范化未能在有限纠错内完成。** T2、T3、T5、H1 三次提案后均有界停止。具体默认采用、几何关系、逐字物理量、最低证据/notice 等诊断逐次保留，不笼统归为模型接口故障。
3. **计划输入角色与执行消费约定不一致。** T4 已批准 Plan 使用 `resolved_identity` 键，而结构准备消费 `identity`，最终报 `preparation requires the qualified resolved_identity input`。本轮没有替产品补接输入。
4. **身份别名证据与目标保持问题。** H2 最终报 `lookup alias lacks independently retrieved PubChem name evidence`。另有六个目标被规范化为 `geometry_relation=optimized`，与原文固定几何/不分别优化的要求冲突。该批准后标签偏移已记录；实际优化或其他越权科学计算没有发生。

本轮只采证，不在任务之间修复冻结产品或换候选补挑成功。各次首次拒绝、自主纠错、最终失败及不可退款结算均保留。未来修复产品后应重新冻结并建立新批次，不能把新候选成功拼入本批次。

## 证据限制

本轮不启动独立参考，因而参考数值核验为 `unverified`；七项必需输出已确定缺失，所以任务总体评分为 `fail`，不能仅用“缺参考未验证”掩盖实际失败。T1 初始结构和部分任务身份解析的既有检查成功，不扩展为优化、频率、激发、屏蔽或极化率的科学通过。第二、第三重复、控制矩阵、真实集群与本轮真实 ORCA 数值均未验证。

冻结检索器保存完整正文的声明 hash 和实际返回片段，但不直接归档完整 HTTP 正文。本轮独立核对片段 hash、同文档/版本的声明 hash，并完成匹配正文的事后补档。没有发现同文档/版本的声明 hash 变化；补取时间不能冒充首次消费时间，也不改变冻结产品原本未存正文的事实。

产品在执行前保存 Request/Plan、代码与输入的事实，与独立评审是否在首次科学执行前完成登记分别核验。T1 已在首次 Attempt 前登记所选条件和拟输入；其他任务没有建立完整可执行科学设置，不能把“未启动任何计算前读到空计划”称为有效完成预登记。H2 的第二份已批准条件快照取得时 Run 已结束，其事后时序明确更正；没有实际科学输出可供其倒填。
