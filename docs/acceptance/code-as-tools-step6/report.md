## 任务、评分与预算

[公开任务](public-tasks.json) 固定 T1—T5 原文、必需数量、独立参考、同方法核对程序和逐性质容差。[独立保留题选择](holdout-selection.json) 在上述产品封存之后完成；评审为未参与产品开发的新 AI 评审，并非人类专家认证，记录了历史检索和新颖性理由。两项保留题的原文、参考和容差与公开题一样冻结，参考答案不进入产品上下文。

七项任务各三次，种子固定 1701/1702/1703，共 21 正式槽；另有 21 独立参考槽和 18 控制槽。完整上限与每槽 BudgetLimits 见 [batch-policy.json](batch-policy.json)，汇总及核验结果见 [validation.json](validation.json)。参考包含预定失败后重试，所有失败、自主修复及未知消耗保留在原槽，不补挑成功次数。上限不是预期用量，不构成本轮启动许可。

[评分规则](scoring.md) 区分执行、产品科学检查、独立评分、目标完成和报告完成。独立参考使用另一个干净工作区，先按预定规则冻结实际方法/输入/核对程序再计算，不由产品解析器验证自身。缺参考、资料变化、未覆盖边界、开发者介入或必需目标未完成都不能记为正式通过；独立评分也不会授予新的 QualifiedOutput。

[控制矩阵](controls.json) 覆盖代码修复、SCF 真失败与耗尽、缺项及最低证据、只读/后处理、成功反馈、取消/崩溃/恢复、跨 Run 并发和 OS 边界。成功反馈两支使用同一原文和同一预算，仅数值证据不同，预期动作保留在独立评分端；越界探针使用无秘密哨兵文件。

## 实现、验证和限制

新增辅助仅负责冻结核验、固定槽预约、账本与独立工作区准备，复用现有配置、BudgetLimits、Store 路径/锁和不可变写入。没有新增生产生命周期、科学求解器或通用评测平台。Run 由原生产入口创建后，辅助核验唯一初始壳与精确原文/许可/配置/预算，在任何模型或 Tool 动作前绑定。恢复沿用原 Run；所有槽共享生产全局环境租约，不能通过另建验收环境绕过并发 1。

本轮定向验证和必要 Store/配置回归的精确命令、结果、跳过项与清单核验见 validation.json。开发中发现并修复了未导入依赖漏检、完整细分预算未冻结、初始 Run 绑定顺序不兼容、可注入初始 Request、测试包入口遗漏，以及反馈对照原文泄露预期动作的问题；它们均属于验收辅助/规则修复，没有改变已封存产品。

默认离线测试禁止外部网络与科学进程。没有执行全量回归；Windows 真实 symlink 反例因创建权限不足而跳过，不声称该项通过。当前辅助不抵抗有权限改写全部源码、冻结证据和环境锚的恶意管理员；正式驱动必须遵循固定环境根和前后核验。每 Attempt 磁盘硬配额、资源采样下界、同程序参考不能替代独立科学软件或实验准确度等原有限制继续保留。

清单绑定本机实际路径和文件字节（包括换行形式），不是跨平台环境迁移包。新检出、移动路径或修改换行后须重新核验，出现差异就停止并明确重新冻结，不能仅凭 Git 提交相同跳过检查。

本轮项目模型调用、ORCA 启动、正式 Run 和参考计算均为 **0**。开发助手 tokens 和实际开发费用未计量，不作零声明。累计预算数值只完成离线验证，任务能否在预算内自主完成、真实方法适用性、失败修复及完整隔离矩阵留待步骤 7。操作顺序见 [runbook.md](runbook.md)；本轮完成不等于步骤 7 通过，也不等于用户已验收。
