## 原因与修复

原接口把 schema 压成字符串池/列编码，模型容易混淆参数形状及身份结果与几何结果；同时要求模型重复填写程序已有的依据 ID、条件参数。工具声明 geometry 输入，而计划使用单独 geometry 字段，也产生接口错配。

参照本机 BG6022-v3（`57f98d237f2a335b7042f43f4530cc370c17a814`）的语义提取与程序构造计划分工，以及 [smolagents 工具提示](https://github.com/huggingface/smolagents/blob/main/src/smolagents/prompts/toolcalling_agent.yaml)、[PydanticAI 参数验证](https://github.com/pydantic/pydantic-ai/blob/main/docs/tools-advanced.md)，v32 改为按当前动作展示原生 JSON schema。模型只提交 action/parameters/reason；程序从实际发送的冻结上下文绑定依据及反馈结果，从确认条件补齐 Tool 声明的参数和内部 ID，统一 geometry 输入绑定。显式冲突仍拒绝，执行许可和科学判定不交给模型。

同一 Agent、Tool 定义和生产执行链保留。未安装新的 Agent 框架；复杂上下文仍可使用原有有界投影，因此此次不能证明任意复杂输入均可靠。详见[决策记录](../../decisions/0028-readable-intent-planning.md)。
