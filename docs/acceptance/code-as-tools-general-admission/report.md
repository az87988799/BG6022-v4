# Code as Tools 通用准入清理

日期：2026-10-20。用户明确要求清理不合理限制并以现行专项方案为准。实现基线 `98b31322`，决定见 [0050](../../decisions/0050-code-as-tools-general-admission.md)。本次是执行范围与准备/分析门槛清理，未新增任务求解 Tool、科学性质端口或 QualifiedOutput。等待用户验收。

## 交付范围

- 新 Code as Tools 配置冻结 `managed-native-1` / `native-orca-input-3`，方法/基组标签开放，取消 H–Ar、气相、RHF/RKS 单重态以及强制 Opt+Freq 的样例限制。显式支持独立优化/频率、数值频率、有限约束/松弛扫描及响应块；原子数和迭代上限按新 Run 配置。
- 输入选择、修饰符与块参数全部保留。条件绑定、已知覆写冲突、显式依赖、资源及累计工作量继续校验；科学关键词有效性由 ORCA 决定，观察保持未验证。`%freq Temp` 明确单值记录为温度，多值保留数组，未指定不猜默认。
- 结构准备允许已确认的离子、自由基和指定立体结构，实际调用锁定 OPI/RDKit。身份查询可先于方法选择，之后通过原决策/Call/Result/hash 重新验证并复用身份；原产物和版本不改。
- 方法/基组选择仍须用户授权、官方来源、准确摘录/hash和理由，去除名称必须逐字出现的门槛。官方资料可在固定 ORCA 6.1 手册中按章节读取，不再局限少数预登记页面。
- 不同体系和条件可逐来源比较；Python 可以分析授权输入及既有直接 ORCA 输出，不要求分析时再次计算。温度等明确附加条件、来源缺失和最低科学要求不满足时仍报告缺口。
- 容器优先获取 ORCA 的可执行文件 inode、路径、PID/启动时间证明，再进行较慢的资源采样，退出前再尝试一次；未取得强证明仍失败，不以名称样本或退出码代替。

## 真实执行与失败

真实记录与逐项 hash、用量以 [live-probes.json](live-probes.json) 为准；由开发者编写小型探针，通过真实 `python.execute → SDK → 统一 ORCA 入口`，不属于真实模型自主验收。

固定镜像 `sha256:6641236074aa40af56505cfb92c6a8e0c2cc6b45f1407eccf39df640e5ec6e08`，manifest `40ec1ba664f9abb7200ade88e161c2156e031cb7c6e0c5c3b4ac44ae646f4c10`。环境上限 4 核/1024 MiB，每个探针明确使用 1 进程、MaxCore 192 MB；Python 与 ORCA 共享同容器 cgroup 和环境租约。单次脚本 600 秒、ORCA 300 秒、收集 180 秒；一次 ORCA/1000 声明工作单位，不盲目重试。

1. `live001` 首次开放壳层探针失败，宿主过长路径使证据收集失败；未覆盖失败或静默回退。
2. `live002` 使用短路径，ORCA 原始 stdout 正常结束且退出 0，但受管启动确认漏记，生产回执保留失败。随后修复强证明观察顺序。
3. `live003` 的九类实际 Python/ORCA 操作完成：F 原子 UHF 双重态；Ca²⁺/PBE；MP2/cc-pVDZ；CPCM(水)；TDDFT；独立 Opt；带明确温度的独立 Freq；NumFreq；二点松弛扫描。原 pytest 的九项终止断言错误地比较 Windows 写出的 CRLF 文件与内存 LF 字符串，记录仍为九失败，不能改称该 pytest 命令通过。测试现比较真实原文件字节；只读复用同一核验函数检查既有九组证据，不为这一断言重复科学计算。

只读复核九组全部通过，11 组源目录文件清单/hash 在审计前后不变；所有已注册 Artifact 的字节和 hash 已核对，环境租约均释放。累计 11 次 ORCA 预约、10 次有强凭据的实际启动、1 次未确认启动保守保留；九次操作完成、两次生产失败。累计声明工作单位 249，容器 CPU 已知下界 45.498525 秒（九次成功为 39.731358 秒），最大观测峰内存 503,783,424 字节。模型调用 0、科学资格新增 0。只读复核工具为 [audit_managed_admission_probes.py](../../../scripts/audit_managed_admission_probes.py)，调用时分别传入三个原始证据目录和目录外的输出位置，不启动计算。

以上只证明具体受管执行与可追溯原始证据，不证明所有方法/体系的准确性、收敛标准、激发态选择或完整科学目标通过；无新增科学资格。

## 保留的实际范围与未验证项

- 原生输入仍要求受管 `xyzfile`；任意自定义基组文件、重启、外部程序、多作业语法和未核算嵌套控制没有契约。原生通用策略不等于所有 ORCA 功能保证。
- 当前结构 Tool 仍要求一个连通图，SMILES 最多 2048 字符；RDKit 加氢前最多 128 个解析原子、加氢后最多 384 个原子，XYZ 最多 64 KiB。仅验证四面体和 E/Z 立体结构；嵌入算法可能失败，初始几何不保证优化或基态。任务代码的计算范围不等于这一准备 Tool 的全部能力。
- 温度单值仅在输入明确声明时有可信记录；标准态等没有原生可信字段时仍缺证，不声称所有附加条件完成。
- 没有真实模型调用、远程作业、Windows 科学复验、完整隔离攻击矩阵或步骤 6/7 正式同版本重复验收。进程资源成本仍为采样下界，每 Attempt 无磁盘硬配额。
- 旧 Run 保留策略、许可、预算、序列化及科学事实。主工作区同时存在其他任务的未提交改动，本次在独立 worktree/分支实施，不覆盖或混入那些改动。
