# 多次内部计算、稳定回执与任务检查点

日期：2026-10-19（Asia/Hong_Kong）。范围：[Code as Tools 步骤 4](../CODE-AS-TOOLS-IMPLEMENTATION-PLAN.md)。状态：已实现并完成本次定向验证，等待用户验收。

## 问题与选择

步骤 2 的单次 SDK 邮箱和共享原生工作目录不能承载多次计算。直接重跑整个 Python 会覆盖证据、重复计算并模糊预算；创建子协调者又会破坏唯一协调者和环境资源约束。

沿用当前 Run 协调者、环境租约和单容器聚合 cgroup。SDK v2 使用顺序编号、大小及次数有界的独立消息；每次 ORCA 调用拥有独立目录、启动门、输入和回执。任务不能指定宿主路径、命令、容器、权限或科学通过状态。旧 v1 请求仍按旧单次传输读取，旧 Run 不自动升级镜像或协议。

稳定请求键和输入内容指纹在 Run 内唯一。完成回执保存原始 Artifact 与 hash，可跨 Python Attempt 重新提供只读副本，不增加计算预算；同键不同内容拒绝。未结算、未知及失败回执均不得原键重新启动，失败修复以新键关联原失败。新候选、计划追加和失败重试分别记录并继承累计预算。原生输入内部工作量仍由同一准入检查决定。

检查点保存 JSON 状态、代码 hash、来源 Attempt 和已完成调用。需要模型判断时，SDK 结束当前 Python；协调者阻止该 Attempt 后续提交，Result 回到原有目标检查与计划影响判断。恢复不承诺 Python 调用栈或自动重放脚本；新代码显式使用检查点和稳定回执。检查点内容是任务数据，不授予执行许可或科学资格。

## 替代方案与验收影响

- 不采用嵌套 Agent、第二协调者、独立子计算环境租约或持久化 Python 调用栈。
- 环境并发仍限定为 1；大于 1 明确拒绝，不声称已实现多 Run 并行 CPU/内存分配。双 Run 竞争必须证明确实共享额度，Python 与内部 ORCA 仍共享一个聚合资源边界。
- 验证限定多次真实 ORCA、回执复用、检查点、取消/崩溃/恢复和反馈配对；离线反馈证据与真实科学执行分开报告，不消耗真实模型调用。
- 新 SDK/helper 需要新的固定镜像；历史镜像、Run、失败和预算不改写。既有磁盘硬配额及成本采样下界限制保留。

实际验证与限制见步骤 4 交付报告；本决定本身不构成能力通过证明。
