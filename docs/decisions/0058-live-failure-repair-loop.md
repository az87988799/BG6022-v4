# 真实测试驱动的持续修复

日期：2026-10-21（Asia/Hong_Kong）。

用户在 refreeze-4 的 0/7 结果后明确要求：一边真实 LLM 测试一边定位、修复根因，直到所有问题跑通；不要无意义的全量测试和回归。该决定替代 0057 中只执行一轮后交付的范围限制。开发过程不等同于原正式三次重复、独立参考和控制矩阵验收。

## 范围与执行

1. 按真实失败修正通用生产链路，优先消除有效输入被丢弃、声明与实际参数不一致、诊断被删除和已知预启动失败直接终止的问题。只运行直接重现与必要局部验证，随后立即进行真实模型测试。
2. 开发源码与正在测试的候选分开。每次真实尝试使用不可变候选快照、原任务原文、独立 Run、固定配置及实际镜像；下一修复可以并行进行，但不改变正在执行的版本。保存候选源码清单、原文 hash、父候选、失败与用量，不拼接不同版本宣称同一正式版本通过。
3. 原七题是固定开发回归目标。根据当前已知阻碍选择下一题；尚未越过的失败不无条件重复，先检查是否存在相关修复。最后逐题报告实际执行、科学检查、完整目标及其代码版本。历史失败、原始数据、配置和预算保持原记录。
4. 运行使用同一环境根和并发租约；隔离、输入 hash、未知执行对账、科学检查和用户最低证据继续有效。文件简称只在同一已结算生产者范围内唯一解析；不能搜索任意目录或按最新文件选输入。
5. JSON/计划/引用校验返回程序产生的具体字段与安全消息。已知预启动引用失败返回主决策循环，只有确认未产生任何新执行记录才可继续；已启动、未知或完整性错误仍须按原规则处理。
6. 已完成执行的状态按声明步骤与实际消费回执共同核对，不能把文件引用解析后的结构差异当成未执行。当前 Plan 中尚需分析的已结算计算保留原始证据索引，不能只因尚未绑定目标而在下一轮隐藏；这不赋予其科学资格。预启动拒绝的待决策状态持久化，同一 basis 的后续有效决定消费该反馈，重启不能重复选择失败步骤。
7. 当前输入的生成器、显式空随机种子、可复现性和保证范围进入有界数据视图；仅有来源 hash 不能代替这些会影响最终报告的限制。新观察的产物引用按精确名称去重并受冻结 Run 产物数、记录字节及总字节约束，取消额外 64 项门槛。目录概括只可展开为同条观察已经显式声明、同生产者且验证通过的精确子文件，记录原声明及展开依据；不遍历目录、不选择未声明文件，不改变 SDK 回执绑定或科学资格。
8. 历史请求的 EOF 语法诊断只在结构闭合后缀可被严格解析时指出缺失括号、有限字段名及仍须检查外层 schema 的提示，不自动补写。a016 实证同类失败后，新 v85 的极窄、可审计格式规范化由 [0065](0065-bounded-format-and-prelaunch-correction.md) 取代该旧限制，科学内容与许可不变。参数子模型的错误路径必须带 `parameters` 前缀，不能引导模型删掉外层必需字段。原始响应、拒绝和成本保留。
9. a008 实证纯元数据 Python 会被旧的“任何 Attempt 后禁止选择”门误当成科学执行，导致授权方法/基组永远待选。`simplified-1` 以真实执行事实冻结选择：纯准备和明确未启动、已结算的原生准入失败不能关闭待选；实际科学已启动或任何执行未结算/未知时仍禁止选择。呈现可提议动作不授予执行许可，提交时从原回执、身份与 hash 验证；原失败、固定条件、预算和旧工作流保持原记录。
10. a009 实际 ORCA 拒绝 `%eprnmr` 中的 `NMR true`；原生输入契约曾把该字符串放在坐标顺序说明中，容易被当成合法性质示例。删除该误导示例，明确顺序校验不提供科学字段语法；开放字段仍由实际 ORCA 验证，不加入硬编码任务求解器或自动改写。
11. a010 的初始几何 Goal 使用 `initial_geometry`，准备工具声明 `prepared_geometry`。只要求二者轮流改名会使模型反复纠错。绑定错误必须同时给出原 Goal 端口、生产者实际输出和真实可用路线；通用报告可通过显式观察适配器保留原物理量并提供来源。不得隐式把不同端口当成相同物理量或改变资格。
12. a010 的真实优化、坐标及完整频率已核对，但最终报告漏掉 Request 中模型已经记录的选型依据。报告必须直接呈现原选择理由及条件证据，不重新编造或要求重算。旧报告、旧状态和科学检查保留；修复后的独立补交需绑定原 Request、选择回执与报告代码版本。
13. a011 的分析已经归档 `task/job.property.txt`，观察收集器却重复拼接 `task/`，误报原件缺失。来源名在本 Result 的受控 task 文件键中精确、唯一解析，只去除一次目录前缀来匹配冻结输入的 `target_path`，并继续原输入到原生回执的来源链。不得遍历目录、跨生产者按相同 hash 猜来源或让普通任务副本自动获得原生证明；歧义、归属与 hash 错误仍拒绝。
14. a013 的已授权 RHF 方法与原默认 RKS 参考冲突，选择入口却先接纳、启动入口才拒绝且不能重新选择。按 [0063](0063-explicit-method-reference-inheritance.md) 在启动前统一协调明确方法与默认参考，保留原默认及派生出处，不覆盖用户明确条件或放松原生检查。

## 成本与退出

沿用每 Run 的实际资源及有限模型/计算上限，修复尝试不覆盖或退款。持续开发账本以此前五批已知用量（355 次模型调用、6,739,568 tokens、13 次 ORCA、11774.337 秒）为不可变起点，初始累计上限为 600 次模型调用、30,000,000 tokens、390 次 ORCA、858,000 内部工作量及 321,600 秒。2026-10-21 在 a014 结算、a015 已开始后，为执行用户“直到所有问题跑通”的持续授权，将同一账本的模型调用上限明确扩展至 1000，其余上限不变；保存原账本完整字节及 hash 链，所有历史实际与未知消耗继续累计，每 Run 上限不变，不清零、不退款。未知项保守占用，不另建账本绕过上限。新 Run 的局部格式纠正可在不扩大 Run 模型调用总额的前提下使用剩余额度，删除提前耗尽小额度却仍有充足总预算的重复门槛。

模型传输失败但已确认没有任何未决科学执行时，保留原 Run 和完整未知 token 预约，不重发原请求；排查后可在带传输类型诊断的新候选继续原任务。累计上限按已知用量加所有未知预约计算，不能把未知值改为零。只有异常类型、程序帧和请求 hash 用于诊断，不记录供应商异常消息、认证头或推理正文。

a012 连续格式失败后，按 [0062](0062-explicit-json-execution-profile.md) 在新候选显式采用现有非思考 JSON 模式；同一真实模型、原任务及所有累计成本保留，旧模式不改，模式差异单独报告。

历史正式批次的整槽预约/占用原样保留，不拿它们抵扣新尝试，也不把已结算但从未发送的调用上限记成实际消耗。本次用户另行授权持续开发，使用上述跨历史已知消耗、当前实际消耗及所有未知预约的统一累计计数；同一 Run 的上限和已用量不变。开发者执行边界验证同样先预约、后结算，纳入此累计账本并独立标注，不能冒称模型自主或独立科学参考。

退出条件是原七题均有真实模型和实际所需计算的完整目标证据，直接失败根因已经修正；或真实环境、累计预算成为无法继续的具体阻碍。未达到时不以局部测试通过或已推送为完成，不把未运行的独立数值参考记通过。持续保存进度，完成时提交推送并等待用户验收。
