# 有界模型上下文与正式评测身份

问题：真实 ORCA 输出与多成员来源链比简单单点更大。若整段输出只替换成 hash，模型可能看不到刚读取的值；若无界加入所有原始文件，则无法保证单次输入和累计预算。

决定：使用 registry 目录与必要参数 schema，保留独立用户目标、条件、许可、预算、当前版本及反馈 ID。查询投影保留已读取值、位置、单位、状态和来源；大值只提供显式标记的有限前缀及继续查询位置。采样投影保留实际坐标、能量、必需标记与缺口。不得把截短前缀当作完整原值。

当普通 JSON 超出保守输入上界时，采用可逆字符串引用与列式表表示；数据的信任级别仍由解码后的原位置决定。池中的字符串不会授予权限。当前版本依据与必须原样返回的反馈 ID 使用普通 JSON。只有具体已结算 Attempt/Call 证明已完成、且不能再修改的 Step 可以以持久 ID 与不可变内容 hash 表示；未执行或未知的 Step 仍保留完整执行信息。历史对象与原始证据不被重写。

完成目标后的解释请求使用仅允许 stop 的精简提示。科学成功仍由程序判断，解释不能改变结果资格。格式纠正、传输重发与科学修复分别计数；模型说明应引用真实科学尝试预算，不能把格式纠正次数当成 SCF 修复额度。

替代方案：无界原始上下文会破坏有限预算；只给 hash 会丢失必要观察；硬编码选择采样方向会替代模型决策；静默提高 token 上限会破坏冻结 profile。以上均不采用。过大的不可裁剪权威信息明确失败并保留确定性报告。

验收影响：同时验证三点分析、反馈后重规划、四点待分析及最终解释的实际长 ID/累计计数负载，而非只检查初始空 Run。开发调用保留旧提示和失败成本。正式评测先冻结代码、提示、配置和参考 hash；每个冻结标签的身份和槽不可重绑。修复后可建立新的明确冻结标签，历史冻结与失败轨迹保留，整批 600 HTTP、6,000,000 tokens、USD 10 和科学分类额度继续累计。

本记录不扩大科学范围、许可、预算或领域对象，不表示正式评测已通过。

真实开发探通还暴露了可见契约缺口：模型看到 `span_too_wide`，却不知道实际判定采用最近的已采样左右邻点及距离容差。Tool 定义增加可选 `check_contract` 描述，并由分析实现的同一契约函数提供；新分析 Result 同时记录生效判据，压缩上下文保留这些字段。它只公开现有规则，不修改容差、目标或科学通过条件，也不提供独立参考的预期方向或未采样能量。旧 Result 保持原字节。该字段属于 Tool 的局部元数据，不建立新生命周期。

v3 开发评测进一步显示公开协议与实际可执行范围不完全一致。v4 的 action enum 从当次 ACTION_PARAMETERS 生成；SP 使用同一局部参数类型同时声明与验证 300 秒上限；缺必需 Goal 或尚未获得 Artifact 的错误给出有界、程序生成的具体位置诊断。既有权限、一次纠正和科学检查不变。比较观察保留 Tool 实际记录的 source.conditions、expected_conditions 和 mismatched_fields，显式 null 保持未知，不用全局默认覆盖成员条件。六段解释格式仅迁移到响应示例中，不由程序替模型编写解释或补齐结论。
