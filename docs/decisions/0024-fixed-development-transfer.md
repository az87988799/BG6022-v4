# 第四开发候选的固定转拨边界

日期：2026-10-08。状态：操作工具已实现，具体增补待用户批准；没有应用到真实账本，也没有冻结或执行第四候选。

## 问题与选择

原修复周期限定三个开发候选，三者均留下实际失败。最新生产修复针对第三候选 V07 的调用选择和未来交付预算，不能用旧候选身份重跑或拼接通过结果。现有累计费用余额不自动授权第四候选。

保持三候选不变会阻止新版本真实验收；增加累计预算并非必要。因此准备一个仅供开发操作者使用的固定增补入口：从 gates-1 和 gates-2 未绑定部分转出合计 64 HTTP / 512000 tokens，给第四候选原有 13 门槛各一次机会。累计 2140 HTTP / 14746912 tokens / USD 20 不变。详见[具体提案](../reviews/2026-10-08-repair-cycle-development-4-amendment.md)。本决定和代码本身都不构成批准。

## 实现约束

原 scope、批准、限额授权链、绑定声明及实际费用保持原件；新增独立增补记录，保存原账本、实际批准及应用收据。各执行入口一致检查已应用的增补，原三候选关闭新绑定与执行。语法上能表示第四候选不代表已经获准运行；第五候选不在范围内。

新增分项没有 ORCA、查询或准备额度。第四候选全部 13 门槛通过后，才可使用原已授权、仍未使用的共享科学分项；其条件、预算和停止规则不变。不增加产品领域对象，不开放模型修改许可或调用这些操作工具的能力。

## 验证顺序与限制

用户最新要求停止正在运行的测试，集中完成剩余修复后只跑一次全量。中途不再为每个补丁重复全量；必要的定向检查单列。此前 v25 生产修复的 132 项定向结果有效，新增补守卫的首次定向会话未取得最终汇总，按未完成验证记录，不能称为通过。

最终应验证未批准拒绝、固定转拨、历史费用不变、中断后幂等恢复、旧候选关闭及科学门槛仍有效。静态审查和离线检查不能替代后续真实门禁、科学轨迹及正式验收。
