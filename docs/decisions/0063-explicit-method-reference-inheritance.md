# 明确方法标签优先于不相容的默认参考

日期：2026-10-21。依据用户允许 RHF/PBE0 选择并要求根本消除运行阻碍的当前授权。

a013 的真实模型已经选择用户允许的 RHF，但 Request 沿用配置中默认的 RKS 参考。选择入口接受该组合，原生入口连续两次以 `conflicting_condition:method/electronic_state` 拒绝，实际 ORCA 启动为零；方法又因已 auto_selected 不再可选。这是默认条件与已授权方法的契约冲突。

不删除原生兼容性检查、不把方法强制改成 PBE0，也不按电子数或奇偶性猜电子参考。已有 RHF 方法标签明确包含 RHF 参考的含义；新简化工作流在科学启动前，用同一纯协调函数处理方法选择及语义归一化入口。仅当电子参考确为与冻结配置及原证据一致的 default 时，可从已授权的明确方法继承其参考，记录 inherited、方法派生规则、原默认值/证据和方法授权来源。

用户明确值、未知、继承值以及 Goal/System 的独立参考约束不被覆盖；不相容时在接受选择前给出可操作的具体冲突。任意 HF/DFT 方法名不因此获得新的参考推断规则，科学资格不变，旧 Run 不迁移。

初始几何的实际依赖仍按准备工具契约核对。相同电荷、重数和身份下的方法参考协调不得暗中撤销已验证初始几何或强迫重新生成；电荷、重数及真实分子条件改变仍不能套用原资格。新请求和执行的实际条件完整保留。

直接验收使用 a013 原记录的只读内存提交、默认继承正例、用户明确/未知/体系约束负例、已开始科学执行拒绝及显式 RHF 语义归一化同根用例。随后立即继续原任务真实模型测试，不用离线回放冒充真实成功。
