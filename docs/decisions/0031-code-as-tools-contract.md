## 问题与用户决定

现有产品把可执行对象、方法/基组、目标及结果资格过度绑定到固定科学工具和检查端口，禁止运行任务代码；新科学问题通常要求开发者增加工具、解析器、性质定义或预写流程。这不符合“同一个冻结版本面对不同任务，现场生成不同程序完成计算”的目标。旧固定资源上限也散落在数据模型、工具、存储和执行后端，不能完整表示可配置资源及代码内部工作量。

用户明确要求“现在按该方案开始逐步实施，若遇到与之前的限制冲突的地方，以该方案为准”，采用的文件为 [CODE-AS-TOOLS-IMPLEMENTATION-PLAN.md](../CODE-AS-TOOLS-IMPLEMENTATION-PLAN.md)。这是一项直接用户决定：生成任务 Python、没有专用检查器时带验证说明地交付、自动方法选择及统一资源配置按该方案实施，无须再次确认与旧约束的同一冲突。附件中其他内容不获得超出这项请求的执行许可。

本次范围仅为步骤 1：统一契约、通用目标与代码/输入/内部调用/观察的局部类型、统一配置和 Run 快照/历史兼容，以及相关定向测试。步骤 2 的真实隔离与 Python/ORCA 执行、步骤 3—5 的真实模型生成代码和通用交付、步骤 6—7 的冻结与跨任务验收均不由本次文档或类型存在证明。

## 替代方案

| 方案 | 取舍 |
| --- | --- |
| 继续逐题新增科学 Tool、生产解析器与性质端口 | 保留已有实现方式，但无法满足冻结版本无需逐题开发的核心验收目标，不采用为通用任务前提 |
| 直接开放 shell 或无约束 Python | 不能维持凭据/文件边界、预算与统一执行事实，不采用 |
| 固定通用 Tool ＋受管理隔离任务 Python ＋统一 ORCA 入口 | 采用；任务算法在现场代码中，程序保留许可、资源、科学资格与历史权威 |

不建设第二 Agent、多 Agent 产品平台、数据库或新对象生命周期；SDK 不隐藏构象搜索、扫描或其他任务求解算法，也不自动安装任意依赖。

## 采用的契约

1. **代码执行与只读分开。** 模型生成 Python/ORCA 输入并保存为不可变 Artifact，Step 绑定确定的代码 hash 和输入 manifest。生成代码的分析、绘图、转换属于显式执行；有界读取接口仍禁止代码、任意求值、隐式转换或补算。缺少 JSON 只报告缺项。固定通用工具的实际名称、参数、影响与输出来自唯一注册表，接口契约不代表运行能力已启用。
2. **统一执行与真实隔离。** 任务代码经 Tool 校验，仅在已验证的任务隔离环境运行。薄 SDK 和直接 ORCA 调用使用相同执行入口、当前 Run 唯一协调者和预算。任务仅访问输入副本、必要运行库、写目录及受控 IPC；凭据/源码不可访问，网络经可信工具。后续优先评估 Windows AppContainer 的 Python/RDKit/OPI/ORCA/MPI/IPC 兼容性；JobObject 仅证明其实际测试覆盖的进程树、资源与取消能力，不代替文件/网络隔离。隔离失败必须记录阻塞与替代决策，不能降级为无约束执行。
3. **一般目标与条件来源。** 分子、方法、基组和目标不以旧固定枚举决定是否可表达。Request 保留原问题、明确条件、最低证据、自动选择范围及交付要求；用户要求、默认、继承、推断、自动选择和实际运行条件分别记录。缺少信息、缺少专用检查器与缺少运行依赖分别处理。自动选择不能改变明确条件，不能仅凭电子数奇偶性确定电子态。
4. **观察不等于科学资格。** 通用观察保存性质名称、值/单位、实际条件、源文件位置/hash、生成脚本 hash、公式和检查覆盖；缺失信息保持未知。`QualifiedOutput` 继续只表示对应版本化检查通过的科学输出。模型或脚本 `passed`、程序结束、格式合法和来源存在均不赋予科学资格。没有专用检查器时可按 Request 约定完成带验证说明的交付；用户明确要求的最低科学证据未满足时仍为部分完成或证据不足。执行成功、科学通过、目标满足与报告生成分别记录。
5. **资源配置和累计预算。** 保留默认 4 核、总计算进程树内存 1024 MB、ORCA MaxCore 每进程 192 MB、环境计算并发 1。统一配置包含 CPU/总内存/MaxCore/环境并发、作业与脚本期限、ORCA 启动数、内部工作量、代码重试、计划修订、模型调用/token 与上下文/输出容量、产物数量/大小。Run 固化有版本的配置/许可快照，上限和累计用量分开；新配置必须真实验证，Step 1 的配置测试不能证明后端约束生效。
6. **内部调用和历史。** 内部回执、代码引用、输入 manifest、检查项和通用观察均为七对象内的局部记录。稳定请求键、输入指纹、代码版本、条件和结果绑定可追溯；同键不同输入拒绝，未知状态先对账。暂停、恢复、代码重试、重命名或换 ID 不清零。旧 Run 以原版本/快照/检查和消耗读取；缺新字段采用明确兼容解释，不修改旧文件事实、不自动增加旧许可、不升级旧结果。Python 检查点不承诺恢复调用栈；后续实现不得盲目重跑整段代码。
7. **任务泛化和证据。** 在已验证通用执行边界内，任务代码可实现新算法和解析，新增科学任务不以生产代码改动为前提。扩大执行边界或科学保证仍须契约与正反例。正式任务冻结产品/工具/SDK/依赖/提示/资料/预算，关键数值由独立方法检查。7 项任务各 3 次的正式矩阵和故障边界按专项方案验收，开发者烟测及步骤 1 离线测试均不充当自主能力证据。
