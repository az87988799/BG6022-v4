# 在新冻结策略中自动整理核性质块顺序

日期：2026-10-21，依据用户消除真实失败根因、简化流程并清除冲突旧规则的当前授权。

a016 与 a017 的原始 ORCA 输入均把核性质 `%eprnmr` 放在坐标之前，原生适配器拒绝后，模型多次只改外层 Python 或误选文件，仍未产生真实 ORCA 计算。该顺序是 ORCA 解析要求，不是新的科学选择；让模型为此反复重新编写、绑定及修复文件是可消除的阻碍。

仅新 Run 可显式冻结 `native_input_policy.property_block_order='coordinates-first-1'`；默认 None 并省略历史序列化字段。旧策略、旧运行不升级。此字段只允许 managed-native-1，通过 OPI/原生/SDK 共用的现有原生准备入口生效，不新增科学工具、求解器或主循环分支。

仅对已被现有解析器完整识别、唯一且确实请求核性质的顶层 `%eprnmr`，在存在唯一合法 `xyzfile` 声明而该块位于其前方时，将整块移到坐标后。块内科学内容保持，其他顶层单元相对顺序保持；已后置或不属于该情形时不移动。不得靠正则猜测块尾，不插方法、基组、性质、数值或其他科学设置，不修改几何或科学条件。重复、截断、嵌套、多个坐标及未受管输入仍拒绝；最终必须经过原有依赖/hash、资源、条件和原生执行范围校验。

原输入 Artifact、`source-input.inp`、源/最终 hash 继续保存；材料化回执分别记录控制字段补入与整块移序规则、位置和块 hash。新策略对未编辑行保留原内容，不能把既有受管控制补入误称为“最终输入仅顺序改变”。排序本身不证明 ORCA 接受，也不授予科学资格。

验收只重现 a016/a017 实际输入、旧策略拒绝、新策略移序后准入、同一准备入口保存原文与差异审计、已后置无操作和非法边界；随后进行新 H1 真实模型及实际 ORCA 测试。T3 等不消费本策略的原题可在此前固定候选上并行推进，执行仍受同一环境并发额度约束。
