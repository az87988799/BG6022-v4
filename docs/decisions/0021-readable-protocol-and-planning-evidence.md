# 协议字面量与规划证据的可读性

日期：2026-10-08。依据用户采用的修复方案第 8–10 节，在修复周期第一开发候选的真实 V06 失败后继续修补。沿用蓝图 P03、P05、P09、P14、P17，不改变领域对象、Tool 权限、科学判据或已批准预算。

## 实际问题

冻结提交 `8ae3fd2`、提示 `agent-json-v22` 的 N06 首答和 V06 两答均含未声明的根字段 `type=json_object`。N06 一次纠正后完成登记；V06 的一次纠正未去掉该字段，两个候选均被严格 schema 拒绝，没有终止收据或科学执行。V06 还把 `terminal-delivery-1` 字符串常量错误写为整数 0、1；该常量在发送上下文中通过字符串池表示。原始响应及失败保持不变，见[第一候选证据](../acceptance/repair-cycle-development-1/report.md)。

V06 第二答交换了中点和右点能量，错误声称没有内部最低采样点。原始绑定实际上是中点最低，但相邻采样点跨度约 0.16 Å 大于 0.12 Å 加容差，原取得目标仍不满足。候选还声称只能停止，忽略了仍被允许的一次既有证据分析。实际上下文仍正确列有 `initial_plan`、分析 Tool 及其额度；无 Plan、无分析 Result 时的 delivery 仅包含当时未绑定的目标事实。

这些证据证明模型输出失败，不证明序列化丢失事实、供应商向模型暴露了 HTTP `response_format`，也不证明压缩是唯一原因。行列压缩、跨表成员连接以及规划时的终止解释选项是需要改善的呈现因素。

## 选择与替代方案

在现有 context 和协议边界内修复：输出对象明确沿用 `Proposal` 派生的闭合字段；关键协议常量保留可直接读取的字面值；安全纠错说明与原错误类型、路径一致。模型仍必须自己提交正确答案，不剥离多余字段、不替换版本、不重写自由解释后冒充原答。

规划用途明确区分：当前 delivery 中的下一步引用用于选择 stop 时的解释，完整可执行动作仍由当前 decision purpose、Tool 目录、许可和预算共同决定。禁止新科学计算不等于禁止已获许可的证据读取或分析。不增加按具体科学工具名称分支的 Agent 逻辑。

成员身份和能量来源应在有界上下文中保持直观关联；必须保留完整原值、单位、来源、未知条件及全部必需成员，不通过删事实或提高 token 限额换取容量。序列化测试证明对应关系保持，不能证明模型必然理解正确。

具体取舍是保留 `available_evidence` 的成员键与其能量、来源绑定相邻；候选坐标仍可使用同一行包含 ID、距离、角色和 hash 的既有列式表示，不按位置拼接两张表。仅在不含规范化动作的 planning 用途中，可省去 `semantic_defaults` 候选模板；它只供规范化展示和校验可选默认值。当前有效条件、默认来源、`condition_evidence` 及完整 Request 均不改变，重新进入规范化时模板必须完整出现。这是有目的的投影，不宣称输出含 Request 的每个原字段。

同样限定于携带交付快照的紧凑 planning 投影，可省去 `SCHEMA_SHA256` 和 `immutable_frozen_details_sha256` 两个可重建的展示摘要。完整 schema 仍在本次请求中，冻结 Step 原件仍在同一 Run 的不可变 Plan、Call/Attempt 中；当前 Plan 版本、已完成 Step ID 及冻结标记仍可定位原件。执行冻结校验使用原 Step 的精确比较，发送及终止接受依赖实际请求字节、当前 basis 和 sidecar 指纹，均不消费这两个展示字段。历史投影、规范化及终止投影保留原表示；任何 Result 来源 hash、科学值、检查、预算或交付指纹都不因此删除。回归必须比较展开后的 schema 及原始 Plan 内容，不能把删除摘要断言当成验证。

字面量共享继续使用既有编码及转义规则。候选选择比较实际子编码成本，并以完整编码后的字节数择小，避免共享父对象反而重复其子串。此项是无损表示选择；上文按用途省去模板与展示摘要属于明确投影，两者分别验证。

提示升为 `agent-json-v23`。已引入的用途校验、发送前合同和终止快照要求必须同时覆盖 v22、v23；不能让提示版本升级绕过守卫。历史记录只读与原费用不迁移为新候选结果。

不采用放宽 schema、补造分析 Result、让程序替模型选择 V06 工具、同槽换 Run 重抽、只重跑失败槽或把确定性报告计为模型解释通过。

## 验收影响

保留真实错误原答作为可在干净检出读取的反例，另行标明合成正确对照。定向验证包括未知字段拒绝、版本常量、允许动作、无 ORCA 许可下的已授权分析、成员对应及三点判据；新旧提示版本的缺用途和缺终止快照均须在 HTTP 前阻止。容量验证仍受原 12000 输入、2000 输出及 Run 总额约束。

完成实际补丁、反例回归、提交和干净离线验证后，才能冻结第二开发候选。第一候选的 N06 通过不能拼入新候选；新候选需重新完成全部 13 门槛，之后按既有方案继续分层、自主输入链、原剩余行为和完整正式验证。本记录没有扩大预算或执行范围，也不声明修复已验证。
