# 0020：有限采样判据检查与取得达标证据分离

日期：2026-10-08。状态：按用户详细修复方案 §7.2 实施，真实验收尚未完成。

用户要求的“检查已有证据是否达标”可以有完整的否定答案；“取得达标证据”在同一判据为否时仍未完成。
不能在报告层凭 intent 字符串把原 sampling Goal 改成通过，也不能修改旧 V06 的 Request、阈值或评分。

增加局部 Tool `analysis.sampling_check`，输出端口 `sampling_check`，检查版本
`finite-sampling-check-1`。它调用原 `finite_sampling` 一次，复用全部几何、来源、条件与数值判据。
只有所需成员均合格、所有候选几何和科学条件有效，且结论为
`sufficient_discrete_evidence`、`span_too_wide`、`boundary_minimum` 或
`not_numerically_distinct` 时，才产生“判据检查已完成”的受检分析 Artifact。
缺失必需成员、损坏来源、不支持或冲突条件均不能产生该输出。

分析 Artifact 明确记录 predicate_satisfied、原科学判据版本和原判据检查。
否定检查输出不发布 `sampling` 科学合格端口；正面检查同样只发布检查端口，不用它绕过取得目标的绑定。
`analysis.finite_sampling` 及既有 `finite-sampling-1` 保持原行为。
Tool 内部的 `checked_artifact_outputs` 只是固定分析产物生成后的局部输出描述，不拥有独立生命周期；
dispatch 校验已声明端口、检查名称和版本后绑定该次 Call 的分析 Artifact。
主循环不增加科学工具名分支。

规范化只区分明确的检查与取得意图。采样候选、阈值等必须来自已登记的 Request 条件；
模型不得补造几何或阈值。可引用本 Request 已冻结的采样目标条件；没有完整规格时保留缺项并澄清。
新意图不追溯迁移旧 Goal。否定、疑问、混合多目标与后续修改继续按原可信消息边界验证。

验收覆盖检查为真、检查为假、取得为假仍未完成、必需成员缺失、来源变化、两种目标不能交叉绑定。
这六个新增正式变体各重复三次，共十八槽；其中三个真实模型语义变体的每轮预留为
36 HTTP / 432000 tokens，其余三个为离线规则边界。它们全部零新增 ORCA。
每个真实变体先由实际模型规范化可信用户修改，再提出分析计划、读取冻结证据并提交终止解释；
测试 harness 不预选检查/取得 Goal 或 Tool。每 Run 最多 4 HTTP / 48000 tokens，正常三次请求按
PreparedRequest 输入界加输出界逐次完整结算。最多一次纠正仍受实际上下文与余额限制，
不保证拒绝后剩余所有阶段均可完成；无法预约时保留失败与确定性交付，不提高上限或启动昂贵 Tool。
矩阵和预算工具按实际最坏合法序列核算，不能借改变测试类别或降低科学规则消除增量；
若旧分项不能有依据地收紧，必须明确记录差量交由修复周期预算处理。

离线测试、真实模型解释、真实 ORCA 和用户验收分别记录；本决定不声明任何新真实通过。
