# 在既有总资源上限内简化工作流额度

日期：2026-10-21，依据用户持续修复直至原七题跑通、清除冲突旧流程限制的当前授权。

原开发配置沿用早期用例的 12 个逻辑步骤、24 次模型调用、4 次分析、2 次代码重试及 12 次计划修订。T3 的七次原生计算若分别使用写入和执行步骤，再加准备、主循环粗扫反馈与最多两次细化，就可能超过这些机械额度，尽管 12 次 ORCA、10,000 工作量、7,200 秒及 1,200,000 tokens 的总额度仍充足。反复新建 Run 不能作为清零或绕过办法。

后续新开发候选显式冻结：逻辑步骤 32、模型调用 48、决策轮次 80、计划修订 32、分析执行 12、代码重试 11、每逻辑/输入尝试 12、证据读取 24，局部格式纠正不再早于模型总调用额度耗尽。其余资源、实际 ORCA/内部工作量、总时间、模型 tokens、产物及统一 campaign 上限均不扩大；完全相同失败输入继续禁止重试，未知执行继续保守占用。所有旧 Run 的额度和累计用量不变，跨候选实际及未知消耗继续累计。

父候选克隆须继承完整冻结配置（仅新数据目录不同），不能只复制镜像和模式却退回旧预算。配置示例与后续真实测试使用同一组有界值。该修改给予合法步骤及明确修复足够的决策空间，不代替实际根因修复、不自动重试、不降低用户科学证据或将未完成结果记为通过。验收以原任务新候选的实际调用、计算及原始科学核验为准。
