# Code as Tools 产品冻结与正式验收规则

日期：2026-10-20（Asia/Hong_Kong）。用户在合并前置修复后明确要求“开始实施步骤6”。

## 范围与选择

本步固定产品、资料访问范围、任务、重复规则、独立评分和整批预算，验证变更检测与独立工作区。不启动步骤 7 正式模型/ORCA 运行，也不将开发交付重标为正式通过。

产品候选为 `5e6e9e38c7e24a10180d474bf95068692b7f9cca`。验收辅助与记录放在 `tests/helpers`、`scripts`、`docs/acceptance/code-as-tools-step6`；不修改运行时科学工具、SDK、提示词或生产源码，不引入新领域对象或评测平台。允许后续提交仅增加验收材料，但核验必须确认生产文件集合、内容、工具定义、SDK、依赖与实际环境仍等于候选。

冻结分为两份有明确依赖的记录：

1. 产品 manifest 固定源提交、完整生产文件集合（包含非 Python 资源）、工具目录、SDK 公开接口、提示词、依赖、Linux 镜像及文档入口。新文件、缺文件、内容或导入来源变化均须被发现。
2. 评测 manifest 绑定产品 manifest、公开任务、冻结后由用户或独立评审选定的两项保留任务、完整输入原文、评分规则、参考计算策略、配置和整批预算，以及验收辅助文件。保留任务选择不得反向推动修改产品或提示资料。

不把 Git HEAD 相等作为唯一冻结判断，也不允许仅比较旧清单内已有文件而漏掉新增求解代码。不同版本的正式结果不得拼接。变更产品必须产生新候选，并重新选择未参与该候选开发的保留任务。

## 成本、隔离与参考

正式任务每项三次。每次从原文进入产品，独立 data_root，统一共享环境资源根；不继承前一次 Plan、脚本、缓存答案或 Run 预算。固定随机种子策略，保留完整首次结果、修复及失败。测试辅助仅驱动、保存和核对证据，不提供科学求解代码给产品。

预算用前置固定槽位预约。正式任务、独立参考和控制反例分别计费，累计预约不退还；换 Run ID、重启或改目录不得清零。未知消耗单列，保守占用预约，不作零处理。环境锚约束冻结根内的账本；人为另建执行环境不属于该锚能自动阻止的范围，正式流程必须拒绝不同环境根。

独立参考的输入条件、原始来源、计算/核对方法和容差提前固定；数值可在正式任务选择方法并产生原始证据后，在独立参考工作区形成。不得用产品生成的解析器验证其自身，也不得事后按结果修改容差。参考答案和评分材料不进入产品上下文。没有生产专用检查器不妨碍带限制观察，但独立评分不会授予 `QualifiedOutput`。

资料源固定官方版本与允许访问范围，实际检索正文和来源 hash 保留。允许范围内的新页面是既定检索能力，不允许任务之间添加新的项目指南或解题示例。动态检索的远端正文不能仅凭版本 URL 声称永不变化；实际消费版本按产物记录核验。

## 替代方案与验证影响

不采用逐题增加工具、提前写解题脚本、复制开发成功脚本、用模型自己的结论作唯一评分、参考/失败成本另起无上限账本等方案。

本步验证以离线正反例为主：生产文件新增/删除/篡改、工具/SDK/资料或配置变化、依赖导入替换、旧预算复用、未知结算、跨任务文件污染和路径越界应拒绝。Docker 仅显式读取已有本地镜像身份，不拉取、不启动科学计算。实际任务质量、科学数值、失败修复与完整边界矩阵在步骤 7 按冻结规则执行。

交付冻结记录、任务与评分规则、预算及辅助测试证据；提交推送后等待用户验收。
