# 当前执行失败事实不随查询窗口滚出

日期：2026-10-21（Asia/Hong_Kong）。

a022 的真实 H1 执行失败后，第 10 次模型决策读取了 stdout 第 160–187 行，其中明确包含 INPUT ERROR、简单输入行不识别的关键字及 GIAO。第 11–13 次请求仍包含这些原文；三次知识查询后，第 14 次请求把该成功读取压成只含覆盖范围的 consumed_read，当前 native 失败记录自身只有 nonzero_exit_code。重复读取不全由此解释：第 15 次请求仍看到完整的前次 stderr，却再次请求同一窗口。上述为逐请求 hash 绑定的事实，不声称受控因果实验。

按 0057 的当前失败有界反馈契约，统一复用已归档日志尾部读取函数。新 managed 执行的已结算失败在 Result 中保存通用 execution_failed 诊断，精确绑定本 Attempt 的 task/stdout.out、task/stderr.txt、Artifact 身份与 hash；SDK 子调用沿用同一函数。每个日志最多 2048 字节，不按错误关键字或科学题名选择，不扫描任意目录、不改变权限、启动证明或科学资格。凭据内容遮蔽，缺失、归属错误或 hash 改变保留读取失败，不能作为已读正文。

旧 Result 和 a022 原件不回写。context 仅使用已成功返回且校验通过的 raw_text 查询，核对当前未修复失败 Result 的精确 stdout/stderr Artifact/hash，并将每个日志最近一个窗口的有界尾部附到该失败 Result 的不可信诊断投影。最多保留四个当前逻辑失败；同逻辑后续执行成功后不再固定旧诊断。这里不读取文件、不启动查询、不新增持久对象；完整读取凭证和原件仍可查询，也不把局部窗口声称为全文。

普通历史读取继续压缩，新增诊断与内部失败共用现有有界投影，完整模型请求上限不增加。验证限定真实 a022 窗口加三次知识检索的回放、紧投影，以及已修复、错误 hash、外部伪源和归档读取边界反例。离线回放不是新模型或 ORCA 科学通过。后续新候选独立冻结，等待用户验收。
