# 有界格式规范化与明确未启动拒绝的纠正

日期：2026-10-21，依据用户清除实际阻碍、简化冲突流程并持续真实测试的当前授权。

a016 已不再重现准备几何路由死循环，但四次真实响应仍仅缺少末尾一个闭合括号，且把选择理由放在参数内。原始响应完整保存、finish 为 stop；此前只提示模型重新生成的规则仍消耗四次调用。另一次原生输入与已有失败输入完全相同，程序正确禁止启动，却以普通 StoreError 直接终止 Run，剩余八次模型调用无法用于修改输入。

新 v85 请求允许极窄的格式规范化，取代 0058 对这些明确格式情况一律不补写的旧限制：仅在完整字符串、EOF 且 finish=stop 时追加唯一确定的末尾 `}`/`]`（最多四个），随后仍用同一严格 JSON 解析器拒绝重复键、非有限数、过深结构及字节超限。不得补字符串、值、逗号、语句、内部缺失内容，length 截断和历史版本不适用。仅当选择动作外层缺少 reason、参数恰含 request_version/choices/reason 时，将该审计理由移至外层；不修改任何选择值、条件、动作或版本。保存原始内容、HTTP 响应 hash、追加后缀、字段移动及规范化前后 hash。完整 schema、当前动作、许可、目标、预算和执行/科学检查照常进行，规范化不授予许可或成功资格。

相同失败输入继续禁止启动。它在任何新预约、Attempt、租约或执行之前使用专用类型返回，主循环仅将该类型和既有明确文件引用拒绝交回决策；共用前后执行记录不变、无未决执行、Agent 已启用、有限纠正次数及持久化检查。普通 StoreError、未知执行、预算耗尽、完整性错误仍不进入该通道；不自动重试原输入。

修复提案同时消除提示矛盾：`repair_of` 简写不能再被要求填写其 schema 禁止的 logical_key；完整 Step 与简写保持各自既有校验。验收仅重现 a016 原件及格式/预启动拒绝的直接边界，再进行原任务真实模型测试；旧失败、旧配置和累计成本保留。
