# 按 Code as Tools 清理样例范围准入

日期：2026-10-20（Asia/Hong_Kong）。用户本轮明确要求“把不合理的限制全部去掉，一切按现在的 code as tools 的计划为准”。实施基线 `98b31322`。本决定先记录范围与验收契约，实际结果另行记录。

## 问题与范围

`bounded-analytic-1` 为首个优化与解析频率用例引入了方法/基组枚举、H–Ar、气相、受限单重态以及 Opt+Freq 绑定。这些局部范围随后也限制了普通单点。结构准备和通用观察仍有类似样例门槛。它们不能作为 Code as Tools 的永久科学范围，也不能用没有科学检查器替代执行影响检查。

本次清理自然语言/结构准备、原生输入准入、条件绑定、通用观察交付及模型指导中阻碍通用任务的样例限制；不新增任务求解 Tool、性质解析器或科学资格。仍沿用一个 Agent、同一执行入口、冻结 Run、薄 SDK 和文件证据。未授权本次一次性完成步骤 6/7 的全部正式重复验收。

## 实施选择

1. 新增显式版本化的通用原生输入策略，作为新 Code as Tools 配置的默认选择。旧 Run 的 `bounded-analytic-1`、无策略路径、检查结果、许可及预算保持原版本，不自动升级旧事实。
2. 科学方法、基组、元素、自旋及环境不以首个用例的枚举决定执行资格。输入仍须提供可核对的明确条件与数据来源；未知条件不伪造为气相、默认态或实际方法。
3. 解析执行影响、文件依赖与有限工作量；阻止外部命令/程序、越界路径、未申报依赖和无法核算的执行结构。保留进程树资源、期限、内部调用与产物预算。科学求解算法留在模型生成的任务代码中。
4. 通用观察可记录不同条件的派生分析，逐源保留条件、公式和局限；只有与用户明确目标矛盾时才阻断对应目标。来源检查、操作成功和科学资格仍分离，现有 QualifiedOutput 不扩权。
5. 官方资料查询取消固定少数页面的限制，允许受控读取冻结 ORCA 6.1 手册内的章节；固定域、版本、单次请求、字节和输出界限不变。
6. 结构准备只根据所用算法的实际依赖、明确身份与参数一致性准入；移除无关的中性/单重态前置门槛，不猜测用户未确定的自旋或立体化学。

## 替代方案与验收

不采用删除所有输入检查的做法：当前气相等事实原先由闭合语法推导，单删白名单会导致错误条件记录。也不按新科学任务增加新的白名单或预写解法。

验证覆盖：旧版本快照兼容；开放方法/基组、重元素、开壳层、溶剂、独立优化/频率、激发态与受管多计算；条件不匹配、文件/外部执行、资源和预算反例；结构准备及跨条件观察；相关定向回归。真实本地 ORCA/容器以有界显式测试取得执行证据，真实模型和完整跨任务矩阵另列，缺项如实报告。提交、推送后等待用户验收。

## 验证中发现的既有问题

短 ORCA 作业可能在容器采样后、可执行文件身份检查前结束，已有采样出现了 ORCA 进程但实际启动凭据未确认。调整为优先检查可执行文件身份，并在退出前补查；仍须满足冻结可执行文件的 inode、路径、PID 和启动时间证明，不以进程名称或 stdout 代替。未取得证明的运行仍保留失败与预算占用。宿主临时目录过长导致的收集失败另列，不通过更改科学结果消除失败。
