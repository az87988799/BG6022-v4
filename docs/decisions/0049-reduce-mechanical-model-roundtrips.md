# 减少机械步骤的模型往返

日期：2026-10-20。用户在模型成本优化期间提供五项优先级表并明确允许参考修改。本轮在 0048 的纯上下文优化之外，补足文件可发现性、受限机械推进、显式 SDK 来源声明及确定性导出；不实施步骤 6/7，不启动真实模型或 ORCA。

## 范围与契约

1. 当前 Result 可直接展示有界文件索引：精确原文件键、Artifact ID/hash 和已知元数据，带生产 Result/Attempt/Call 来源。省略明确计数；只投影已有回执，不自动读取正文。继续使用具体 CodeRef/InputManifest 和原权限、归属、hash 检查。不引入“最新文件”、猜测用途、未来未结算文件自动绑定或不计子读取额度的批量工具。
2. 新 Run 可冻结机械推进策略，历史快照缺该字段解释为关闭。唯一主循环先重验目标；仅当前已批准 Plan 的纯文件写入回执全部成功、检查通过、源文件完整、冻结 Step 与版本一致，且目标状态没有变化、无新消息/信号/未知执行时，允许继续既有 ready Step。工具定义显式声明机械反馈；主循环不按科学任务名分支。科学/分析/查询观察、失败、检查点、计划修订、条件或目标变化均回模型。沿用原 Tool 入口、执行准入、累计预算与环境租约；确定性决策占决策轮数并持久化依据，崩溃恢复不重复执行。
3. SDK `receipt_source` 只把脚本明确选取的收据和原文件键写成现有来源声明，不扫描、补全其他来源或推断物理值。原收集端仍独立验证真实回执、hash、条件冲突与最低证据；helper 不授予科学资格。产物声明仍显式。
4. 0048 的等价 schema、当前证据引用、稳定前缀和动作输出额度继续使用；已有 `repair_of` 继续复用冻结修复合同。同一 `workspace.write` 接受 Python 旧 CodeRef/hash 与最多 16 项精确替换；片段须在原文件唯一命中且互不重叠，输入/输出仍限 64 KiB。预检与写入均核验许可及原字节 hash，生成新 Artifact、保留原字节，后续经过原修复/执行校验；不能模糊修补或执行补丁代码。全文写入保留原序列化合同，新 schema 明确两种形式互斥。
5. 报告和终态解释原本已确定性生成/持久化，不再另建总结循环。新增有界结果包通过显式导出操作触发，包内包含报告、清单和校验后的原字节产物；不将打包塞进只读 GET，不让模型抄表或生成归档脚本。缺失、失败、排除与 unverified 身份保留；导出不修复科学证据或改变 Goal 状态。

## 验证与退出条件

所有验证使用离线 fixture、脚本化传输和旧 JSON，不发送真实 API 或启动 ORCA。分别证明：文件索引可直接用于既有精确绑定；机械继续比旧策略减少实际模型入口调用且遇变化退回；来源辅助函数与原声明一致、伪造仍被收集端拒绝；导出有界、hash 核验、不覆盖历史、无新增模型调用。已有 schema 表示测试改为独立语义核对，保留非法提案反例。原有 16 项基线失败单独记录，不伪称全量通过。

结构/表示的离线节约与真实 token、缓存率、端到端质量分开报告；新增行为的真实效果未验证。交付相关代码、有限证据和限制，提交推送，等待用户验收。

## 取舍

继续要求模型逐次选择纯文件步骤会保留不必要的往返；扩大到科学反馈自动继续会掩盖对目标和计划的影响，因此当前只采用已结算纯写入的明确工具契约。文件索引与精确引用复用原消费入口，避免再建一套动态文件选择协议。SDK helper 仅编码显式来源，不尝试从数值或文件访问轨迹推断科学依赖。局部修改采用唯一原文片段，避免模糊补丁的错误匹配；不适合局部修改时仍可全文写入。显式结果导出复用现有报告及校验，避免另设模型报告循环。

SDK 更新随受管 Linux 镜像重新冻结；本次使用本地缓存与禁网构建，并完成纯 Python helper/hash 烟测。旧镜像及历史 Run 配置保留。该验证不替代 ORCA、MPI 或完整隔离矩阵；旧 Run 不自动换镜像，旧镜像与新版宿主 SDK 不一致时新 Attempt 仍拒绝。
