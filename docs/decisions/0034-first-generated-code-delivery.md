用户要求先完成进入步骤 3 前必须处理的问题，再按专项方案实施步骤 3。本决定不授权步骤 4—7，不把开发验证记为正式跨任务验收。

## 前置条件

上轮保留的 87 项失败记录须逐项对应到本轮结果：上下文容量、缺字段、历史快照、协议断言及未完成的离线流程。该数量是用例数，不是独立缺陷数；其中输入来源链用例在旧基线因缺配置文件失败，其容量问题的历史归属未确认。旧报告和原始测试记录保留，本轮用新增证据纠正归因。

生产缺陷修复与契约变化分开处理。上下文不得截断用户目的、丢弃必要事实或提高历史预算来消除失败。历史兼容测试检查原有字段逐值保留、原始文件字节不变、已定义的保守默认及不扩大许可；不能通过忽略所有新增字段放行。工具参数的动态资源上限由冻结配置验证，测试不再以旧重复 schema 常量作为权威。

进入步骤 3 前运行上述定向回归，并检查必要回归中是否还有阻断自然语言、单协调者、预算或执行安全的失败。Linux 四核路径继续作为已选择后端；Windows MPI 的已知不适用不要求先扩展另一后端。未知执行保守占用、没有每尝试磁盘硬配额和不完整 CPU 成本仍公开保留；不得据此声称完整恢复、完整资源审计或步骤 4 已实现。

本轮只读审查另发现 Python 尝试额度漏洞：更换 logical ID 并改变代码 hash 可使既有 `code_retries` 判定重新成为首次尝试，而合法同逻辑代码修正又被只支持 SCF 的修复入口拒绝。本次先修复这一执行前置条件。当前受限实现将同一 Run 首次 Python 之后的每次代码执行都计入额外代码尝试额度，包括不同脚本；不把该保守计数解释为同一科学失败。未知尝试仍须先对账，历史累计记录不清零，代码修订保留原目标、输入与所有旧版本。更精细的多脚本任务成本分类留待明确扩展，不以新 ID 绕过现有额度。

扩展一般条件表达后，旧 HF 科学检查的范围缺口曾从自然语言归一化中丢失，导致水溶剂等明确条件被保存却没有显示检查器不覆盖的事实。本次只恢复旧科学检查契约的覆盖诊断；不重新对一般观察设置 HF 白名单。结构化旧适配入口也改为在导入产物前核对自身适用范围和实际配置资源，避免先产生文件再拒绝；可调有限预算及迭代参数不重新套旧 schema 常量上限。原始历史回复保持原样，离线测试适配当前协议和明确配置。

上下文仍使用既有三字段意图和八字段提案协议。紧凑表示复用无损字符串池、字段字典及 schema 列表示；保留原始标记碰撞处理和可直接读取的执行权威字段。单次使用的 schema 定义可等价内联，闭合字段约束不可删除。允许修订的未执行 Step 必须保留相应工具参数 schema；已知参数不能成为隐藏可变参数规则的理由。最终说明的预算占用保持原值，未知模型消耗仍占用预算；某个历史诊断超过剩余预算时保留拒绝事实，不通过缩写诊断内容或放宽预算消除失败。

## 步骤 3 的实现边界

沿用一个决策协议和现有 Run/Plan/Step/Tool/Result/Artifact 责任链。一般分子及目标保留其用户原文、条件、来源和证据要求；未指定方法由模型依据版本化资料选择，结构身份、电子态歧义不得以奇偶性或模型声明代替确认。

模型通过有界通用文件 Tool 生成不可变代码 Artifact，程序提供确定的 ID/hash 后再绑定执行 Step。写文件不启动计算，不授予脚本权限；代码引用、输入副本和实际执行仍经过原统一入口。任务算法、ORCA 输入和新性质解析由模型现场生成，不预置乙醇求解脚本。

首个开发用例需要有界优化和解析频率。本次只扩展同一次受管 ORCA 调用中能够明确核算的导数工作量；数值频率、扫描、多次 SDK 算法调用及检查点恢复仍留后续步骤。涉及执行准入的扩展必须有局部正反例和实际 ORCA 证据，不因关键字可解析就视为科学检查通过。

本轮实际 Opt+Freq 探针只覆盖 HF/STO-3G；已实现的 DFT 准入组合仍只有离线正反例，尚无真实 DFT 执行及独立输出核验。不得把该准入集合写成已真实验收的兼容矩阵。

通用交付只评估请求约定的来源、完整性、实际条件及验证说明，不授予 QualifiedOutput。模型/脚本声称 passed、ORCA 正常结束、归档成功和极小值确认分别处理。用户明确要求的专用检查仍为硬要求；没有生产频率检查器时保留缺项，独立开发评分不能升级生产结果资格。

通用交付不能只核对方法、基组、电荷、多重度、电子态和环境而漏掉额外用户条件。明确温度、标准态或未知的物理条件若没有当前可信来源证明，保持目标未完成；优化后与固定初始几何也须核对对应执行类型、绑定的初始几何和归档输出角色。角色/来源成立仍不代表脚本数值、优化收敛或极小值科学检查通过。

新 Run 显式冻结 `bounded-analytic-1` 原生输入策略：气相、明确电荷/多重度和受支持的闭壳层 HF/DFT 导数执行组合，只接受已核对来源的初始几何及与当前 Request 一致的条件。兼容集合是执行准入范围，不是科学检查或通用方法推荐；旧 Run 没有该策略时保持原始策略与序列化。优化上限、SCF 上限和响应迭代上限分别冻结，数值频率、扫描、外部程序、未知导数影响及多 SDK 请求继续拒绝。工作量采用 `Opt MaxIter+1` 几何评价槽、1 个 Hessian 任务槽和 `3N` 响应方向槽的保守声明；它不是实际 SCF 次数或 CPU 用量。直接调用在一次 Run 原子保存中同时写入 Attempt 的不可变预留与累计工作量；SDK 仅由内部调用回执收费。

任务代码通过 `observations.json` 声明有界观察和文件位置。程序从已归档文件核对身份/hash，绑定脚本 hash 与实际准入条件；脚本声明的行号、解析结果、单位和科学解释仍未获独立科学验证。生产交付可以满足明确允许带限制报告的目标，但不可满足用户指定的更高科学检查。开发独立核验结果单独记录，不写回生产科学资格。

注册的身份、初始结构输出仍按 Tool 声明的输入检查验收；独立输入 Goal 不继承整句优化任务的优化后关系，也不能借输入检查满足优化、收敛或其他科学要求。交付明确标为已检查的输入产物，科学资格为 false。输入 Goal 的真实未知项必须保留。无原生执行回执时，根几何及已声明的科学条件会阻止通用科学目的验收；尚未应用的配置默认模板不形成任务条件，实际采用的默认值和原文条件则必须核对。

当前 SDK 请求键在整个 Run 内唯一；任务不能复用旧回执重放执行。已结算失败后的新计算请求使用新键并继续消费同一累计启动和工作量预算；未知请求先对账，不因换键获得新额度。回执复用和多个 SDK 请求仍属于后续步骤。

提交前交叉审查还要求关闭 SDK 与直接 ORCA 切换的追加许可/额度缺口。本次单 SDK 范围采用保守边界：后续新的 SDK 科学请求须核对追加科学许可，已存在直接 ORCA 的预约也参与追加分类；SDK 在先的后续直接 ORCA 同样不得重置为免费首次调用。只增加代码重试额度不授予追加科学许可。纯旧适配器初始多 Step 的既有分类保持原契约，已经完成的回执查阅不产生新启动。此项以离线正反例验收，不将八次未进入计算的模型运行当成该门禁的真实执行证明。

模型名称与传输限制进入冻结配置；未指定新名称的历史快照不新增序列化字段。仍使用原有单一 DeepSeek JSON 调用协议、有限纠正和累计预算。没有定价表的可配置模型只报告 token 与费用未知，不套用另一型号的价格。本次示例配置的默认电荷、多重度和电子态明确来自配置；方法和基组留给有来源的选择，不从电子数奇偶性推断自旋。

## 验证和退出条件

### 通用名称来源、结构版本与条件选择

新 `request-semantics-3` 允许模型提议一般分子身份和一般物理量，但名称、物理量与用户明确的最低证据要求仍绑定用户原文。查询别名另记为推断，不把模型翻译改写为用户明确指定。旧结构回执继续使用 `structure-identity-1` / `structure-prepare-1`；只有冻结身份契约为 `general-identity-2` 的新体系按 Tool metadata 选择 v2 检查。Store、输入绑定和消费规则共同核对版本，不能把历史结果重新标为 v2。

本次采用较保守的局部名称映射决定：推断别名先核对 PubChem 同义词；如不能确认，再以固定 Wikidata API 查询原始中文名称，要求至多五个候选中只有一个具有精确中文标签/别名和唯一匹配的 PubChem CID。两个来源的原始响应、URL、hash 和返回状态均保留；Wikidata 明确标为社区维护的交叉引用。这是本次实现选择，不能解释为总蓝图要求所有名称翻译必须通过两个数据库，也不能称为权威化学资格或实验样品证明。真实开发探针发现 PubChem 中文“乙醇”查询 404，完整官方同义词表不含该中文名称；生产 Tool 已通过通用交叉引用取得同一 CID 与分子图，证据见[名称来源记录](../acceptance/code-as-tools-step3/identity-sources.md)。未新增乙醇名称、CID 或 SMILES 白名单。

一次 resolve Call 最多四次固定公共端点 HTTP 请求，累计检索期限 120 秒；原有 PubChem 性质响应上限保持 256 KiB，同义词及 Wikidata 响应各限 1 MiB，候选数和总归档声明有界。仍消费既有一次身份查询调用额度，并在回执分别报告 HTTP 次数；不开放模型任意 URL、代理、重定向或网络凭据。网络、取证或歧义失败保留原始响应，不能静默采用模型别名。

v2 解析单个连通的具体元素分子图，非显式氢原子数至多 128、加氢后至多 384，核对完整图、分子式、形式电荷和原子顺序，保留同位素、自由基及潜在立体信息。当前初始几何准备仍要求已确认或明确配置默认的中性单重态，并保守拒绝自由基、立体中心/立体键及未解身份歧义；没有从偶数电子推断多重度。几何检查仅覆盖有限坐标、图键距离与原子映射，不表示优化、构象穷尽、立体配置保证或电子基态资格。

固定 OPI 2.0 的 XYZ 序列化包含末尾空行。结构准备与原生准入仅在校验视图忽略末尾纯空白行，不重写、规范化或重新散列原始输入；策略仅读取已校验的 N 个原子行。内部空行、额外原子或第二帧、非有限坐标仍拒绝。失败的有界准备候选保留为未合格证据，只有完整校验通过才发布成功回执；历史未落盘的 XYZ 不回填。

`select_conditions` 是同一决策协议中的窄 Request 修订入口。只有用户明确授权且尚未指定的字段可选，不能覆盖明确、继承、未知或推断字段，也不能修改 Goal、消息、许可或预算。Store 独立检查当前 Run 中已完成的 `knowledge.search` Result、绑定 Call、文档 hash、逐字引文及引文 hash；方法/基组必须出现在引用的官方资料中，打包指南不能冒充官方文档。电子态、电荷、多重度目前不通过该入口自动推断；配置默认继续标明来源，不作为分子态证明。选择必须先于结构查询/准备或受管执行，因为输入绑定包含整个 Request 版本及实际条件。上述局部类型与函数没有新增领域生命周期。

所选方法/基组按完整标识匹配官方原文，保留斜线、连字符、星号、括号等名称组成字符；`PBE0`、`B3LYP/G`、`def2-TZVPP` 等不能仅凭前缀证明另一个方法或基组。该检查只保证引文确实提到所选标识，不证明科学适用性。

首轮真实模型暴露了一般目标入口仍混用旧范围提示的问题。代码授权的当前上下文将旧检查范围、端口到规则映射明确标为专用科学资格；不向一般分子任务发出旧的全局 unsupported-system 通知。一般物理量、明确几何关系和授权选型若被模型漏掉或误记为未知，入口聚合返回有限纠正，绝不自动代写目标、端口或方法。既有真实 unknown 与一般目标 missing 缺项不再因刷新而被静默删除，用户明确 qualified 要求也不能改为一般观察。单位只对有限明确句式保留逐字最低证据，不新增单位解析或科学检查资格；未覆盖表达仍属于理解限制。首轮失败 Run 及两次原始回复保留，由固定 hash 夹具离线回放验证新的拒绝边界。

先关闭前置缺陷，再验证一般目标、代码文件写入/引用、权限和预算、生成失败有界修正、通用结果保守交付的正反例。真实开发运行仅从自然语言进入产品，由真实模型生成 Plan、代码与输入并执行真实乙醇优化/频率计算；开发驱动仅负责配置、调用、采证和独立核验。

真实模型/ORCA 的首次结果、失败、修正、全部尝试和成本均保留。提前记录独立核验方法，不能用生成解析器验证自身，不能人工代填生产 Plan/输入/代码使任务通过。代码错误必须保留原版本并由同一模型闭环修正，另验预算耗尽时有界停止。

实现事实、定向/必要回归、真实运行与未验证项在本轮验收记录中分别报告。完成后提交、推送并核对远端，等待用户验收。
