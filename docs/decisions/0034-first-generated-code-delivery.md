## 步骤 3 的实现边界

沿用一个决策协议和现有 Run/Plan/Step/Tool/Result/Artifact 责任链。一般分子及目标保留其用户原文、条件、来源和证据要求；未指定方法由模型依据版本化资料选择，结构身份、电子态歧义不得以奇偶性或模型声明代替确认。

模型通过有界通用文件 Tool 生成不可变代码 Artifact，程序提供确定的 ID/hash 后再绑定执行 Step。写文件不启动计算，不授予脚本权限；代码引用、输入副本和实际执行仍经过原统一入口。任务算法、ORCA 输入和新性质解析由模型现场生成，不预置乙醇求解脚本。

首个开发用例需要有界优化和解析频率。本次只扩展同一次受管 ORCA 调用中能够明确核算的导数工作量；数值频率、扫描、多次 SDK 算法调用及检查点恢复仍留后续步骤。涉及执行准入的扩展必须有局部正反例和实际 ORCA 证据，不因关键字可解析就视为科学检查通过。

初版实际 Opt+Freq 探针只覆盖 HF/STO-3G，当时 DFT 准入组合只有离线正反例。2026-10-19，live017 首次从原始乙醇请求自主完成 B3LYP/def2-SVP 的真实优化和解析频率调用及带限制交付，13 次模型 HTTP、159232 tokens、1 次 Python、1 次 ORCA；实际为气相 RKS、电荷 0、多重度 1、ORCA 1 进程和 MaxCore 192 MB，容器上限仍为 4 核/1024 MiB。计算 Result 的优化结构与 27 个频率值均为 unverified 观察，qualified_outputs 为空，终止解释合同通过。随后[独立科学核验](../acceptance/code-as-tools-step3/validation/live017-independent-scientific-audit.json)通过，覆盖实际 B3LYP 组成、电子态、优化/响应收敛、结构与完整频率谱；开发检查不授予生产科学资格。live018 的故障种子尚未执行便失败；live019 消耗一次代码重试和两次 ORCA 后仍 failed/partial，v49 原文请求 live020 随后 completed/complete、四个 Goal 满足，[独立科学核验已通过](../acceptance/code-as-tools-step3/validation/live020-independent-scientific-audit.json)，live021 则因测试观察器误要求最后决策为 call_tool 而在科学预约前 failed/partial，0 Attempt/Python/ORCA，不属于模型 Python 执行失败。随后只修正开发测试驱动以只读核验生产既有 activated Plan 首个 ready Step，生产源码、提示和配置未变，gate、budget、outcome 定向测试 122 通过；同一生产 v49 和 v4 配置的 live022 已 failed/partial，359 字节占位脚本触发真实 NameError，0 ORCA、没有执行有效修复；首版不含完整计算流程，不能计为完整任务程序修复成功。实际代码错误的完整有界修复及最终回归仍待完成，步骤 3 尚未完成或验收通过，也不能据单个实测组合宣称整个准入集合均已真实验证。

通用交付只评估请求约定的来源、完整性、实际条件及验证说明，不授予 QualifiedOutput。模型/脚本声称 passed、ORCA 正常结束、归档成功和极小值确认分别处理。用户明确要求的专用检查仍为硬要求；没有生产频率检查器时保留缺项，独立开发评分不能升级生产结果资格。

后续真实事实分别保留：v50 的 live023 原文自主交付及[独立科学核验](../acceptance/code-as-tools-step3/validation/live023-independent-scientific-audit.json)通过；live024 在 Python 前因保留计划提案错误失败。v51 的 live025 选型引文/JSON 失败，live026 中文 PubChem 404 后相同查询换 ID 重复被拒绝，均没有 ORCA。live027 的完整首程序真实触发 NameError，并由模型保持同 Run、同 logical_id、非代码合同不变，仅删除标记后重跑；第二次因原生输入 `%output jsonpropfile end` 缺标量被 SDK 拒绝，仍为 2 次 Python failed、0 ORCA、1 次代码重试。不能把实际修订执行等同于成功修复交付，也不能把开发独立核验写回生产资格。

通用交付不能只核对方法、基组、电荷、多重度、电子态和环境而漏掉额外用户条件。明确温度、标准态或未知的物理条件若没有当前可信来源证明，保持目标未完成；优化后与固定初始几何也须核对对应执行类型、绑定的初始几何和归档输出角色。角色/来源成立仍不代表脚本数值、优化收敛或极小值科学检查通过。

新 Run 显式冻结 `bounded-analytic-1` 原生输入策略：气相、明确电荷/多重度和受支持的闭壳层 HF/DFT 导数执行组合，只接受已核对来源的初始几何及与当前 Request 一致的条件。兼容集合是执行准入范围，不是科学检查或通用方法推荐；旧 Run 没有该策略时保持原始策略与序列化。优化上限、SCF 上限和响应迭代上限分别冻结，数值频率、扫描、外部程序、未知导数影响及多 SDK 请求继续拒绝。工作量采用 `Opt MaxIter+1` 几何评价槽、1 个 Hessian 任务槽和 `3N` 响应方向槽的保守声明；它不是实际 SCF 次数或 CPU 用量。直接调用在一次 Run 原子保存中同时写入 Attempt 的不可变预留与累计工作量；SDK 仅由内部调用回执收费。

任务代码通过 `observations.json` 声明有界观察和文件位置。程序从已归档文件核对身份/hash，绑定脚本 hash 与实际准入条件；此归档检查不独立验证脚本声明的行号、解析结果、单位或科学解释。生产交付可以满足明确允许带限制报告的目标，但不可满足用户指定的更高科学检查。开发独立核验结果单独记录，不写回生产科学资格。

注册的身份、初始结构输出仍按 Tool 声明的输入检查验收；独立输入 Goal 不继承整句优化任务的优化后关系，也不能借输入检查满足优化、收敛或其他科学要求。交付明确标为已检查的输入产物，科学资格为 false。输入 Goal 的真实未知项必须保留。无原生执行回执时，根几何及已声明的科学条件会阻止通用科学目的验收；尚未应用的配置默认模板不形成任务条件，实际采用的默认值和原文条件则必须核对。

当前 SDK 请求键在整个 Run 内唯一；任务不能复用旧回执重放执行。已结算失败后的新计算请求使用新键并继续消费同一累计启动和工作量预算；未知请求先对账，不因换键获得新额度。回执复用和多个 SDK 请求仍属于后续步骤。

提交前交叉审查还要求关闭 SDK 与直接 ORCA 切换的追加许可/额度缺口。本次单 SDK 范围采用保守边界：后续新的 SDK 科学请求须核对追加科学许可，已存在直接 ORCA 的预约也参与追加分类；SDK 在先的后续直接 ORCA 同样不得重置为免费首次调用。只增加代码重试额度不授予追加科学许可。纯旧适配器初始多 Step 的既有分类保持原契约，已经完成的回执查阅不产生新启动。此项以离线正反例验收；初版八次及续作至 live016 的零 ORCA 失败不能证明实际切换门禁，live017 的单次 SDK ORCA 也没有覆盖 SDK/直接 ORCA 切换或追加启动。

模型名称与传输限制进入冻结配置；未指定新名称的历史快照不新增序列化字段。仍使用原有单一 DeepSeek JSON 调用协议、有限纠正和累计预算。没有定价表的可配置模型只报告 token 与费用未知，不套用另一型号的价格。本次示例配置的默认电荷、多重度和电子态明确来自配置；方法和基组留给有来源的选择，不从电子数奇偶性推断自旋。

## 验证和退出条件

### 通用名称来源、结构版本与条件选择

新 `request-semantics-3` 允许模型提议一般分子身份和一般物理量，但名称、物理量与用户明确的最低证据要求仍绑定用户原文。查询别名另记为推断，不把模型翻译改写为用户明确指定。旧结构回执继续使用 `structure-identity-1` / `structure-prepare-1`；只有冻结身份契约为 `general-identity-2` 的新体系按 Tool metadata 选择 v2 检查。Store、输入绑定和消费规则共同核对版本，不能把历史结果重新标为 v2。

本次采用较保守的局部名称映射决定：推断别名先核对 PubChem 同义词；如不能确认，再以固定 Wikidata API 查询原始中文名称，要求至多五个候选中只有一个具有精确中文标签/别名和唯一匹配的 PubChem CID。两个来源的原始响应、URL、hash 和返回状态均保留；Wikidata 明确标为社区维护的交叉引用。这是本次实现选择，不能解释为总蓝图要求所有名称翻译必须通过两个数据库，也不能称为权威化学资格或实验样品证明。真实开发探针发现 PubChem 中文“乙醇”查询 404，完整官方同义词表不含该中文名称；生产 Tool 已通过通用交叉引用取得同一 CID 与分子图，证据见[名称来源记录](../acceptance/code-as-tools-step3/identity-sources.md)。未新增乙醇名称、CID 或 SMILES 白名单。

一次 resolve Call 最多四次固定公共端点 HTTP 请求，累计检索期限 120 秒；原有 PubChem 性质响应上限保持 256 KiB，同义词及 Wikidata 响应各限 1 MiB，候选数和总归档声明有界。仍消费既有一次身份查询调用额度，并在回执分别报告 HTTP 次数；不开放模型任意 URL、代理、重定向或网络凭据。网络、取证或歧义失败保留原始响应，不能静默采用模型别名。
