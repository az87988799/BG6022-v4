# 0083：Windows 当前用户网页自启动与桌面入口

日期：2026-11-13（Asia/Hong_Kong）。用户要求直接打开网站，不再每次手动启动本地网页。本次明确授权当前用户登录后后台启动现有网页，以及桌面快捷方式在服务未运行时先启动再打开浏览器；此授权窄幅更新 0025 和蓝图 10.3 的首版前台部署范围，无需重复确认。

## 选择与范围

采用 `scripts/desktop_web.py` 作为本地启动辅助程序，`scripts/install_web_desktop.ps1` 安装当前用户的两个快捷方式。Startup 中的 `.lnk` 通过项目已有虚拟环境的 `pythonw.exe` 无窗口启动辅助程序，仅确保网页可用；桌面 `.lnk` 调用 `--open`，先有界确保同一服务可用，再打开 `http://127.0.0.1:8765`。用户也可在登录启动完成后直接访问该地址。

安装入口使用本机已有的 PowerShell 7（`pwsh -NoProfile -File scripts/install_web_desktop.ps1`），不安装新 shell、不修改安全策略或使用 Bypass。本机 PowerShell 7.6.9 已在原有 RemoteSigned 策略下完成实际安装；Windows PowerShell 5.1 仅保留脚本语法兼容，不承诺本机策略允许其执行 `-File`，此前策略拒绝不计为安装成功。

这是同一台 Windows、同一用户的部署便利入口，不增加 Windows 系统服务、管理员要求、公网监听或新的协调者框架。Startup 表示用户登录时启动，不承诺开机未登录时运行，也不承诺注销、重启、断电或异常退出后计算保活。现有手动 CLI 启动仍可用。

## 契约

- 后台网页仍使用现有单 worker、本机 Store 和 Coordinator，只监听 `127.0.0.1:8765`。既有 Run 协调锁、网页服务锁、环境并发及受管进程清理继续有效，不为快捷方式另建执行路径。
- 自动启动网页仅提供页面和已有事实；不扫描恢复 Run，不调用模型、任务 Python 或 ORCA，不自动启动 Docker、安装依赖或拉取镜像。提交、继续、取消和暂停仍由原界面及许可边界决定。
- 保留已有 Run 的版本、配置、预算、后端许可、累计用量与未知执行事实。服务重新启动不代表计算恢复；显式继续仍先对账，不清零预算或重复启动未知执行。
- 启动辅助程序使用明确的项目、虚拟环境、配置文件和工作目录，避免登录时工作目录或 PATH 改变导致另建 Store。Windows 快捷方式与进程参数须正确处理空格和中文路径，不借助拼接 shell 命令。
- 启动与桌面打开共用有界 ensure。纯健康 GET 核对固定应用 ID 及配置 `data_root` 的指纹，不能以端口可连接或任意 HTTP 200 认定为本服务。错误服务占用端口时明确失败，不杀进程、不自动换端口；重复点击不创建第二个网页实例，也不添加无限重试或崩溃重启循环。
- 健康 GET 仅返回服务身份与数据根指纹等最小部署信息，不返回模型凭据或触发工作；网页其余接口沿用原 Host、Origin 和本地令牌边界。
- 无窗口启动须正确处理标准输入输出与 Uvicorn 日志，不能依赖 `pythonw` 下可用的控制台流。日志保存在当前用户 LocalAppData 下按工作区 hash 分隔的目录，不写入仓库或原科学产物，不记录模型密钥。
- `scripts/install_web_desktop.ps1 -Uninstall` 仅移除本项目安装的快捷方式，不删除代码、日志、配置、Run、Artifact 或测试数据，不改变既有科学运行状态。
- 服务正常退出仍进入现有停止接收启动、暂停及有界收集流程；强制结束、注销等未完成清理的情形保留未知状态，使用原恢复对账规则，不将后台部署等同于计算保活保证。

## 验收与未验证项

本决定先记录部署契约，不凭快捷方式文件存在宣称运行成功。需要定向验证首次 ensure、已有实例复用、并发启动、错误端口服务、缺失依赖、日志和快捷方式参数，以及原 Run/预算不变、没有模型或科学启动；当前会进行实际后台和快捷方式启动验证，结果另记验收报告。
