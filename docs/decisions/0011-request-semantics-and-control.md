# 受控语义候选与消息激活

日期：2026-10-07。落实蓝图 §4、§6、§10；不增加科学能力、预算或领域对象。

原来的结构化 bundle 保留。未提供 goals 的原始文本输入先创建未决 Request 和同一 Run，登记原文消息；首次语义调用使用现有模型预约、收据、纠正和总预算。语义候选是 Proposal 的 `normalize_request` 局部参数，版本为 `request-semantics-1`，不能含权限、预算、路径、通过状态或执行步骤。

程序核验消息与 Request/control 版本、注册体系、字段白名单、引用片段、明确继承及已授权默认。结构验证不能证明任意自然语言理解正确，真实语义效果仍须独立评审。未知和推断的关键条件保留未决，不提升为 explicit。默认规则仅来自用户输入配置，不由模型批准。原始文本澄清不要求 ORCA doctor，真正启动前再冻结环境。

普通模型 Plan 修订继续保护目标和最低证据。用户专属 Request 通道可规范化首轮、补充条件或明确替换当前目标；保存旧版本、原消息、变更类别和替换关系，受影响 Plan 失效。用户 update-file 也经此通道；活跃协调者期间仅入队，不争抢改写 Run。语义候选不直接调用将所有变化标成 explicit 的旧入口。

消费消息、未决条件、Request/Plan 引用、处理结果和已确认控制代次先进入不可变决策记录，再一次原子激活 Run。未激活孤立候选不能执行；重放使用稳定决策 ID。确认继续仅接受完整的无歧义短句，否定语句不作子串匹配。status 只返回现有快照；暂停/取消采用控制入口。Request 修订不扣 Plan 修订额度；消息最多 24 条，复杂分类仍扣模型/决策/纠正额度。

预约 ToolCall/Attempt 与最后科学启动检查共用已吸收 control_generation 门禁。计划激活后回循环头；锁内已持久消息先于后续启动。挂起进程的句柄先保存再复核，复核失败由后端终止，不恢复线程；保留真实创建计数和预约。恢复先对账旧动作，条件变化不阻止归档。明确 resume 清除 pause 后，仅当没有未处理消息时确认该控制变化。

验收：原始文本和普通多轮、用户改题/模型改题拒绝、状态零副作用、未决原子激活与崩溃重放、三处消息竞态、同一 Run 累计预算和 deadline、挂起进程清理。离线脚本只证明控制边界，不能充当真实语义或 ORCA 证据。

恢复补充：已经提出的澄清必须等待对应用户回答；无回答的 resume、continue 和 status 不消除阻断，也不再次花费模型额度。旧问题被回答而新问题仍未决时，新 Request 接续阻断。消息形式的暂停/取消与消费记录在同一 Run 激活中发布，避免先写 signal 再崩溃使候选永远过期；独立 pause/cancel 控制接口继续保留。明确数字条件还核对电荷/多重度标签和认证原文中的否定语境，不能仅凭截取的数字作为 explicit 证据。

局部协议修复（2026-10-07）：真实候选曾给 `parameters` 添加未声明包装，或将新 Goal 的候选 `key` 误作既有 Goal.id 补绑定。语义响应的 `parameters` 直接组合现有 `SemanticCandidate` 生成的 schema；定义只在响应根 `$defs` 保存一次并明确重定位引用，`ACTION_PARAMETERS` 仅保留说明和注册表，不维护第二套候选结构。严格 JSON 和额外字段拒绝保持不变，不替模型删除字符、展开包装或丢弃字段。

`goal_bindings` 只补充当前 Request 中已存在的真实 Goal.id，初始 `raw_request` 占位不属于合法目标；定义新 `goals` 时仅由其 `system_refs` 绑定，不能同时给 `goal_bindings`。合法 ID 和“定义新目标时禁止补绑定”来自同一局部契约，投影到模型 schema 并用于激活前校验；仍逐项核验注册体系、用户原文指代和原目标作用域。采用这一局部约束，不新增意图类型或长期对象生命周期，也不靠自动猜测 `goal_` 前缀兼容错误引用。

验收增加：两份真实失败形状的离线重放、包装/猜 ID/混合模式拒绝、既有目标合法补绑定、实际未知要求保留、schema 引用可解析且参数结构不重复，以及 12000 输入上限和临界澄清上下文。开发者明确修正后离线通过只证明程序边界，不能代替真实模型理解或科学证据。

语义轮只有 `normalize_request` 可选，因此省略当轮不可调用的 Tool 目录和普通 Tool 参数 schema；完整许可仍在 AUTHORITY，受许可只读端口的查询 schema 与最低证据注册表仍在语义说明中。后续正常规划/执行轮重新加载对应 Tool 目录及参数。这是去除重复协议以维持输入上限，不删除用户事实或增加执行授权。

v9 的真实开发已成功规范化 N-01，但后续普通决策重新询问原文明确的“只登记、不执行”，将显示单位缺省列为当前登记任务的阻断。原文、规范条件和许可在上下文中完整存在，故不通过增加权限或改写 Goal 解决。v10 仅在无可用 Tool 的普通决策提示中明确：只问阻塞当前用户范围的未知项，不重问明确选择；显示单位缺省保留未知；若用户已明确仅登记或不执行，说明登记事实及科学目标未满足后停止，不请求反向执行许可。不能仅凭 permission=false 推断登记任务完成，真实关键缺项及用户请求计算但尚未授权的澄清仍保留。程序不新增自然语言关键词分类器，不自动删除模型问题，也不放宽独立语义评审。

v10 的 N05 真实提案保留了不支持的水溶剂，但没有可见范围说明。v11 将既有 questions 字段的用途说清：新缺项需要澄清问题；程序检出的不支持范围可在同一字段给声明性说明，保留明确要求及未满足状态，不重新询问已明确的条件。门禁本来只要求可见文本而非问号，此次不改变接受谓词；错误反馈不再暗示存在另一个未声明的 unsupported 决策字段。声明不能消除程序追加的 unsupported 事实，也不能使历史气相结果满足该目标。真实原提案照旧拒绝；开发者补写说明的离线回放与新的真实语义验证分开记录。

v11 真实候选在机械通过后仍重问已排除的气相选择，或仅要求补乙醇几何、遗漏体系能力限制。v12 将长提示里的能力范围移为独立只读投影：六条件取自当前用途的 PROFILE，支持组成与几何校验共用 registry 的原有 H2O/CH4 白名单，科学输出来自实际 Tool 定义。它只是给语义模型看的能力事实，不是许可或默认来源，不是 SemanticCandidate 的新字段。程序不从乙醇关键词猜组成，不增加科学能力；已登记体系、原始证据和原适用性谓词保持不变。

questions 的说明单独区分两种内容：对象/物理量指代或关键条件仍需用户决定时提问；当前仅登记、不执行时，对已明确的不支持要求或明确缺少的执行资料给声明性说明，保留要求与未满足原因，不要求现在提供文件、重确认已作选择或改成受支持的替代问题。此提示不消除真正未决条件，也不使补几何自动获得新体系执行资格。旧真实轨迹及其独立失败结论保持；新增同源和边界回归不计作真实模型通过。

v12 真实复评仍暴露已命名目标与已注册输入混淆、零修订额度仍提供修订模板、以及历史来源和调用影响误述。v13 的语义能力名称复用既有 H2O/CH4 中英文别名；明确“没有已登记几何”不是“用户没有命名目标”。不按物种关键词自动分类或补候选，不扩大能力。

动作投影对齐 Store 的累计修订计费：尚无 initial_science_steps 基线时首次 Plan 仍可建立；已有基线且额度耗尽时移除建 Plan/修订模板及规则。已有就绪 Step 保留，未规划即时查询在读额度耗尽时不再展示。此显示不替代 Store 的完整预约校验，待执行 Step 的预算仍须执行门禁核验。
