# 首轮契约修复与同题重新冻结

日期：2026-10-20（Asia/Hong_Kong）。用户明确要求“修复这轮暴露的问题，重新冻结后再把全部任务各跑一轮真实计算”。

## 本次范围

修复首轮暴露的通用契约：原生输入准入版本与工作量预约一致；计划输入角色与 Tool 定义一致；身份别名使用独立检索的名称证据；请求规范化保留否定、局部几何关系和最低证据，并在有限纠错中返回完整可操作诊断。检索正文若已取得，则按同一字节保存来源产物，不用事后重新请求冒充首次消费归档。

这些修复不新增科学求解 Tool、任务算法、性质端口或科学资格，不为七个任务硬编码答案，不增加运行预算或放宽科学要求。历史 Run、冻结清单、失败及累计消耗原样保留。

原生直执行的工作量预约按该 Run 的不可变 `native_input_policy`，复用准备器和工具契约共用的 `profile_contract` 精确核对准入版本：`bounded-analytic-1` 只接受 `native-orca-input-2`，`managed-native-1` 只接受 `native-orca-input-3`。不得把两个版本视为可互换，也不得用 Store 新默认配置改写旧 Run。无 policy 的历史 v1 输入继续走原链路，不获得新工作量准入；已启动、无准入或输入 hash/policy 不符仍在启动前拒绝。离线回归执行真实准备、预约、证据收集和结算链路，仅在操作系统启动边界停止，不以模拟 ORCA 输出宣称科学通过。

## 输入角色、名称证据与资料正文

计划审批从 Tool 的 `check_contract.input_ports` 核对必需输入角色及对应输出端口；例如消费者角色 `identity` 对应 `resolved_identity` 输出，二者不能互换。字段错误须在计划激活前反馈，不能等结构准备开始才失败，也不通过给执行器新增角色别名掩盖错误。没有固定角色映射的现有成员分析工具继续按其自身契约处理。

对明确尾随分子式的名称，允许在保留完整原文的同时，提取独立名称证据的查询目标。仅支持中文名称紧邻分子式，或名称与分子式以空格、配对中英文括号分隔；分子式必须可解析为具体元素计数并与已检索完整分子图一致。公式不符立即保留失败；公式一致也不能替代拓扑、同义名称或同 CID 证据。记录原名、名称部分、公式及解释规则；不按分子设置白名单，不改写 Request。独立名称证据缺失时，`structure.resolve` 保留原始回执和未确认身份观察并返回失败，不能先发布合格身份再在下游拒绝。

`knowledge.search` 在既有一次 GET 中取得的完整有界正文，按 HTTP 内容解压后、UTF-8 文本解码前的原始 bytes 归档为现有 `knowledge_document` Artifact；本地指南使用其原 UTF-8 bytes。调用只新增 `archive_retrieved_evidence` 效果，明确归档已取得的响应，不进行另一次请求、格式转换或科学执行，也不授予写任务文件的许可。产物使用现有每文件、数量及总字节配额；超额时保留 Call 原始文件与结构化失败，不声称完整归档或供方法选择引用。Result 保留正文 Artifact ID/hash、原 URL/版本/访问时间、字节口径与摘要；缺匹配摘要仍可归档已经读取的正文。旧 Result 不回填正文，也不把首轮事后补档时间改写成首次读取时间。

## 请求规范化与目标保持

首轮把完整消息中的优化/单点词强加给所有目标，并漏识别“不分别优化”和“固定几何”，造成错误纠正及目标标签漂移。有限词法校验现按 `quantity` 的认证原文位置确定同句上下文，并保留前句独立几何指令；遗漏或反转明确几何条件仍拒绝。否定优化不再成为正向优化证据，也不抹去独立的固定几何要求。不同科学目标可保留各自关系，报告和种子等独立目标不从整段任务强行继承同一个标量关系。该校验仍是有界的来源检查，不宣称能证明任意自然语言语义。

`fixed_initial` 的既有执行与观察检查含义是绑定同一注册/准备初始 XYZ 的字节 hash，不能泛指任意候选的单点运算或保持内部几何的坐标变换。通用请求明确包含多候选、逐扫描点或派生坐标时，不把每个成员的单点/优化类型硬写成一个标量 `fixed_initial`/`optimized`；没有适用标量就省略，并将逐成员计算类型、原子顺序/内部几何限制、禁止优化和独立真实计算要求逐字保留在对应目标的 `text_basis` 或 `minimum_evidence`。短引文不能截掉这些义务。明确要求初始 XYZ 或其 hash 的约束仍优先保留，即使其他句子提到候选；用户授权多几何不授予新的执行权限。执行器的初始 hash 门槛、生成候选元素顺序检查和科学资格检查均不更改。首个离线重放中把 H2 全部关系替为 `fixed_initial` 的测试派生只曾证明规范化接受，不证明执行可行；修订重放另存并明确撤回该派生作为正确修复的解释。

通用目标的 `quantity`、输入目标的原文数量描述、目标绑定和最低证据原文错误在同一反馈中并列返回；模型必须显式修正，程序不代填条件、不改写目标、不提高纠错预算。最低证据仍须使用注册规则或连续逐字用户原文，不能通过删减、改数值或改单位消除错误。提示明确逐字复制及所有分子目标的对象绑定，配置默认仍需明确采用和披露。

显式 `query` 继续走既有只读查询契约；有 `quantity`、无 `query` 的通用输出，不因端口字符串与既有查询输出重名而退回旧查询规则。它仍按 `generic-observation-1` 保存用户最低要求及验证缺口，不取得 `QualifiedOutput`、执行许可或科学通过。已有只读目标、输入准备检查和历史结果不升级。

电子能覆盖检查同样按认证原文中的通用 `quantity`、原目标、必需性和通用几何关系判断，不再要求通用输出使用旧 `energy` 端口，也不把通用逐候选单点重新强制为旧标量初始 XYZ 关系。只有原文对应义务中的电子能数量描述可覆盖该义务；其他子句的能量提及、键名、理由或自由能不能代替。原有非通用能量目标的固定检查契约继续保留。

## 重新冻结与复测

先完成相关离线测试、提交产品修复，再建立新产品与评测 manifest。沿用原模型、已验证执行环境、资源上限、七项原文、种子和评分容差；新候选使用独立批次和工作区，继续共享原环境租约。原批次预约与消费不退款，新授权批次单独预约，交付同时列出两批累计事实。

本次仅执行 T1—T5、H1/H2 各一个新候选的 `formal repeat=1`。没有授权继续第二、第三重复、参考或控制矩阵。生产源码、提示或执行环境一旦在新批次中变化，停止继续使用该冻结身份，不拼接不同候选的成功记录。

H1/H2 的原始选择和评分规则保留，但开发者已读到其失败，不能再宣称它们对新候选是未见保留任务。按用户要求重跑原七项属于复测；本次不另选两项新题，不把复测当作专项方案要求的全新保留评测通过。验收辅助显式记录这种来源并核对原题字节，不能通过重写选择时间伪造新颖性。
