## 问题与范围

历史真实运行因重复声明默认条件、限制说明遗漏、重复原文定位、理由长度和非执行备注而多次拒绝提案；文件写入还与 Python 分析共用四次分析额度。已有上游几何准备的 SDK 计划被要求在计划批准前就持有准备完成的几何。旧 12K 上下文回归在展开全部历史结果时超限。

最新名称简化离线证据为 515 通过、1 跳过、0 失败；本次修复包括此前仍未解决的四项上下文回归，不能把它们描述为这 515 项中新产生的失败。真正的脚本错误、无效 ORCA 输入和未通过科学检查仍须按事实反馈，不能通过降低成功标准消除。

## 本次契约

1. 已在请求配置中授权、候选中未填写且无显式冲突的默认条件由程序填入，来源保持 `default`，保存程序补入的记录和模型原始提案。用户显式未知、否定或冲突不被覆盖；不擅自选择方法或基组。
2. 程序根据已知能力及最低证据要求生成必要限制说明，不因模型漏抄说明而拒绝整个规范化。原最低证据、未解决项和未验证事实保持不变，说明不能授予科学资格。
3. 同一消息内重复精确引文可绑定程序找到的全部位置，保留范围；共享条件由程序保存原文引用，不要求每个目标重复抄写。当前身份查询消费端同步核验完整位置证据，旧身份契约和无该证据的历史唯一性检查保持原样。跨消息来源歧义以及真实条件冲突仍须处理。
4. 非执行性 `reason` 过长由程序有界收录，原响应留在既有模型证据中；已知非执行备注可以保存为备注，不进入执行参数。未知执行字段、错误类型、工具参数或科学条件继续按原 schema 校验，不能泛化为忽略任意未知字段。
5. 新 Run 的文件写入采用独立有限计数，额度默认不超过已有 Artifact 数量额度；Python 分析仍使用原分析额度。文件数量、字节、执行许可与累计消耗约束继续生效。缺少新字段的旧 Run 保持原计费和序列化含义，不重置或扩大历史预算。
6. Plan 准入可接受同一体系、明确输出 `prepared_geometry` 的上游 `structure.prepare` 依赖。结构输入 Tool 的新 Step 可只在 Step 或声明参数中填写一次同一体系 ID，由程序补齐另一处；两处冲突或请求中不存在的体系仍拒绝，旧 Step 不改写。实际 SDK 执行仍须具有真实准备完成或注册的几何，失败或错误体系的依赖不能满足条件。
7. 模型上下文只展开当前目标、待执行依赖和最新未处理反馈所需信息；其他历史结果保留可查询的身份、状态和证据引用。原始记录不删改，不通过提高 12K 测试上限掩盖超限。当前失败、必要数值/来源和用户条件不能被压掉。
8. 模型 token 或时间预算接近耗尽、实际规划请求加终局预留不能同时容纳而一次终局解释仍可容纳时，主动进入有界部分交付；真正不足时记录确定性部分完成。不把单次输入的最大许可当成当前请求实际大小。调用、轮数、token 和期限仍有限，不能预约超额。

新提示版本为 v76，历史版本仍可读取。以上调整沿用现有七对象、工具和责任链，不新增任务专属解法、求解工具或科学资格。隔离、资源硬限制、原始几何、每次独立尝试和用户目标保持原契约。
