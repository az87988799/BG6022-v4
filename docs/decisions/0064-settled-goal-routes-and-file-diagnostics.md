# 保留已完成目标的证据与精确文件纠错

日期：2026-10-21。依据用户持续真实测试、从根因简化并消除冲突旧规则的当前授权。

a014 的真实模型响应全部为有效 JSON，但 24 次调用仍未启动 ORCA。当前初始几何已通过，方法选择后 Plan 为空；模型反复把该 Goal 绑定到文件写入步骤，旧反馈只枚举本次提案的生产者，连续十二次显示没有可用路线。原 Call、Result、Artifact 和当前输入绑定并未丢失，问题是已验证证据与新 Plan 的绑定规则脱节。随后五次原生输出文件引用错误只返回笼统 ValueError，模型反而修改无关写入步骤。

在新简化流程中，共用 `current_goal_evidence` 的实际认证结果，为已完成、同一 Run 的即时工具输出投影精确 EvidenceRef。新 Plan 可省略这些已完成目标，程序保留其现有证据；将已完成目标错误重复绑定到不声明该输出的写入步骤时，也规范化为同一当前证据。保存原绑定摘要及 hash、Goal、Request 版本、认证规则和实际 EvidenceRef，提交时重新验证。用户条件变化、不同物理量、没有通过检查的结果、未知执行和任意文件不因此获得复用许可；初始几何原件不覆盖。有效的新工作及其依赖仍须明确计划。

上下文同时展示这一精确绑定与省略保留规则，避免强迫重建准备过程；文件编写和执行使用完整三字段 JSON 范例，示例内容不提供科学求解算法，也不授予任何额外许可。

a015 再次证明文件选择的具体诊断被主循环丢弃：原校验已生成 `FileReferenceError.detail`，决策反馈却只保留异常字符串。仅对这一程序自有异常及既有白名单透传有界细节；错误必须指向实际消费者字段、生产者和声明名称，原生执行产物用真实文件键，不能使用写入工具专属端口。虚构 Artifact、错误 hash、越权和歧义继续拒绝。错误几何约束仍拒绝，只返回约束类别、所需索引数和实际记录，不改写模型的科学输入。
