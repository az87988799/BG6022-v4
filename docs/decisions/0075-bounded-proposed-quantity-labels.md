# 提议显示名称先认证来源，再收敛到持久字段

日期：2026-10-21。依据用户持续修复真实模型阻碍的当前授权，接续 0069、0072。

## 实际问题

a025 H1 首次归一提案使用 299 字符的显示名称，但引用的真实目标原文只有 26 字符。语义候选在 0069 来源认证及名称规范化之前，已被持久名称的 256 字符限制拒绝。实际物理条件及来源并未因此不合法；让模型再抄一遍名称属于重复机械门。

## 决定

仅由程序在当前 `request-semantics-3`、冻结 `simplified-1` 的提交入口传入受信验证上下文，允许候选的 `quantity` 使用既有原文输入的 1000 字符上限。复用 `ScientificLabel` 的严格字符串、非空、字符及首尾空白约束，只在这一临时候选字段覆盖最大长度；没有受信上下文或旧版本仍保持原校验。提示 schema 使用同一常量与类型规则。总响应字节预算、目标数量及其他字段上限不变。

来源认证后，缺省、非逐字或超过最终名称界限的提议统一经 0069 生成原文短片段，完整来源及原 `proposed_value` 继续保留。0069 规范化与 0072 审计消费共用同一适用判断，使过长但逐字的名称也能保留真实能量义务。未获合法来源、特殊契约不适用或其他原因无法规范化的值，提交前仍必须通过原持久标签校验。

`Goal.quantity` 仍为最多 256 字符；不放宽方法、基组、条件、最低证据、权限、物理量或科学资格。旧 Run、原响应与活动冻结副本不改写，不新增长期工作流对象。

## 验证

保存 a025 原提案及原请求的无凭据、带 SHA256 fixture，原样离线回放；核对目标及科学字段、原提议审计、短名称与完整来源。定向验证长逐字能量名称、旧入口、错误来源、非字符串、非法字符、超过既有 1000 输入界和持久 Goal 界限；不调用模型、ORCA 或全量回归。
