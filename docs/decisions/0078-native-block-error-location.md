# 原生控制块尾随输入的有界错误定位

日期：2026-10-21。范围来自真实 LLM 测试后的底层诊断修复授权。

## 问题

a026 的两个原生输入在 `%scf ... end` 后放置裸 `NoAutoStart` 行。既有解析器正确拒绝，原执行回执均记录 `not_started=true`，但错误只有“控制块后存在尾随输入”，没有指出块和位置。模型随后尝试读取尚未生成的执行日志。该候选之后已自行修正并完成两次实际 ORCA；本改动不回写其历史记录，也不据此主张新的科学成功。

## 决定

保留原有空格拼接、`_TOKEN.findall`、`_block` 解析及拒绝条件。只在原尾随输入异常中使用相同正则的 token offset 和拼接段范围，定位第一个未消费 token 所在的有效输入行。错误显示已经通过块名白名单检查的 `%block` 与从一开始的有效行号，并明确空行及纯注释行不计数；该编号不是原文件物理行号。

不回显未知 token、整行或输入正文，不增加凭据扫描、模型模块依赖或科学语法自动修复。原始输入、执行字节、资源、权限、物理条件和科学检查均保持；既有拒绝继续拒绝，合法解析结果不变。

## 验证

定向验证两份 a026 原输入的精确 SHA256 及同一行尾随、空行/注释行定位，另验证合法多行块的值、结束位置和输入字节不变。验证仅调用解析函数，不启动模型、ORCA 或任务代码；不运行全量回归。
