# 有可执行的当前目标工作时不提前终止

日期：2026-10-21。依据用户持续真实 LLM 测试并修复至原问题跑通的明确授权。

## 实证根因

a007 的完整原件因来源清单上限被拒后，程序只建议部分交付。a009 的外层 Python 正常完成，内部 ORCA 明确报输入字段错误；尚余 12 次模型、11 次 ORCA、3 次分析及写入/修订额度，程序快照却为未满足目标生成 `stop_with_partial_results` 和“不要开始更多工作”的指令，终端仅核对引用便接纳停止。它把当前缺口错误地等同于无法继续。

a011 又暴露同类遗漏：模型在初始 Plan 中把未见过输出格式的张量解析记为待分析 gap，实际原生 ORCA 已完成且完整张量原件可读，快照仍照抄旧 gap 并指令不再工作。结构化 gap 没有选定 Result，不代表当前计划缺少可检查的归档数据；计划中的旧说明也不是当前执行状态。

## 当前目标的有界继续

1. 新报告策略 2 统一推导当前必需、未完成 Goal 的具体可执行工作：现有批准 Plan 的未执行步骤及依赖；当前相关、已结算且可修复的执行失败；或已有完成原件的来源/分析修复。按当前绑定、版本、系统、真实生产者与 hash 关联，不因无关历史或已被替代的失败强迫计算。
2. 快照给出对应继续路线及必需失败事实，终端验收使用同一推导拒绝提前停止。模型仍提出具体计划、代码、参数与修改；程序不自动重试、不执行自己发明的方案，也不改变用户物理目标或科学检查。
3. 外层 Python 完成而内部 ORCA 失败时，保留成功外层与原失败。修正通过新的 writer/后续 Step 及 SDK 的新 key、`failure_retry/retry_of` 完成；不能误用仅适用于失败外层的 `repair_of`。完整已有原件只允许建议显式分析/manifest 修复，不建议重复计算。
4. 未决或未知执行先对账；无许可、真实必要额度不足、执行边界不支持及程序确认的 final-only 仍可诚实部分交付。模型自述预算不足不能替代账本。模型调用结算和时钟不进入稳定快照指纹，动态最终交付余量从已认证请求及现有预算校验判定。
5. 使用现有单主循环、修订/执行校验与累计预算，不新增调度框架或领域生命周期，不清零预算、不授予观察科学资格。旧策略与历史终端回执保留原记录。
6. a011 显示，必需通用报告 Goal 尚为结构化 gap 时，当前 Plan 的同系统执行可能已经完成并归档真实原件。新策略不再因未绑定 Goal Result 而忽略这些文件：核对当前 Request/Plan、生产 Attempt/Result、代码及文件归属/hash 后，给出 `plan_analysis_from_current_evidence`，要求模型提出新 writer 与 `sdk_orca=false` 分析步骤。同一路线适用于已绑定分析 Result 缺少目标观察且有该项清单拒绝的情形；分析 Result 自身也须完整认证，具体拒绝原因随共享原件引用展示，不能借邻接有效原件掩盖坏来源。外层完成但内部科学失败仍走原失败修复路线。来源候选只证明文件可供检查，不证明其中存在目标物理量或已满足条件；科学资格与最低证据检查不变。缺失或错误来源、未知执行、必要许可/额度不足及 qualified 目标不获得此路线。
7. 已发请求的原字节经 hash 认证且程序明确限定为 terminal、仅允许 stop/clarify 时，保留该最终交付出口；较便宜的终端请求或实际结算释放 token，不能事后撤销程序已经发出的只准终止指令。模型自行声称 final-only 不构成证据。
6. 对仍待分析的必需通用报告目标，当前 Plan/Request、同体系、已完成并核对归属和 hash 的原件可形成显式分析候选。仅说明文件可检查，不断言含有所需物理量，不把 gap 文本当权限；已有分析、写入和修订许可及必要额度满足时，提示提出新 writer 与无 SDK 原生执行的分析 Step，零新增 ORCA。终端复用同一继续事实。未知、缺失、异体系、旧版本、越权或篡改的来源均不可成为该候选。
