# 网页方案续建：性质与知识交付

2026-10-09。用户要求继续未完成方案、快速交付，不重复全量离线验证。本次先完成优化后偶极矩、查询和知识链，再按真实证据扩展覆盖；每项分别记录已实现与未验证，不改写旧运行。

偶极矩沿现有 OPI → ORCA → 统一解析/检查链增加 dipole_moment 端口，不增加执行器。OPI 2.0 Output.get_dipole(index=-1) 提供对应几何的属性；结构化值与同一坐标/SCF/能量片段内唯一的 stdout 偶极矩段交叉核对，拒绝重复段、单位缺失或冲突。保存向量（原子单位）、模长（Debye）、原始单位、坐标系、结构和文件位置。中性体系总偶极矩不依赖平移原点；方向只针对记录坐标系。优化输出还要求现有严格优化终段和最终结构检查全部通过。

字段与单位依据：[ORCA 6.1 属性清单](https://www.faccts.de/docs/orca/6.1/manual/contents/utilitiesvisualization/property_file_list.html)、本地锁定 OPI 2.0 dipole_moment.py/get_dipole 实现。预先固定交叉核对容限：向量/原子单位模长 5e-8，打印 Debye 与 2.541746473 转换的差 5e-6，能量 5e-8 Eh，坐标分量 3e-6 Å。不能以实测结果调整容限。新性质使用独立 dipole-binding-1 来源规则及现有 orca-hf-2 通用检查；旧结果无此端口，不自动升级。

知识回答和资料读取须留在既有 Run、模型计量、Tool 边界与交付合同，知识回答不获得科学资格；外部文本不能授予权限。优先版本化官方资料，检索适配和实际结果另行记录。不建设第二 Agent 或自由脚本接口。

本轮开发真实执行上限：共 32 次模型请求、192000 tokens、已知模型费用上界 USD 0.20、最多 4 次身份查询、4 次结构准备、6 次 ORCA 启动、20 次资料 HTTP 请求。每个 Run 期限不超过 900 秒，4 核/1024 MB/MaxCore 192 MB，全环境一个计算任务。新请求单独计量，历史 Run 不恢复、不重置预算。到达上限如实记录未完成项；代表性三次正式重复和其余验收义务不由单次成功替代。

读取已有 SP 产物时发现 ORCA 的打印 Debye 使用历史换算 2.541798，而非现代常数 2.541746473；原容限未放宽。按 ORCA 教学资料（https://paperzz.com/doc/8017746/part-i---symposium-on-chemical-physics）明确区分 ORCA 原打印值与程序现代单位转换值，两者均保留来源和常数，先按 ORCA 约定交叉检查，再发布明确标注现代转换的数值。

多目标真实登记成功后，旧 12000 UTF-8 字节保守输入界限阻止规划。新输入上限改为 24000（实际 token 仍按供应商用量结算），新本地配置采用该值；每个 Run 总 token 仍为 48000，旧 Run 冻结上限不变。减少重复材料保留，但不为满足单目标遗留限制继续堆叠编码。此变更是新任务容量扩展，不恢复既有失败。

真实知识任务暴露模型将 Tool 名作为 action 的自然意图。v33 / decision-intent-2 明确声明可立即调用的 Tool 名及参数 schema，并由程序转为既有 call_tool；只有冻结发送 schema 和当前许可都存在、且 Tool 定义允许立即调用才接受，不开放任意函数。主循环使用通用 Tool 契约，未加入化学工具名分支。

官方文档检索使用固定版本化 URL 索引，每次至多一个 HTTPS GET（不跟随重定向、不带认证、不自动重试，12 秒、1 MiB），费用为零的公开文档读取，仍按 knowledge_queries 计量。正文摘录保存于不可变 Result，记录 URL/标题/hash/访问时间和未知发布日期。此能力不等于全网文献搜索。知识答案是非科学交付，不生成合格科学端口。只读追问创建明确关联来源的轻量 Run，原科学预算不迁移，来源事实每次消费前重新核验。

32 次实际调用后定位检索摘录被旧 1024 字节投影隐藏的问题；已取得文档仍只显示 hash 导致模型重复查询。修复后在用户“继续完成、快速解决”授权范围内增补最多 6 次开发模型请求，累计上限 38 次，其余累计 token/费用/科学执行上限不增加；先记录再执行，旧失败及费用全部保留。
