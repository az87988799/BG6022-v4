# 登记限制告知与规划目标绑定契约

日期：2026-10-08。依据用户采用的修复方案第 7–10 节，以及第二开发候选的真实 N06、V06 失败继续修复。遵守蓝图第 3–6、11、12、14 节；保持七对象、单一循环、权限、科学判据和累计预算。

## 证据与问题

候选 `repair-cycle-20261008-development-2` 冻结提交 `65947b1`，提示 `agent-json-v23`。N06 首答因多余根字段被拒，一次纠正后登记被程序接受，但实际文字只说明乙醇未登记及缺几何，没有独立明确当前科学能力仅支持 H2O/CH4。最终独立复核判语义和限制披露失败。第一版复核及其修订理由保留，不能把程序接受等同于解释通过。

V06 两答都是被拒的初始规划。首答把诊断码当成 Goal ID；第二答纠正 ID，却在一个目标绑定中同时填 `step_key` 和 `gap`。两次拒绝均有效，未启动分析或 ORCA。第二答还有把 energy 结果说成已经绑定 sampling 端口的事实错误。失败依赖为规划协议，不据此推断终止渲染器缺陷。

完整科学范围、当前 Goal ID、许可和零科学额度都存在于原发送请求中，不能声称事实被删。可直接修复的接口缺口是：规范化的缺项告知只检查非空，未验证独立限制覆盖；规划 schema 的 `goal_map` 是任意字典，模型只见示例，互斥约束直到转换成持久绑定时才触发。缺 Goal 的纠正又仅举 gap 一种例子。引用被池化增加阅读距离，但不是丢失证据或模型错误的唯一原因。

## 选择

规范化保留现有 `notices: list[str]` 结构，增加版本化的局部告知合同。程序从已校验的目标身份和实际缺几何事实生成适用的有限完整语句；模型必须自己选择并原样提交必需项。程序检查当前适用性和覆盖，不插入、替换或润色回答。科学能力边界与缺少输入各有独立告知。未知身份不擅自等同于已知不支持的体系；多目标中部分缺输入不能描述成全部缺失。自由 reason 和额外文字继续独立评测，有限选项通过不保证任意附加主张正确。

新规范化提交记录 `registration-notices-1` 的局部检查事实；候选 JSON 的 `request-semantics-2` 形状不变。历史已接受决定、费用和评分保持原字节，可读取和报告，不批量迁移成新合同通过。没有待答问题的 registration_only 不因这项检查增加用户问答。

规划使用三个闭合的局部类型表达目标路由：未来 Step 输出、已有证据、明确 gap。每项都保留请求端口，且只允许一个来源。同一类型生成 schema，并用于完整接收校验；它们是临时提议的嵌套结构，不新增长期对象。持久 Plan/OutputBinding 继续沿用原格式。错误在参数路径上报告，缺 Goal 诊断提供准确 ID/端口和互斥形状；程序不替模型选择路由或工具。计划指向一个未来输出不代表目标已完成。

完整规划 schema 加入后使水的部分合法输入链上下文超出 12000，因此模型侧采用从同一完整类型生成的结构投影：保留闭合顶层、1–8 Step 数量、目标路由三选一、端口类型和额外键限制，只不展开 `steps.items` 与 `EvidenceRef` 的内部字段。系统提示明确标注结构摘要，既有 Step 和引用例子保留；全部嵌套字段仍在接收端验证，Tool 参数 schema 不变。该投影不是完整 schema 的等价替代，不能据它单独断言所有参数有效。另行使用的单次引用内联、闭合分支合并、穷尽动作条件合并是等价表示压缩，有独立正负矩阵检验；这两类处理不得混称。闭合分支都只向共同必需字段增加一个来源字段时，用共同字段必需加精确属性数表达三选一，保留各字段类型和禁止额外字段；其他分支不适用该简写。它解决了原生长 Goal ID 与纠正共存时 12044 的超限反例，修复后的该完整合成链最大输入为 11930；未放宽 12000 上限或删掉 Goal ID 防护。

独立审查还发现：没有绑定自身体系的命名 Goal 会借用另一已登记体系的几何或 prepare 意图，掩盖缺输入。修复按目标身份限定隐式几何关系；已有显式绑定与历史无身份字段的行为分别保留，未知或冲突身份不能借无关体系解除缺项。另保留任意合法 Step 符号标签，持久 ID 仍由程序生成，不因临时引用类型化而额外限制中文或带空格的标签。

当前目标 ID 保持直接可见：仅当既有原生 `AUTHORITY.goal_status` 的键与当前目标集合完全相同才用作复制位置，否则保留 Request Goal ID 的原生值。最终键编码也保留该状态子树，不能把真实 ID 替换为 `$N`。历史兼容 Run 含已退出目标状态的合成反例触发了集合包含判断的缺陷；核查的 161 个实际 Run 未发现这种残留，不将其描述成已发生的证据污染。提示区分诊断码和终止解释短引用。schema 与已有例子去重，容量仍受 12000 输入、2000 输出、48000 单 Run tokens 限制；保留科学事实、来源、条件和未知项。提示升为 `agent-json-v24`，发送前及接受守卫同时覆盖旧 v22/v23 和新 v24。

新规划结构 schema 仅进入带发送快照的当前上下文。无快照的历史只读重建保留原先规划例子和容量，不把它升级为当前可发送合同；既有发送守卫拒绝这类上下文。历史原始请求、回答和评分不变，新版显示文案与输入大小单独验证。

仅在带发送快照的紧凑 planning 展示中省去 Request 的 `id/version` 副本；不可变 Request、发送记录及 sidecar 保存完整绑定，响应版本仍取原生 basis。无修复许可时，只对从未出现在任何 Attempt/Call 预约中的 Step 省去逻辑 ID 展示，保留或修改该 Step 时程序按 Step key 绑定原逻辑身份。已预约的失败、活动或已完成 Step 均不受此规则影响；尤其用户明确更改几何后，合法重规划仍可能需要其原逻辑身份，不能只按“是否成功完成”判断可省略。原 Plan/Run 不修改。

对于全部当前 Goal 均为已冻结采样/采样检查规格的规范化入口，`available_evidence` 只显示原映射引用、hash 和 `planning_only` 用途。该入口只能按 `analysis_goal_ref` 原样继承规格，不消费单个科学输入或据能量改造规格；全部 Goal 判据、坐标、角色、当前 Request/System 条件和来源仍显示。规划恢复完整证据映射，原 Request 不变。这里不支持推断“取最低能点”之类未解析的新需求；不允许用展示省略来声称证据不存在。

带发送快照的紧凑规范化输入也省去仅供展示的 `SCHEMA_SHA256`，完整 schema 仍在同一发送记录中，可独立展开并核 hash；原始发送字节、请求 hash、当前 basis 与 sidecar 不变。六项 reason 说明在系统提示保留一份，不再另附重复模板。历史无发送快照投影及终止专用 schema 摘要保留原约定。这些是显示去重，不能修改接收 schema 或历史证据。

不采用仅加一句提示、放松互斥规则、把不支持分子换成水、自动改写被拒原答、以确定性报告抵消模型解释失败或挪用正式预算。
