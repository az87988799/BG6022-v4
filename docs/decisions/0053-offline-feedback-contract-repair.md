# 复测后的离线契约修复与真实 ORCA 验证

日期：2026-10-20（Asia/Hong_Kong）。

用户要求修复复测分析中确认的问题，先进行离线测试和 ORCA 测试，明确暂不进行真实 LLM 测试。本次不是步骤 7 的又一次正式候选评测；不消费正式重复槽、不覆盖旧 Run、不把开发者编写的测试脚本称为模型自主生成。

## 问题与范围

1. 路径脱敏误删自然语言中的斜杠；局部几何判断混入结论警告、随机种子要求；规范化不同校验层的错误逐次暴露，无法有效利用有限纠错。
2. 工具计数成本未完整进入模型目录，计划审批未检查共享工具计数的总需求；SDK 的初始几何前条件与上游可见描述、检查时点不一致。
3. 启动前失败的步骤仍被显示为 ready，而执行准入禁止原样重试；最终解释虽预留一次模型调用，耗尽规划余量后却没有切换终局交付。
4. 文档目录命中和二进制乱码读取容易被当作可用于编写输入、解析器的证据。需要更清楚的资料覆盖、格式与有界读取反馈，以及基于实际输出的离线/ORCA 验证。

修复使用现有 Request、Plan、Step、Tool、Run、Result、Artifact、局部字段与函数，不引入新领域生命周期，不添加按科学任务命名的求解工具、生产解析器或任务答案。模型生成错误只能通过通用契约、反馈和验证改进；无真实模型复测时不承诺已证明模型能自主完成七题。

## 契约

- 自然语言中的分隔符不能被视为文件访问授权，也不能因类似路径被任意截断。真正的主机路径仍以注册引用代替；原始证据和原文 hash 不变，投影与引用校验须兼容。
- 几何约束限定在几何相关语境，种子可复现性和对结果的警告不能变成相反的几何条件。保持用户原目标、逐字来源、最低证据、默认采用及未支持项告知；不由程序默填科学条件。
- 工具计数成本来自唯一 Tool 定义，模型目录、Plan 审批和执行预约使用同一计数映射。检查所有未结算的已知必要调用，按共享计数汇总；已结算调用不重复计入未来需求。保持原额度及实际消耗，拒绝超限计划，不通过增加预算掩盖失败。
- 新 Python 提案显式声明 `sdk_orca`：false 为纯分析，不强制需要几何并拒绝 SDK ORCA 请求；true 在批准与预约前检查原科学权限、当前已准备/已注册初始结构及条件绑定。旧字段缺失保持旧序列化 hash 与执行检查；旧任务代码修复必须给出声明，既有显式模式不允许通过修复改变。派生候选不能替代合格初始结构，未知或失败身份不能发布为成功。
- 已结算失败不再因“未启动”被视为可原样执行；修复须新输入和明确修订，未知执行先对账。通用原生输入可在同一 logical Step 中修复输入及副本 manifest，保持体系、条件、观察和依赖；前次失败 Result、执行回执、冻结输入和原始来源须完整绑定且 hash 一致。就绪提示与准入门槛一致，不删除原样失败重试保护；旧结构化 SCF 修复范围不扩大。
- 要求解释且只剩最后一次调用或决策轮时，动作集合切换为终局交付，发送前仍复核同一依据、实际剩余预算和用户消息。token/time 容量继续使用原保守检查，本次不扩展其切换策略。未完成目标保持 partial/insufficient_evidence；终局失败仍生成确定性报告，不额外调用或重置计数。
- 资料读取不暗中追链、转码、转换或执行。二进制/非文本读取须明确失败或不可用事实；目录链接只表示后续可查询位置，不代表章节语法已被读取。新检索仍走既有显式 Tool 与预算。

## 验证与退出条件

先用完整历史失败输入、候选和反例做离线回归，覆盖实际 wire 投影、规范化、计划审批、真实 SDK 准入及失败后的下一决策。离线默认禁网，脚本化 transport 仅为测试输入，不连接模型服务。不得使用模拟科学结果冒充真实 ORCA。

在稳定源码快照上运行相关回归；真实 ORCA 使用已有固定 Linux 容器、原环境租约和 4 核 / 1024 MB / MaxCore 192 / 并发 1 基准。以显式开关执行小体系和与本轮缺口相关的原生输入、SDK、输出读取/任务分析验证，设置有限次数与时限，记录所有失败和实际启动。具体矩阵在运行前保存；任何追加须由失败诊断与本次授权范围支持，不进行真实 LLM 测试。

交付记录修复范围、稳定源码 hash、离线通过与失败、真实 ORCA 原始证据、累计成本和未验证项；旧两批正式证据与账本不改写。完成后按仓库授权提交、推送，等待用户验收；七题自主任务和步骤 7 完整标准仍待后续真实模型验证。

## 未采用方案

不放宽身份或科学资格、不把任务内生成 XYZ 自动当合格初始结构、不允许原样失败输入反复启动、不增加模型或细项预算、不为七题内置专用算法、不使用真实模型试探修复。

## 快速失败而启动采样未确认的局部修复边界

真实 ORCA 探针发现原生输入错误可在容器轮询取得 `/proc` 可执行文件证明前退出。此时可信执行器可已完成工作进程静止检查、容器终止和归档，仍须保留 `orca_actual_start_unconfirmed`、`started=false` 与 `actual=0` 的历史事实；原始 stdout 中的程序标识不能代替实际启动计数证明。

允许不同输入的同 logical 修复仅增加一个窄例外：前次 Attempt 与 Result 已终结为 failed，执行回执 reason 和启动状态分别精确为 `orca_actual_start_unconfirmed`、`unconfirmed`，`not_started` 为 false，退出码是非零整数（排除布尔值），回执中的 linux-container / orca / gated_launcher handle 与 Attempt 精确一致且含容器、launch 和有效进程身份；可信资源回执记录整数 `active_processes=0`。继续要求完整收集、原始输入及回执 hash 绑定、无控制中断/对账/未结算内部执行。unknown、缺字段、仍活动、身份不符、零或布尔退出码均不准入。

该例外只证明可以提出并审批新的输入尝试，不补记实际启动、不宣告科学通过、不改旧 Result、不恢复额度。后续仍由原 Plan 修订、不同输入指纹、同 logical 尝试数、累计 ORCA 预约和额外启动上限约束；不自动执行或原样重试。离线测试使用合成归档回执验证正反例，真实 ORCA 验证另行记录。
