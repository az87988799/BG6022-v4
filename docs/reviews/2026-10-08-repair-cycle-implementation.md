## 实现范围

- 从现有 Goal 适用性检查生成统一交付事实，保留数值、单位、判据、成员角色、当前条件、来源及并列阻断。科学输出、原始观察、操作完成与目标完成分别记录。
- 新模型终止采用 `terminal-delivery-1`：逐目标核对事实、解释关系、必须披露的阻断及允许的后续动作。模型自由 `reason` 原样保存供独立评分，不作为机械验证过的科学正文。
- 终止决定、应用标记、Run 状态及局部收据原子保存；报告发布单独记 pending/rendered/failed 与不可变文件 hash。恢复不重复调用；显式重开需重新决策。接受前再次检查来源，报告读取时也复核来源及文件 hash。
- `agent-json-v22` 统一规范化、规划/反馈、终止及真实澄清的决策用途，发送和接受使用同一合同。预留最终调用、tokens、轮次与时间；未满足目标也能使用最后一次终止机会。上下文只做声明过的可还原去重，硬上限仍为输入 12000、输出 2000。
- 生产代码读取已保存计划、环境、许可和收据 JSON 时显式使用 UTF-8，与写入格式一致；避免 Windows 默认 GBK 在中文路径处解码失败。固定 E2E 测试保留实际中文临时路径验证。
- 增加有限采样“检查是否达标”的意图及 Tool 输出，复用既有科学判据；原 V06 的“取得达标证据”目标不变。纯文本水/甲烷原请求保留，修复了获取初始结构及禁止误称优化结构的中文/英文作用域解析。
- 原累计账本接入固定修复周期、最多三个开发候选及条件第二正式轮。每个操作绑定候选、固定分项、唯一槽、活动时间和独立审查；同一失败不得换 ID 原样重抽，正式失败不能跨版本拼接。
