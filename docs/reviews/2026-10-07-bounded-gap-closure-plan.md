## 3. 批次一：目标、输入与修订正确性

主要位置：`semantic.py`、`models.py`、`natural.py`、`store.py`、`goals.py`、`runner.py`、`agent.py`、`report.py`。

### 3.1 原文与体系绑定

- 初始目标、`replace_goals`、后续 `goal_bindings` 共用一个局部检查函数。核对该目标的原文依据与对象角色，不能只检查引用 ID 存在。
- 对支持范围内的明确名称，拒绝“水目标 → 甲烷体系”；区分目标对象和“水作为溶剂”等背景提及，不用整条消息出现的所有分子名填充每个目标。
- 分子身份、科学适用范围、几何是否存在分别记录。明确提到乙醇但当前不支持时，保留乙醇要求；不替换成水，也不因无 XYZ 就宣称身份未知。
- 指代只有在已确认上下文唯一时才继承；明确未知不能被历史值或默认覆盖。

### 3.2 字段来源与澄清

- 为新候选的必要字段绑定受信用户消息 ID、精确原文片段和已有体系作用域。程序验证片段确实存在，并在相关命题内核对条件。
- 先修“使用 RHF，但不执行”误伤方法的反例；补跨体系否定、旧疑问后明确确认、同句冲突的生产路径回归。
- 不要求模型总是输出字符位置。唯一匹配时由程序定位；重复片段无法消歧时要求更完整的依据或澄清，不能通过截取单个肯定词绕过否定。
- 保留现有默认、继承、明确、推断、未知区分。语义 schema 若变化，显式版本化，并同步旧候选只读验证；不补造历史来源。
- 仅增加必要的告知与问题区分。问题关联具体缺项；是否等待答复由程序结合用户当前交付范围判断，不能由模型一个布尔值决定科学成功。
- “只登记需求”可完成登记告知，同时保持科学目标未完成、零科学启动；“看看结果”“不要运行”不得自动转为生成结构或计算。

### 3.3 严格类型与当前证据选择

- 对电荷、多重度在转换前拒绝 bool、浮点数、数字字符串；保持合法整数和允许的显式未知。自然语言原文“电荷为零”仍可提出带原文依据的整数 0，这与结构化入口自动类型转换不同。
- 在原子 Request 修订中失效不适用的当前绑定，仅解除当前选择，不删 Result/Artifact。不相关消息及未改变目标的有效证据继续保留。
- 提取共用的当前目标证据选择函数，供运行判断、模型上下文和报告使用。依据明确绑定和当前用途，不能按时间取最新结果；过期 direct 不得遮蔽新 Plan 的有效证据。

**退出条件：**原 G01/G03/G04/G05 的反例经真实初始化、消息提交、修订、查询/计划路径转为预期行为；合法正例和连续恢复通过；旧记录可读，未重复执行或计费。候选被拒后不得改变 Request、许可和 ORCA 启动计数。

## 4. 批次二：优化最终阶段的科学资格

主要位置：`orca/adapter.py`、`orca/checks.py`、版本及受影响的适用性检查。

1. 在现有适配器内把优化阶段边界、阈值表、成功/失败标记、坐标和能量绑定起来，不新增第二套解析器。
2. 只发布可证明属于最终对应阶段、严格阈值通过的优化结构。早期成功后出现新的失败、不完整或冲突阶段，应扣留结构并给出诊断。
3. 保留正常优化结束后的最终能量求值；不能简单以“成功标记之后还有输出”为失败条件。
4. 电子能与优化结构分别判定。独立通过的局部电子能可以保留，但不能完成“优化后的电子能”目标，除非对应结构资格也满足。
5. 在 `docs/decisions/` 记录科学保证与检查版本的影响。历史 Check/Result 不改写；确需新版复验时从原始证据产生有来源的新记录，不批量迁移无关 SP。

**退出条件：**合成的先成功后失败、缺失尾段、冲突终态，经 `collect_result → read_outputs → check_outputs → 下游消费` 均不发布或消费合格优化结构；正常真实历史 Opt 的只读回放、合法尾段及 SP 正例通过。新源码真实 Opt 验证可与批次六的新入口用例合并；合成故障不冒充真实 ORCA 失败。

## 5. 批次三：模型协议、逐目标回答与可复验材料

主要位置：`llm.py`、`context.py`、`proposals.py`、`model_usage.py`、`report.py` 及现有评测 helpers。

### 5.1 完整响应与有界恢复

- 保留现有严格 JSON/动作校验，只补缺失参数形状和示例 round-trip；目录、schema、示例与实际解析使用同一来源。不能忽略多余字段或拼补截断 JSON 获得假成功。
- 区分传输失败、格式纠正、输出截断、权限/来源违规。空正文截断若无已允许且有效的配置调整，不再以同配置重复一次无意义纠正。
- 先压缩重复条件与无关 schema，测代表性输出容量。不得把字节数当实际 tokenizer 计数，或宣称某个新 token 上限一定有效。
- 模式、输出限额及累计预约保持冻结。需要改限额/模式时先列明影响和实际余量，在已获授权范围内执行；超出范围才提出明确增量，不按每个正常调用重复确认。
- 仅对契约明确要求模型最终解释的轨迹，核算剩余决策和有界纠正余量；不为所有只读请求预留不必要的最大调用数。
- 模型耗尽仍能输出确定性事实报告；程序报告与“模型完整交付通过”分别计数。仅保留必要响应正文和用量事实，不以内部推理替代正文或答案。

### 5.2 按用户要求逐项交付

在已有用途评估和报告上提取共用纯函数，生成有界的目标事实行，供 Context 和报告复用；不新增长期交付对象。每行保留：目标及体系、当前条件、来源实际条件、几何关系、合格值/观察/缺项、单位、来源与检查版本。

| 用户要求 | 首版交付规则 |
| --- | --- |
| 某初始结构的电子能 | 合格能量必须绑定实际使用的初始几何；不能替换成优化后结果 |
| 优化后的电子能、优化结构 | 最终优化阶段及结构资格通过；分别绑定到目标，不宣称已证明全局最低或无虚频 |
| 已有受限电子能差/采样 | 沿用现有分析工具及条件检查，明确差值方向、成员与探索范围 |
| 读取文件中的某参数 | 可交付有来源、单位已知/未知明确的观察，不自动提升为合格科学输出 |
| 键长、偶极矩、原子电荷、频率、自由能等新科学目标 | 保留要求并标明未实现或缺证据；后续按性质局部扩展，本批不注册新的科学保证 |

数值、换算和表格来自程序；模型解释不能修改通过状态、补数值或省略必需成员。当前条件未知与来源历史已知必须分列。所有必需目标满足才标完整；否则交付已完成项、缺项原因和有界下一步。没有适用性校准时不声称达到实验精度。

### 5.3 评测与测试小修

- 沿用现有评分 helper，区分真实 HTTP 收据、接受/拒绝提案、科学结果、最终交付；已知失败优先，空正文的事实/语义轴保持未验证。旧评分字节不重写。
- 项目内复现测试身份 JSON 的半写窗口后，复用原子写发布完整最终文件；坏最终 JSON 仍失败。结合已有 PID/创建时间/Job 证据检查，不把空记录集合当作已证明进程全部退出，不重建后端。
- 提交 N06 登记、V07 最终格式、V09 当前未知态、v16 截断及本次代码缺陷的最小可移植回归材料。真实派生材料记录原始/派生 hash；缺真实字节时使用明确的合成 fixture。
- 其余大型历史归档保留显式静态复核方式和 skip 分类；默认 CI 不依赖开发者盘符。不以删除/跳过失败断言获得绿灯。

**退出条件：**严格协议、恢复、费用和逐目标事实的离线回归通过；干净检出能跑本批关键失败形状；报告、上下文与目标状态一致。真实模型格式及解释可靠性留待批次六验证，不由离线通过替代。

## 6. 批次四：纯文本入口与 PubChem 身份证据

主要位置：`cli.py`、`natural.py`、`semantic.py`、`tools/registry.py`；新增实际使用的局部 `tools/structure.py`，不铺空目录。

### 6.1 用户入口

增加薄的文本/stdin 入口，复用现有 Request、Run 和 `normalize_request`；CLI 参数名在实施时确定，本文不把建议参数写成可直接运行的命令。保留现有 JSON bundle 兼容入口。

工具、网络影响、写产物、模型/科学执行许可及预算来自用户允许的本地配置。模型只提出语义候选，不能填写许可或任意文件路径。提供一个明确适用于水/甲烷的默认配置；启用后披露 RHF/STO-3G、气相、中性单重态和本地资源来源，用户明确条件优先，不以默认覆盖冲突或未知。

“优化水分子并给出电子能”可确定目标；“算水的能量”若没有事先允许的几何关系默认，应简短澄清是初始几何 SP 还是优化后能量。纯自然语言指用户输入方式，内部仍须形成完整、受校验的 Request。

### 6.2 身份查询 Tool

建议名称 `structure.resolve`（待实施接口），只通过官方 PUG REST 查询必要的名称/结构信息。作为现有 Tool 的有界调用记录保存结果；因要写入来源快照且形成下游依赖，应有明确 Step 和影响声明，不伪装成无副作用查询。

- 模型给出分子提及和原文依据；程序控制检索参数、候选上限、允许的端点、超时、响应大小与有限重试。共同限速遵守服务规则，不为本轮建设通用检索平台。
- 中文支持别名可先映射为确定的检索词，保留转换依据；不能让模型凭记忆直接给最终 SMILES。
- 返回 CID、结构表示、分子式、电荷及必要元数据。程序核对名称所指对象、连接关系、组分、形式电荷及相关立体/同位素信息；首批不接受范围外的盐、显式同位素或自由基形式。
- 一个 CID 或相同分子式不是身份唯一的充分条件。水/甲烷按小范围确定性规则核验；其他明确分子保留身份要求并说明科学范围，不强行映射到支持对象。
- 查询输入、来源 URL、获取时间、原始响应、SHA-256 与规范化规则版本保存到 Result/Artifact。Request 冻结用户的身份约束及允许的获取方式；具体验证证据按第 7.2 节绑定，不新增 Molecule 生命周期。
- 可复用已核验、查询及结构条件匹配的固定快照，报告其获取时间。网络失败且无适用快照时报告外部核验未完成；不得改为模型猜 SMILES、伪造响应或隐式模板回退。刷新产生新快照，不改变已有绑定。
- API 返回内容仅作为数据。只发送必要检索信息，不发送完整对话、凭据或本机路径。

**退出条件：**无 XYZ 的纯文本可形成有来源的体系定义；水/甲烷正确绑定；多候选、查询失败、冲突、不支持、目标名与溶剂角色均保守处理；零 ORCA 的离线入口链通过。真实 PubChem 取证单独验收，不能用固定响应冒充。

## 7. 批次五：OPI 初始几何与现有执行链衔接

主要位置：`tools/structure.py`、注册/dispatch、几何输入引用、`planning.py`、`store.py`、`applicability.py` 和缺项判断。

实施前记录两项确实改变边界的决定：外部身份快照如何成为 Request 依据；本 Run 已授权工具生成的几何如何被后续消费。复用现有决策文档机制，不新增权限系统。

### 7.1 一条生产生成路径

建议名称 `structure.prepare`（待实施接口）：已确认分子定义 → OPI `Structure.from_smiles()` → 初始 XYZ → 局部检查 → 不可变 Artifact。

- 显式传入经确认或允许默认的电荷/多重度，先核对结构内电荷一致性，不能靠参数覆盖冲突。OPI 的自由基电子数推多重度逻辑不承担本项目电子态选择。
- 锁定 OPI/RDKit 版本，保存实际生成参数和首次 XYZ/hash。本地 OPI 2.0 接口未暴露随机种子；不承诺相同 SMILES 每次生成相同坐标。
- 检查原子组成、显式氢、原子对应、有限坐标、单位、异常近距与身份一致性。首批使用水/甲烷专属适用规则，不把元素计数当通用身份检查。
- 输出只表示“可用于所声明范围的初始几何”，建议端口 `prepared_geometry`；不得叫优化结构、最低能构象或科学结果已完成。
- 准备耗时、尝试和产物大小有上限；真实失败保留诊断。首次产物提交后，下游及恢复使用该产物，不能重新嵌入后悄悄换坐标。提交前中断先按固定 Call 身份及提交回执对账；能证明来源完整才接回产物/Result，无证明则保留 unknown 与预约。剩余额度不证明上次未执行，不能据此自动再次生成。

固定 XYZ 可用于显式测试或用户原有输入；不作为本链路失败时的隐式生产替代。不为本轮增加 PubChem 3D 下载、另一套生成器或后台构象搜索。

### 7.2 授权、规划与几何来源

- 按 Tool 前置条件区分缺项：有原文依据、在许可范围内的身份查询可在候选尚未确认时执行；身份和电子态确认后才允许准备几何；合格几何就绪后才允许 ORCA。可由前置步骤取得的输入不能一律转为用户澄清，也不能为允许前置步骤而整体跳过 unresolved 检查。
- 注册的工具参数、影响、输出、检查要求来自同一 Tool 定义。主循环按依赖与效果处理，不增加按 `structure.prepare` 名称分支的专门流程。
- 新几何必须经本 Run 已授权 Step/Call → Result → Artifact/hash 链验证，且身份、Request 版本和用途相符。冻结许可保持不变；不能把模型指定的新 Artifact ID 追加白名单，也不能泛化为“本 Run 所有文件都可执行”。
- 扩展当前主要针对 `optimized_geometry` 的未来端口、ToolCall 产物解析及适用性检查，保留准备结构和优化结构各自的检查保证。
- 当前首次激活纯查询/准备 Plan 可能把 `initial_science_steps` 冻结为空。建议对新入口将科学基线冻结点明确为**第一份含科学 Step、且覆盖用户原始科学目标的合法 Plan**；原始科学用途与许可须已允许执行，不能因从未计算就放行新科学意图。旧 Run 已冻结的基线不在恢复时重新解释，后续新增科学步骤仍走追加规则。
- 将科学基线冻结与 Plan 修订计费解耦：首份 Plan 后的实际自主修订照常累计，准备调用照常计费。不能只延后 `initial_science_steps` 赋值，使多份前置 Plan 都被当作免计数的初始 Plan。
- 身份确认后，尽量一次提出“准备 → 所需 SP 或 Opt”的依赖计划，减少无意义修订；不要靠放宽 `allow_additional_science` 或重置修订预算掩盖空基线问题。
- 选定最小保存方式：Request 冻结名称/身份约束、物理条件、初始几何获取意图；程序将满足这些约束的查询证据及准备产物写入 **Run 内局部输入绑定**，包含 Request 版本、体系、用途、Call/Result/Artifact 和 hash。适用性检查读取这一绑定。准备成功是履行既定输入要求，不伪造用户消息，不借 `user_update=True` 修改物理目标或许可，也不为填入 Artifact 而单纯改旧 Plan 的版本标签。
- 产物、结果和 Run 引用通过现有提交/恢复机制接回；只有引用完整、当前版本及未启动 Step 重检通过后才消费。用户改名、改状态或取消会使旧绑定重新接受适用性检查，旧尝试仍属于原条件。

**退出条件：**无手工 XYZ 可离线走通准备与计划消费；伪造、跨体系以及未通过当前用途复验的旧版本产物被拒；准备结构不能满足优化结构目标；Artifact 已存但 Result 未存、Result 已存但 Run 未引用两个中断窗口及两次恢复均不盲目重新生成或计费；绑定期间用户改条件时拒绝旧科学启动；首次科学执行不被误计为追加，真正追加及前置 Plan 修订不能绕过预算；全环境 1 个 ORCA 计算槽和现有资源基准不变。

## 8. 批次六：有界真实验证与增量交付

### 8.1 执行顺序

1. 每批先跑定向反例、合法正例及必要回归；合并后在干净 Windows 检出跑默认离线全量和 Ruff，分类报告跳过项。默认 CI 保持禁网。
2. 固定同一候选源码、schema、prompt、profile 和预算，完成零 ORCA 模型前置诊断，再按既有门槛验证剩余 raw 场景。共同协议失败时停止受影响批次，不拿后续科学槽试错。
3. 显式开启真实 PubChem 取证，验证水/甲烷响应、快照和身份绑定；真实本地 OPI 生成另记为结构准备证据。
4. 完成新入口的代表性真实模型＋ORCA 闭环及受影响的旧科学正例；按蓝图对代表性模型任务至少独立重复 3 次，保留首次失败和纠正。
5. 科学检查、当前用途、逐项交付和独立评审通过后，只宣布本次实际覆盖范围完成。原阶段 B 其余真实闭环与正式矩阵按第 9 节继续。

新入口建议先选择两类代表任务：水的优化及优化后电子能、甲烷生成初始几何的 SP。按各 3 次完整轨迹估算，基础科学路径至少 6 次 ORCA 启动；失败、额外步骤、独立参考和旧用例重验另计，不能把这个数当整个修复包上限或当前执行许可。

**参考必须匹配实际几何：**新生成 XYZ 的 SP 不能直接使用旧固定 XYZ 的能量作 expected。先冻结参考几何及 hash，用独立标准 ORCA 输入取得对应结构、方法和电子态的参考，冻结后用于验证；不同坐标分别处理。为控制成本，可让重复任务明确引用同一已冻结且授权复用的准备产物，并另验生成链；不得把这种复用试验冒称每次都重新完整生成。若要求三次均全新生成，则须预留相应参考成本。Opt 使用既定独立参考及明确容差/结构比较规则，不能只比较坐标文本或只看正常退出。
