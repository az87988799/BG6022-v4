## 1. 本轮范围与阶段目标

本轮只交付执行方案，不修改运行时代码，不调用付费模型，不启动 ORCA，不更新能力为“已实现”。用户后续明确要求实施后，按本文件的依赖顺序及指定范围推进；本文件本身不扩大执行授权。

阶段 B 的完成目标：在现有本地真实计算底座上，实现一个受目标、许可、科学检查与累计预算约束的 Agent。它能够处理自然语言及多轮补充，生成合法 Plan，执行真实计算，查询和导入已有证据，完成一种可复算比较，并根据失败或成功结果决定修复、追加、澄清或停止。

阶段退出必须同时满足：

1. 总蓝图第 13.3 节的 11 类场景全部有对应验收证据。
2. 真实初始规划、真实失败修复、成功反馈再规划分别形成真实模型与真实 ORCA 联合闭环。
3. 不同成功观察能导致不同调整；充分证据时停止；真正修复耗尽后停止。
4. 七对象、唯一主循环、统一 Tool 边界及已有科学和执行保证不退化。
5. 提交证据、适用范围、失败、未验证项和成本；交付后等待用户验收。

### 1.1 科学范围

沿用已验收的 Windows 本地后端、ORCA 6.1.1、OPI 2.0.0、MS-MPI、H₂O/CH₄、中性单重态、RHF/STO-3G、SP 与严格无约束 Opt，以及现行 orca-hf-2 科学规则。

新增科学应用仅限：

- 条件相容的电子能差与有限成员结果表。
- 对已登记几何候选进行有限 SP 采样，并依据结果选择一个局部加密点。
- 已验证 SCF 诊断对应的有限参数修复。

不将本阶段扩展为通用 DFT、频率/热化学、通用几何生成、完整扫描引擎、过渡态、远程集群、Web 界面或常驻服务。用户要求自由能、光谱等未支持能力时，保留其目标与条件，说明缺项；不能默认换成 HF 电子能。

### 1.2 架构范围

长期领域对象仍只有 Request、Plan、Step、Tool、Run、Result、Artifact。模型提案、目标检查项、调用记录、待处理用户消息、成员清单和执行快照均作为局部类型存在。

继续采用文件存储、原子写入及必要锁，不增加数据库、事件总线、Kernel、Reducer、Service/Repository 分层或多 Agent 产品架构。模块随任务建立，不提前创建空骨架。

## 3. 模型接入与运行配置

### 3.1 官方名称和传输方式

截至 2026-10-06，官方文档给出的名称为 **DeepSeek-V4.1-Flash**，API 标识为 **deepseek-flash**，OpenAI 格式 base URL 为 **https://api.deepseek.com**。不使用自行拼写的 deepseek-4.1flash。[官方模型表](https://api-docs.deepseek.com/quick_start/pricing/)

首版冻结以下接入方式：

- 单一 DeepSeek 适配器，使用 Chat Completions、非流式请求。
- 显式关闭思考模式；采用 OpenAI SDK 时传 extra_body={"thinking":{"type":"disabled"}}。这是本方案的首版取舍；官方默认开启思考模式，不能依赖默认配置。[思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)
- response_format={"type":"json_object"}，提示明确要求 JSON 并给出动作示例。处理空内容及长度截断；JSON 合法不等于动作合法。[JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)
- 模型返回项目局部动作提案；工具参数 schema 从唯一 registry 生成。本阶段不同时维护供应商原生 Tool Calls 和 JSON 提案两套协议。
- 在 B-04 固定实际采用的 SDK 版本并更新 pyproject.toml、uv.lock；关闭 SDK 隐式重试。未验证版本不写成已兼容。
- API key 只从本地环境变量 DEEPSEEK_API_KEY 读取；配置示例只写变量名，不能保存密钥、请求认证头或包含密钥的异常。
- 不静默回退到其他模型、供应商或模拟结果。缺 key、连接失败或额度不足应记录未验证/失败。

模型调用记录包含：请求标识、请求及响应摘要/hash、依据版本、提示模板版本、SDK 版本、请求模型、响应模型信息、参数、时间、错误类别和可获知用量。供应商提供额外版本标识时保留；不宣称 API 别名固定了模型权重。

预算执行规则：

1. HTTP 调用前持久化计数与 token 上界预约；使用经过验证的计数方式或保守上界，不能将字符数直接当 token 数。
2. 已知用量按实际结算；超时、响应丢失或没有 usage 时保留未知和保守占用，不记为零。无足够余额时不发请求。
3. 401/权限错误不自动重试；可重试网络/限流错误在次数、等待与总期限范围内处理，明确记录每次发送。
4. 同一 Run 的 ID、逻辑身份、预算和截止时间不能通过暂停、恢复或新会话清零；旧 Run 的零模型/修订预算仍为零。
5. 预算耗尽后停止受限的新动作，继续必要取消、对账、收集及确定性交付；这些尾部操作仍有有界资源与超时。
6. 独立调用次数、运行时间和物理资源分别限制，不能将一次 Tool 调用等价为一次低成本计算。

## 4. 核心契约和持久化顺序

### 4.1 Request、Plan 与目标

- Request 保留用户原文、消息来源、体系与比较关系、每项条件的来源、必需/可选目标、未决歧义、最低证据和规则版本。
- 未支持的目标也要可表达为未解决目标，不能因科学参数 schema 受限而丢弃原文或自动降级。
- 用户许可与规范目标分别保存。模型可提议澄清或修订，不能增加许可、预算或降低科学规则。
- Plan 的目标映射允许“已有证据”“未来端口”“尚未解决的目标缺口”；必需目标不能被删除，未决缺口不能伪造绑定。
- 放开当前四 Step 的语法上限到第 3.2 节的有限 DAG 容量；科学启动仍最多四次，查询/分析不会因此获得科学执行许可。
- 旧结构化请求保留兼容读取和无模型执行路径。历史文件缺少新字段时按旧语义读取，不能自动启用模型、迁移科学规则或重写原文件。

### 4.2 动作与调用记录

局部提案至少包含：动作类型、依据的 Request/Plan/许可版本、控制代次、相关 Result、理由摘要和类型化参数。动作限定为澄清、初始规划、受控修订、已登记工具调用、交付/停止；不能接受任意代码或路径。

程序生成持久 ID、路径、hash、状态及预算用量。无 Plan 的只读 Run 可保存即时查询调用及 Result；科学执行必须有 Plan、Step 和 Attempt。导入副本、生成派生 Artifact 或形成下游依赖的分析必须建立 Step。

Tool 的输入 schema、影响、输出声明、检查和执行入口仍从 registry 取得；CLI、Agent、历史查询共用校验，不另开隐藏执行通道。查询不得要求 ORCA 安装、doctor 成功或占用科学并发槽。

### 4.3 修订提交与恢复

普通 save_run 保持禁止任意修改 Request/Plan/许可的约束。新增专用的校验并提交函数，顺序如下：

1. 在唯一协调者下核对当前 Request、Plan、许可、控制代次及依据证据。
2. 校验目标覆盖、Tool 能力、DAG、来源、条件、影响、预算及允许的科学改动。
3. 保存不可变修订及关联的决策依据；同一决策使用稳定标识，重放不得生成第二份追加行动。
4. 原子更新 Run 的当前版本引用、累计用量和已处理反馈标识。
5. 只有已激活版本可启动后续尝试；落盘但未被 Run 激活的孤立修订不能自动执行。

每次科学启动前冻结当时的 Request/Plan/Step/许可版本、实际输入、消费绑定和指纹。恢复旧 Attempt 使用其启动快照，不能从新 Plan 搜索或拼回已删除的旧 Step。

同一 Step 的多个 Attempt 全部保留。下游消费显式绑定具体 Attempt、Result、Artifact、hash 与规则版本；不能按“最新文件”或任意一次成功选择。当前 supersedes_result_id 只用于未知执行补收的替代关系，不用作普通重试、改判或检查版本升级。

跨文件保存不当作数据库事务；必须测试“Result 已写、Run 未引用”“修订已写、Run 未激活”“反馈已生成、追加步骤未绑定”等窗口，恢复要重接引用且不重复计费或启动。

### 4.4 检查版本按用途验证

替换 runner._validate_execution_rules、calculation.revalidate 及 _validate_future_binding 中不适用于混合目标的全局同版本假设：

- SP/Opt 仍要求其适用的 orca-hf-2 规则。
- 电子能差规则声明所需的两个合格能量来源、条件及规则版本。
- 查询规则验证准确提取，不承担对应物理量的科学保证。
- 有限采样目标使用自己的验收规则，并引用合格 HF 能量作为输入证据。
- 旧 orca-hf-1 科学来源未经显式复验不能直接提升或供要求新规则的消费；查看历史事实可以继续。

不能通过简单删除版本判断实现兼容。复验生成带来源的新 Result，保留原 Result 和原检查事实。

### 4.5 多轮输入和唯一协调者

当前协调者全程持 Run 锁。新增外部消息入口在独立短控制锁下持久化有界消息及控制代次，由唯一协调者吸收；不能让第二个客户端直接改 Run。

模型等待期间保留唯一协调责任。模型返回后先检查暂停、取消及新消息，应用合法的用户修订，再核验提案版本。过期提案不能只改版本标签后执行。

前台协调者结束后不承诺后台继续规划。status 只读；显式 resume 先对账再继续。暂停允许当前计算在期限内结束并收集；取消请求停止受管计算并确认状态；未知状态继续保守占用额度。

## 6. 三类真实闭环的固定设计

### 6.1 初始规划

从自然语言开始，模型形成合法 Plan，再执行真实 ORCA。正式初始规划证据可复用左右加密、充分停止、修复和 CH₄ Opt 控制中的首份 Plan，无需额外重复启动相同计算。

证据串至少包含：用户原文 → 规范 Request 及条件来源 → 模型调用 → 合法 Plan → Attempt/输入 → 原始文件 → 逐输出检查 → 目标判断 → 报告。

H₂O SP 只交付合格电子能；CH₄ Opt 检查优化收敛与几何输出，不声称无虚频、全局最低或过渡态。

### 6.2 SCF 修复与真正耗尽

**成功用例：**

1. 使用现有 water_scf_limit 几何与受限 scf_maxiter=1，产生真实不收敛。
2. 模型根据诊断提出 scf_maxiter=100；允许区间与具体候选在 B-01 冻结。
3. 保持几何、方法、基组、电荷、多重度及科学收敛标准不变，创建独立尝试。
4. 真实重跑后，只有输出通过适用检查且满足原目标才计为修复成功。

**耗尽用例：**

1. 冻结最大两次尝试的 Run。
2. 首试真实失败后，执行一次合法修复，第二次仍失败。
3. 程序拒绝第三次，保留两个失败 Result、参数变化、逻辑身份及累计成本。

候选为 scf_maxiter=1→2，但必须经独立参考确认第二次仍失败；不能事先假设任意环境都满足。耗尽用例在执行前明确限定允许的修复为提升至 2，模型不能换成 100 绕过该用例的许可；只拒绝越权提案而没有执行第二次失败，仍不满足真正耗尽验收。

若仅使用真实失败 fixture 和离线执行器证明耗尽逻辑，必须标为离线验证，不能宣称真实耗尽闭环；本方案正式联合评测目标仍是保留真实两次失败的配对证据。无法在预算内冻结该反例时，如实报告未完成。

### 6.3 有限采样、左右加密和充分停止

每个用例预登记五个 H₂O XYZ，指定一个 O–H 距离 r，另一个键长、夹角、原子顺序、单位及科学条件固定：

~~~text
r = c + {-h, -h/2, 0, h/2, h}
初始执行：c-h、c、c+h
允许追加：c-h/2 或 c+h/2 中的一个
~~~

原始几何只读保存；候选列表含坐标来源、hash 和 atom mapping。首版不需要运行时几何生成工具，也不把五个候选都计算后伪装为模型决定。

程序必须从已核验 hash 的 XYZ 实际坐标、明确原子索引与单位重算被扫描的 O–H 距离、另一键长及夹角，按冻结的几何容差确认一维约束。候选坐标标签、原子映射及数值与实际几何不符时拒绝该候选；邻点排序和跨度使用重算的距离，不能信任清单自行声明的 r。

独立参考应先验证：

- 左加密与右加密采用不同的已冻结中心窗口，粗采样中心为明确内部最低点，左右邻区的证据分别支持相反侧选择。
- 给定目标宽度 w，加密类满足 2h>w 且 1.5h≤w；新增选定中点后仍存在内部明确最低点，实际最近左右邻点跨度≤w。
- 停止类使用相同目标含义及足够密的初始点，满足 2h_stop≤w，三点已经足够。
- 能量比较阈值从独立参考与实际输出精度确定，不能采用通用任意常数；阈值用于数值区分，不是方法误差条。

目标通过的确定性条件：

1. 三个初始必需点全部有合格、条件相容的能量。
2. 当前已采样点中存在可明确区分的内部最低点。
3. 该点有合格的最近左、右采样邻点，且相对能差超过冻结的数值区分阈值。
4. 最近邻点跨度不超过 Request 中的 w。
5. 结论明确限定于已采样离散范围。

模型行为另行验收：依据粗结果选择正确侧、不同观察选择不同侧，充分证据时停止。不能将独立参考全部注入模型上下文，也不能在程序中按用例 ID 硬编码选择。

边界最低、近简并、缺点或预算不足时交付部分结果及限制；不宣称连续极小值、全局最低点、振动稳定结构、TS 或完整势能面。

### 6.4 未注册字段与外部文件的固定样例

- 优先使用真实 water_sp 的 property JSON：发现并读取 Geometries[0].Dipole_Moment[0].dipoleMagnitude。该字段保持证据观察身份；未经注册科学检查不能成为合格偶极矩端口，单位不明时保留未知。
- 字段路径属于数据视图时注明视图类型/版本，不能冒充原文件中的精确路径。
- 部分导入使用仅 stdout 或缺 input/JSON 的文件集合；准确返回已有片段及缺失项，不补造运行记录。
- 删除 JSON 的副本用于纯查询反例：报告缺失与后处理需求，科学和后处理启动次数均为零。
- 电子能差正例使用本项目已合格的两个 H₂O 几何结果；不强迫部分外部导入获得科学资格才能完成阶段验收。

## 8. 测试入口与执行命令

### 8.1 独立测试边界

当前 live 标记继续表示真实 ORCA，以兼容已有测试；新增 model 与 e2e 标记及 --live-model 开关。所有新增文件名和开关在对应任务实施后才存在。

| 模式 | 网络 | 科学进程 |
| --- | --- | --- |
| 默认离线 | 禁止 | 禁止；backend 标记只允许既有受控测试子进程 |
| 仅 --live-model / model | 只允许配置的 DeepSeek HTTPS，禁任意地址/重定向 | 禁止，包括本地 _native 入口 |
| 仅 --live-orca / live | 禁止 | 仅允许已配置的真实 ORCA 测试 |
| e2e 且两个开关同时开启 | 按模型测试边界允许 | 按 ORCA 测试边界允许 |

缺 key、缺 ORCA 或开关未启用时标记未验证；skip 不计通过。两个开关均开启也不能放开普通离线测试的网络/进程限制。

### 8.2 现有回归命令

工作目录为仓库根目录；依赖已按锁文件安装后运行：


涉及模型/存储/执行契约的定向回归：

新增依赖只在 B-04 显式解析和安装，提交更新后的锁文件；离线验证不自动联网安装。

### 8.3 新增验收入口

以下是 B-04 至 B-11 应建立的入口，当前不视为已存在：

~~~powershell
# 默认离线；新增 planning/agent/llm/context/analysis/report 的单元与集成测试随实现加入
py -3.11 -m uv run --offline --locked pytest tests/unit tests/integration -q

# 真实模型，只读取冻结证据，禁止科学启动
~~~

离线注入用于验证传输失败、崩溃窗口和权限边界；真实 fixture 验证解析与检查；两者均不能替代模型真实决策或真实重跑闭环。
