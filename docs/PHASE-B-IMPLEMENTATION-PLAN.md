## 1. 交付目标与范围

交付一个通过前台 CLI 使用的 Agent：理解自然语言和补充条件，形成可校验的 Request/Plan，通过既有 Tool 执行；每个新结果先更新目标与计划适用性，再决定查询、修复、修订、澄清或停止，最终交付带来源和限制的报告。

首批科学范围沿用阶段 A 的 H₂O / CH₄、中性单重态、RHF/STO-3G、SP/严格 Opt。为验证成功反馈再规划，拟局部增加 **H₂O 一个指定 O–H 键的固定几何单点路径与有限加密**。该能力须单独验收，不表示通用扫描、约束优化、极小值或 TS 已受支持。自由能和光谱请求先用于“不偷换目标”的拒绝/部分交付测试，本阶段无需为此实现 Freq 或 TDDFT。

本地后端、OPI 责任链、全局单任务额度、不可变尝试与科学检查继续复用。长期领域对象仍只有 Request、Plan、Step、Tool、Run、Result、Artifact。模型响应、调用记录、成员清单和修订差异使用局部类型；不引入新的领域生命周期、数据库、事件总线、多 Agent 平台或后台常驻协调者。

阶段 B 完成必须覆盖蓝图 13.3 的全部 11 个场景。一次自然语言 SP 成功只代表中间里程碑。

## 2. 从当前代码出发的必要改动

| 当前阶段 A 的固定假设 | 阶段 B 的最小扩展与兼容要求 |
| --- | --- |
| Request 必须含单一几何和可执行科学条件；Goal 只有能量/优化结构端口 | 可保存缺项、冲突、查询目标及尚不支持的物理量；对象与条件属于目标本身。未决 Request 可以持久化，但不能通过科学执行校验 |
| Plan 非空、最多 4 个科学 Step；每个目标立即绑定一个输出 | 科学 Plan 保持有界 DAG；允许显式目标缺口和多证据要求。纯查询 Run 可无 Plan，不制造虚假科学 Step |
| Step、Attempt、Tool 名称及参数只支持 SP/Opt | 从单一工具定义提供 schema、影响、资源和输出；实际接入证据、导入、分析及有限结构操作时局部扩充类型，不增加另一套同义注册表 |
| `save_run()` 禁止 Request/Plan 等版本引用变化 | 增加受控修订提交：版本校验、不可变修订先落盘、最后更新 Run 引用；原许可和预算不得由模型改写 |
| runner 遇历史失败即停止，同 Step 的多个 Result 被视为歧义 | 在显式合法修复后允许新尝试；按逻辑步骤、具体尝试、合法恢复替代链及当前绑定区分结果，不能按时间选择“最新成功” |
| `_recover()` 从当前 Plan 找历史尝试的 Step | 历史尝试绑定当时的 Plan/Request 版本和固化 Step 参数；替换或取消待执行步骤后，旧尝试仍可用原契约收集与解释 |
| 执行门禁统一要求全局 SP/Opt 检查版本 | 按能力绑定规则；SP/Opt 继续使用已验收的 `orca-hf-2`，查询、派生量和新几何操作使用各自的检查契约，不能为接入新 Tool 全局放宽检查 |
| 模型调用、计划修订预算固定为 0 | 仅对新启用的模型任务设置有限预算和持久调用记录；旧记录缺省仍为 0，读取或恢复不自动获得新额度 |
| `extra_orca_starts` 当前只统计逻辑步骤重试 | 明确统计修复和初始计划外追加执行，记录初始科学执行清单；换 Step/Plan ID 不能绕过额外预算和总预算 |
| 已有 evidence 只能列文件、读文本及已知字典字段 | 增加字段发现、有界数组索引/切片和文本搜索；同一 Tool 边界审计，仍无求值表达式、自动转换或计算 |
| Result 强制关联科学 Step/attempt | 按实际调用契约允许查询/导入/分析结果，保留来源和操作事实，不伪造 ORCA attempt、耗时或科学资格 |

旧格式兼容不等于自动升级旧规则。读取、取消、对账与补收继续可用；旧证据用于新目标时必须检查其条件和规则。新检查结论追加保存，不覆盖旧 Result，也不滥用专供 unknown 恢复的 `supersedes_result_id`。

## 4. 各任务工作内容

### B-01：冻结契约和验证标准

- 以本方案第 2 节为代码差距清单，逐一写出输入、输出、旧格式行为及失败状态。
- 在 `docs/decisions/` 记录目标/修订、纯查询 Run、工具影响和模型预算的局部设计：问题、候选、取舍、兼容与验收影响。先解决这些边界，再修改运行契约。
- 冻结第 6 节的测试清单：原始提示、条件来源、必需/可选目标、准入范围、停止条件、独立参考、容差、失败判据及预算。缺少实测参考时保留待测，不填入被测输出。
- 成功反馈用例提前固定路径定义、范围、样本数量和“需要加密/已经充分”的程序判据；只对允许的候选动作开放执行。
- 明确拟使用的一个模型服务、模型版本、结构化输出能力、超时、token 计量和依赖许可证的选型要求。尚未选定时列为 B-04 首次外部调用前的待定项，不阻塞本批文档工作。

**本批退出：**用例与契约可审查，预算可算清；不新启动模型、ORCA 或远程任务，不以文档宣称 B 功能通过。

### B-02：目标和计划契约

- 规范 Request 保留用户原文、指代来源、对象/原子映射、条件来源、冲突/未知、必需目标及最低证据。`inferred` 不能冒充用户明确要求，未解决电子态不能靠默认猜测执行。
- 区分“提取文件字段”“获得合格电子能”“获得指定判据收敛结构”“比较指定对象”“不支持的自由能要求”等目标；查询完成不等于科学通过。
- Plan 修订绑定 Request/Plan 基线与新证据。允许显式待探索目标缺口，但只执行依赖和条件已满足的 Step；不能伪造未来端口来覆盖缺口。
- 输入引用从单一初始几何扩展到已授权的具体 Artifact、Step 输出及集合成员。消费时固化 Result/attempt/hash/检查版本，数据存在与科学前置条件分别校验。
- 工具目录、参数验证、影响、输出和模型可见 schema 来自同一注册定义。凡涉及执行、新产物或下游依赖的操作必须形成明确 Step，包括导入快照、结构准备及写产物的分析/报告；即时只读查询可不建 Plan，正常调用审计记录不属于科学产物。所有调用共用边界，科学执行仍必须绑定 Plan/Step。
- 最低检查版本按能力/物理量绑定，不让分析或查询被迫冒充 SP/Opt 科学检查。运行状态表达等待、执行、检查和交付事实，阶段名不进入运行状态。

**定向测试：**自由能被电子能替代、多必需目标漏项、条件冲突、无 Plan 的查询、未知工具/端口、循环依赖、未来结构未通过检查、模型自填科学通过或任意路径均被正确处理。

### B-03：修订、预算与防重复

- 用稳定逻辑步骤身份累计尝试；模型只给逻辑引用，持久 ID/路径/hash 由程序生成。失败换名、取消后重建步骤、追加后再删除均不退还消耗。
- 记录每次模型请求的预占、响应/失败、纠正和可获知 token；SDK/HTTP 重试也计入总调用数。响应丢失或用量未知保守保留占用，不能按零计费。
- 区分提案次数、决策轮数、已提交 Plan 修订、语义纠正、只读查询、科学重试、初始计划外新增执行、内部子计算与资源用量。
- 提交修订及启动前在同一 Run 协调锁下重查 Request/Plan/许可版本和控制信号。先保存不可变修订，再原子更新当前引用；孤立修订恢复时不能自动触发新计算。
- 持久化新 Result 的反馈处理进度与决策依据。结果已处理但追加步骤尚未提交时崩溃，恢复不能把同一反馈再次消费为另一轮追加计算。
- 已启动尝试不跟随新 Plan 改写；按当时固化版本收集。当前适用性变化与原科学结果错误分别记录。

**定向测试：**模型响应落盘前后崩溃、修订保存后 Run 未更新、同一反馈重复消费、Plan 改写期间用户补充、旧作业在新条件下结束、换 ID 耗尽预算、已结算恢复结果重接、两 Run 竞争。继续覆盖 A 的 R-01～R-05。

### B-04：模型接入与多轮澄清

- 一个传输适配器，少量临时响应 schema，动作限定为提出目标/计划/参数、查询、修复、澄清或停止。程序验证后才形成持久事实。
- 先用离线脚本化响应验证正常/畸形/越权/过期提案；缺少真实服务时明确未验证，不静默回退为模拟 Agent。
- 冻结实际 provider/model、SDK/协议、版本、许可证、超时和预算。密钥只由本地配置/环境读取，不进入提示词、产物、错误信息或 Git；服务地址由程序配置，不能由证据内容改变。
- 上下文只提供规范目标、条件、计划摘要、新证据、诊断、候选工具和剩余预算。证据、文件注释、导入文本和参考资料均作为数据；有界裁剪不得丢掉来源和未决项。
- CLI 支持同一任务的补充输入和显式控制；会话文件只做索引。关键歧义提出简短问题并持久等待，澄清期间不执行可能被答案推翻的工作。

**验收：**同义表达、多轮指代、多个历史候选、相互矛盾条件、默认披露和不支持目标各有测试；真实模型结果另列，不以 JSON 合法率代替任务正确率。

### B-05：唯一反馈主循环

- 按蓝图 6.3 推进：先处理控制和对账，再收集/检查/记账，评估目标与后续步骤必要性，最后决定下一动作。每个新 Result 都经过反馈判断，成功也不例外。
- 将现有 runner 中调度决策迁入或收敛为一个主循环；`runner.py` 可保留单步执行、恢复或兼容入口，不能与 `agent.py` 各自推进同一 Run。
- 结构化 CLI 与自然语言入口共用校验、执行和恢复责任链。无模型的确定性路径继续可测试；模型轮询不嵌入后端或科学检查。
- 初始真实闭环先选一个 H₂O SP：真实模型提出合法计划，程序校验，真实 ORCA 执行并检查，目标评估，确定性结果与有来源解释交付。
- 目标已有充分证据时停止；不为“显得自主”追加任务。缺预算或模型失败时仍可取消、对账、收集并交付确定性事实。

**退出：**闭环通过但不标记整个 B 完成；后续查询、比较、失败修复和成功反馈用例仍需逐项通过。

### B-06：发现、导入和复用证据

- 扩展已有证据工具：文件/字段发现、类型与形状、明确数组索引/切片、受限字面文本搜索；分页、最大字节、命中数、深度和时间均有界，不接受代码或任意表达式。
- 先支持用户显式选定文件的不可变快照导入，保存原来源、hash、导入时间、文件角色与未知条件。不做任意目录扫描；如提供外部只读引用，必须实现每次读取/消费前后的 hash 核对。
- 只有 `.out` 或部分旁文件时，用同一 ORCA 适配器提取可靠观察；不为满足现有解析器而虚构 `input-manifest`、原 Plan、原执行时间或 ORCA 资源记录。
- 科学资格所需条件不齐时保留未验证。若要启用完整外部结果的科学资格，单独声明检查依据和正反例；仅供查询的导入不自动获得该能力。
- 历史复用先做按性质要求的精确匹配；新版再验证追加结论与来源。旧检查不能直接满足新版目标。

**退出：**真实已有产物中的一个未注册科学字段可被模型发现和读取，说明单位/验证状态；候选为既有水 SP property JSON 的 `Calculation_Info.NumOfBasisFuncts`，数组路径另做切片测试。缺 JSON 仅返回缺失事实或后处理需求，实际进程启动数为 0。

### B-07：有限比较与报告

- 首个派生量选同一 H₂O 体系两个明确不同几何的电子能差 `ΔE = E(B) − E(A)`。绑定原子身份/映射、电子态、方法/基组及环境；允许目标规定的几何差异，不一律要求坐标相同。
- 由 analysis Tool 确定性计算，保存公式、方向、单位、换算常数/版本、每个操作数的 Result/Artifact/hash/检查版本。模型解释不能替换计算值。
- 拒绝把 H₂O 与 CH₄ 的裸总能量差作为稳定性比较；未知方法/态、来源损坏、缺必要项或用户要求自由能时，不发布不适用的合格差值。
- JSON 和 Markdown 报告列出目标满足程度、科学输出、观察、条件、来源、失败/修复、全部成本及未完成项。数值由确定性结果填充；模型解释失败时仍可交付结果清单。

**退出：**真实两侧结果可独立复算比较；单位/方向错误与条件不匹配反例被拒绝；报告不把结构收敛写成全局最低或无虚频证明。

### B-08：有界失败修复

- 选择阶段 A 已有的 H₂O SCF 限次反例，在新的独立任务中真实触发失败。模型根据诊断提出将 `scf_maxiter` 从测试限次值改到预先冻结的正常上限（候选为 100），程序检查许可和剩余预算后真实重跑。
- 不改变方法、基组、电荷、多重度、目标物理量、收敛标准或硬资源。最大迭代次数变化属于已声明修复范围；许可不足时保留失败并请求所缺范围。
- 修复候选必须来自局部已验证规则；unknown 执行先对账。完全相同的失败输入、无有效修改或重复诊断不能无条件重试。
- 保存失败原文、检查、模型建议、实际参数差异、Plan 修订、每次独立尝试及累计成本。

**退出：**至少一例真实失败经真实重跑获得合格目标输出；另一例在预算/候选耗尽时停止并准确交付不足。受控限次修复不能表述为通用 SCF 难收敛修复能力。

### B-09：成功反馈再规划

- 新增最小受控结构操作：对 H₂O 指定 O–H 键沿固定方向改变长度，其他原子和方向保持，记录初始结构、原子映射、坐标单位、操作参数与 hash。输出角色是路径采样几何，不是优化结构。
- 初始 Plan 只含 3 个已冻结粗采样点的结构准备、独立 SP 及必要分析，不提前加入加密 Step。结构操作和分析如写新产物，也必须有明确 Step 和影响声明。
- 每点使用现有 SP 责任链独立预算/检查；Artifact manifest 保存点坐标、身份、必需性、结果和失败。缺必需点不能宣称完整曲线。
- 获得成功结果后，模型依据能量/条件/剩余预算选择一个有意义的区间与新增点，形成可审查 Plan 差异；程序校验范围、重复点、证据需求及成本后再执行最多 1 个新 SP。
- 本方案以离散采样需求为验收目标，3 个粗点加 1 个新点共 4 次 SP；如粗采样失败后已消耗修复额度，不能再承诺完整加密。若 B-01 冻结的目标确需更多点，应先修订有限 profile 与验收影响，再启用该用例，不能把额外点藏在内部循环。
- 配对用例：证据已充分时不加点；不同合法观察产生不同加密位置；点失败/预算不足/最优样本在边界时如实停止或说明范围不足。固定追加同一点不能通过。
- 用户目标须提前明确为有限路径的采样/加密目标，不能临时降低精度。报告只描述限定路径及已采样点，不宣称连续曲线全局最小、平衡键长、自由能、势垒或 TS。

**退出：**保留初始 Plan、成功 Result、新观察、模型提案、真实 Plan diff、新增真实执行和最终目标评估；至少一条完整真实链，配对分支有明确证据。

### B-10：控制与恢复组合验证

- 覆盖模型请求期间、提案到达后、修订落盘后、启动前、执行中、Result 保存后各窗口的暂停/取消/协调者退出。
- 模型响应依据已过期时丢弃执行资格并重新校验，不能仅改版本号后提交；新用户条件不会回填到旧作业。
- 恢复沿用同一目标、许可、期限和累计用量；取消不被清空，未知进程保持额度。模型余额为零不阻止必要清理、收集与确定性交付。
- 在 XYZ 注释、stdout、导入 JSON、模型结果和参考资料中加入越权指令反例；验证不能读取凭据、修改权限/源码或调用 shell/Python。
- 已启动尝试引用的旧 Plan 即使不再是当前版本，也能正常收集；多个尝试和 unknown 替代链保持唯一合法的当前消费绑定。

**退出：**新增路径与 A 的故障矩阵同时通过，无第二协调者、隐式执行或预算重置。

### B-11：评测与交付

- 将第 6 节全部场景做成固定清单，分别运行离线、真实模型固定证据、本地真实 ORCA、完整端到端测试；远程能力保持未验证。
- 代表性模型任务至少独立重复 3 次，保留首次输出、失败、纠正和重试；报告每类成功率、错误类型、token/请求/ORCA/资源成本。固定证据下的模型重复与包含新 ORCA 的端到端重复分别计数，不能互相冒充。具体通过阈值和允许纠正次数在 B-01 冻结，不能挑最好一次或事后改阈值。
- 验收报告逐项附提示、模型配置、Request/Plan 修订、调用与成本、Result/Artifact/hash、独立依据及失败历史。敏感凭据和完整大产物不进入仓库。
- 更新能力矩阵只列实际已验证能力；提交、推送并核对远端后，交付状态为“等待用户验收”。

## 5. 预算与执行边界

以下为 **B-01 待冻结的初始开发 profile 建议**，不是当前代码能力或新执行授权。可按用例收紧；扩大上限须在执行前显式确定，不得因测试失败而临时放宽。

| 维度 | 建议上限与计数要求 |
| --- | --- |
| 科学资源 | 沿用 4 核、进程树 1024 MiB、MaxCore 192 MB/进程、全环境 1 个任务 |
| 每 Run ORCA 总启动 | 保持最多 4；简单 SP 用 1，比较用 2，粗采样 3 加细化 1；失败重试也占同一总额 |
| 每逻辑步骤尝试 | 最多 3，或用例更小；ID/参数修订不重置已用次数 |
| 初始计划外额外 ORCA | 最多 3，包含修复和新增采样；同时受总启动数约束 |
| 原生后处理 | 保持 0；本阶段缺 JSON 查询不启用转换 Tool |
| Plan | 每个版本最多 16 个 Step（包括结构/分析）；每个 Run 最多 2 次已提交自主修订；初始规划另计但受模型和决策预算约束 |
| 决策与查询 | 最多 12 个决策轮次、24 次证据调用；无新信息不反复调用模型；查询有独立字节/时间限制 |
| 模型 | 每 Run 最多 8 个实际 HTTP 请求，包含传输重试和纠正；每个提案最多 1 次格式/语义纠正，每次失败最多 1 次传输重试，均不额外赠送总额度 |
| Token | 每次上下文最多 12000、输出最多 2000；每 Run 输入加输出总预算 48000。provider 计量口径、估算/预占和未知用量处理在 B-04 首次启用前验证 |
| 时间 | SP 最多 300 秒、Opt 最多 900 秒、Run 最多 1800 秒；模型单次超时最多 60 秒且不能超过剩余 Run 期限 |

纯查询/导入/分析允许 ORCA 额度为 0、科学执行许可关闭；其文件写入和计算成本仍按工具实际影响校验。集合或复合工具不能用一次外层调用隐藏内部 ORCA 启动。

修订版本、模型请求身份和预算占用持久化。暂停、恢复、用户等待或重新命名不清零；未知成本保留未知和预占。模型费用如可准确取得则记录，否则明确未知，不能把未知写成 0。测试环境的合成响应只用于离线验证，和真实模型计量分别报告。
