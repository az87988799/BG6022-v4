\begin{abstract}
大语言模型能够生成量子化学输入与任务代码，但从自然语言需求到可信科学结论仍受到目标歧义、计算失败、证据遗漏和成本失控的共同制约。本文以 BG6022-V4 为核心，并补充 v2/v3 的历史量化证据，结合 AutoDFT 的闭环规划与结果反思思路，以及自主多参考量子化学研究对工作流决策和电子态识别的分析，提出并实现面向 ORCA 的证据约束研究原型。系统采用唯一决策主循环，将用户目标与最低证据要求独立于执行计划保存，使用固定通用工具组织现场生成的 Python 和 ORCA 输入，并通过统一执行入口、隔离环境、累计预算与不可变产物记录约束实际操作。报告严格区分执行正常结束、科学检查通过和完整目标完成。v2 两条人工批准的成功链保留了六个真实计算节点与完整频率证据；v3 固定科学矩阵为 11/11，含真实模型参与的核心基准为 18/18 情境、37 次调用和 147,938 tokens，但任务范围与评分口径均有限。v4 早期乙醇案例完成一次自主优化与频率计算，独立开发审计支持所得构型为局部谐振极小值；有限正己烷案例完成四个候选的单点能量比较，但交付包含开发者元数据协助。最新冻结版本的七项跨任务测试产生 53 次模型调用、1,048,678 tokens 和 8 次真实 ORCA 启动，其中 7 次正常结束，完整目标完成数仍为 0/7。失败主要分布于来源规范化、逐目标条件传递、修复路线继承、上下文容量和错误证据发现。结果说明，受控执行底座与个别科学案例已有真实证据，通用自主可靠性尚未建立。本文据此给出可复核的能力边界、失败分类和后续验证方案，为闭环量子化学 Agent 的工程评价提供实践依据。
\end{abstract}

\section{引言}
电子结构计算已经成为研究分子结构、反应性与光谱性质的重要手段。密度泛函理论（density functional theory, DFT）通过电子密度描述基态多电子体系，Kohn--Sham 方案则将其转化为可实际求解的自洽场问题\cite{hk,ks}。现代量子化学软件能够执行丰富的计算，但科学问题与软件操作之间仍有显著距离：研究者需要确定电荷与多重度、选择方法和基组、生成合理结构、识别收敛问题，并判断输出是否真正回答了最初的问题。

这一距离并非仅靠自动写入输入文件就能消除。例如，几何优化正常结束，并不自动证明所得结构为极小值；一个能量值能够从文本中提取，也不证明它与所需的构象、溶剂或电子态一致；脚本完成四个候选的计算，也不能据此宣称找到了整个构象空间的最低能量。对于多参考激发态，活性空间和电子态身份又构成比程序退出码更严格的科学要求。因此，自主计算系统需要同时处理决策、执行和结论资格三个层面。

大语言模型提供了一种将自然语言、软件文档与程序生成连接起来的方式。ReAct 将推理与外部行动交替组织，Toolformer 探索工具调用的学习，Reflexion 利用反馈改善后续行为\cite{react,toolformer,reflexion}。ChemCrow 与 Coscientist 则展示了语言模型结合化学工具和实验操作的可能性\cite{chemcrow,coscientist}。这些研究为自主科学计算提供了启发，也提出了一个必须正面回答的问题：模型能够执行操作时，什么证据才足以支持它交付科学结论？

本文以 BG6022-V4 为主要设计对象，并补充 v2/v3 中可以追溯到原始计算和评测记录的量化成果。v4 选择 ORCA 作为计算核心，以 ORCA Python Interface（OPI）作为主要适配底座\cite{orca2020,orca6,opipaper}，将现场生成代码置于受管理工具边界之内。AutoDFT 是本文闭环方法的重要参照，多参考自主计算论文则为任务覆盖、方法决策和正确性评价提供了更严格的参照\cite{autodft,multirefagent}。两篇论文的共同启发是：自主性需要在中间结果出现后继续发挥作用，而科学正确性必须接受任务相关的独立审查。

本文的贡献是一个可审查的工程实现与评价报告。第一，给出单决策循环、目标独立和统一执行责任链的系统设计；第二，通过分层结果状态与不可变证据避免把运行成功直接写成科学成功；第三，结合 v2 的已批准计算链、v3 的冻结有限基准和 v4 的生成代码评测，呈现各版本已取得的成果与尚存缺口。本文不主张新的电子结构方法，也不以不同任务集之间的数字比较证明系统优越性。

\section{相关工作与研究定位}
\subsection{传统计算自动化与语言模型工具调用}
量子化学和材料计算在语言模型出现之前已经具有成熟的自动化基础。ASE 提供跨计算程序的原子体系接口；AiiDA 强调工作流执行与数据来源；Atomate2 组织模块化材料工作流；cclib 则提供计算化学输出的统一解析能力\cite{ase,aiida,atomate2,cclib}。这些系统具有各自的动态控制与恢复机制，不能简单概括为完全静态的批处理。其共同价值在于把可重复操作、软件适配和数据组织从个别计算中提取出来。

语言模型的增量作用主要是解释开放需求、在候选行动之间作选择、生成任务特定代码，并根据新证据调整路线。工具增强不意味着每种科学任务都需要一个新工具，也不意味着所有判断都应交给语言模型。本文采取职责分配：模型提出方案，程序验证权限、依赖与资源，并根据现有科学检查确定可发布的结果。化学知识、算法实现和执行许可由此具有不同来源和不同权威。

\subsection{AutoDFT：成功与失败都进入闭环}
AutoDFT 将战略规划、即时参数规划、执行、监控、恢复、步骤反思和后处理组织为七角色闭环；其 VASPBench 含 34 个任务、9 类计算。原文表 1 中，GPT-5.2 完整系统完成 32/34（94.1\%），开环与规则基线分别为 28/34 和 23/34。另有 20 个材料的性质评价，误差在成功计算上相对数据库参考统计\cite{autodft}。这些结果对应论文自己的 VASP 环境和任务定义，各配置每任务仅运行一次。

对本项目而言，最有用的设计思想是让成功结果也触发下一步决策：新的结构、谱学特征或精度缺口可能要求补算，而不是只在程序崩溃后才调用模型。本文将这种反馈原则放入一个协调者，分别实现规划、工具执行和证据评价职责。角色数不是闭环性的充分条件，单协调者同样需要证明结果确实影响后续行为。

\subsection{自主多参考计算：覆盖率与已覆盖子集精度}
Lee 与 Rondinelli 研究使用 ORCA 执行多参考计算的自主 Agent，采用 CASSCF/SC-NEVPT2 与 aug-cc-pVTZ 基组。其 558 个 QUESTDB 垂直跃迁目标中，基线、决策阶梯和完整信息复制设置分别覆盖 139、246、378 个目标，覆盖率为 24.9\%、44.1\%、67.7\%；对应已确认电子态子集的 MAE 为 0.373、0.339、0.023 eV\cite{multirefagent}。这些误差的分母随覆盖子集变化，完整信息复制也具有更强的先验输入，不能解释为所有目标上的通用自主精度。

该研究提示，执行协议正确与电子态身份正确是不同问题。CASSCF 需要明确活性空间，NEVPT2 在多参考波函数基础上补充动态电子相关\cite{casscf,nevpt2}；AVAS 等既有方法为自动构建活性轨道提供专业算法基础\cite{avas}。QUESTDB 提供高精度激发能参照，也使态归属和方法条件成为可检验的评价对象\cite{questdb}。本项目目前没有真实验收证据支持自主 CASSCF、NEVPT2 或活性空间选择，因此将这些问题作为未来科学契约扩展，而非现有能力。

\section{科学背景与评价定义}
\subsection{方法选择与科学问题的条件依赖}
固定核构型下，Kohn--Sham DFT 的电子能泛函可写为
\begin{equation}
E[n]=T_{\mathrm s}[n]+\int v_{\mathrm{ext}}(\bm r)n(\bm r)\,\mathrm d\bm r
+E_{\mathrm H}[n]+E_{\mathrm{xc}}[n].
\end{equation}
分子势能还需加上核间排斥能。交换相关近似、基组、几何和环境共同决定具体计算。PBE、Becke 杂化方案与 LYP 相关泛函提供不同近似选择；def2 基组和 D3 色散修正进一步说明方法名称之外仍有必须明确记录的设置\cite{pbe,becke,lyp,def2,d3}。本文引用这些方法作为选择空间与历史案例背景，不表示每一项都已纳入生产资格或最新评测。

激发态需要区别于基态能量。含时密度泛函理论（TDDFT）的理论基础来自 Runge--Gross 研究\cite{tddft}；所需态数、能量、振子强度和态身份均可能影响任务验收。环境比较同样需要明确连续介质模型、几何是否固定以及能量差的物理定义，CPCM 是相关方法之一\cite{cpcm}。模型可以建议这些选项，但最终报告必须披露实际执行条件，并保持用户明确要求的物理量。

构象搜索可先使用较低成本的方法提出候选。GFN2-xTB 和 CREST 展示了低成本势能描述与构象集合搜索的研究基础\cite{gfn2,crest}。本文的正己烷历史案例实际使用 RDKit/MMFF 候选和 DFT 单点，不能因为引用这些文献就声称项目使用或验证了 xTB/CREST。方法背景与本项目实际运行记录在全文中分别处理。

\subsection{执行、科学检查与目标完成}
令第 $i$ 个实际尝试的运行事实为 $X_i$，第 $k$ 个输出的科学检查为 $S_{ik}$，第 $j$ 个用户目标是否满足为 $G_j$。至少需要区分
\begin{equation}
X_i=\text{正常结束},\qquad
S_{ik}=\text{已通过规定检查},\qquad
G_j=\text{证据满足目标要求}.
\label{eq:states}
\end{equation}
三者不是同义状态。正常结束可以产生未经检查的观察；科学检查也只在所声明的适用范围内成立。一个正确单点能量无法替代用户要求的优化自由能或完整扫描图。

报告层面的完整任务判定要求所有必需目标均有足够证据，且必需交付项齐备：
\begin{equation}
C_{\mathrm{task}}
=\left(\bigwedge_{j\in\mathcal G_{\mathrm{required}}}G_j\right)
\land D_{\mathrm{required}}.
\label{eq:complete}
\end{equation}
式 \eqref{eq:complete} 是评价语义的概括，不表示所有科学问题都具有同一固定检查清单。未注册性质可作为带来源与验证说明的观察交付；是否足以满足目标仍取决于原请求的最低证据要求。

对参考能量评价，覆盖率与误差应共同报告：
\begin{equation}
\mathrm{Coverage}=\frac{N_{\mathrm{matched}}}{N_{\mathrm{target}}},\qquad
\mathrm{MAE}_{\mathrm{matched}}
=\frac{1}{N_{\mathrm{matched}}}
\sum_{i\in\mathcal M}|E_i-E_i^{\mathrm{ref}}|.
\end{equation}
其中 $\mathcal M$ 只包含可确认对应关系的目标。本文未为最新七题运行独立数值参考，不报告不存在的 MAE，也不以没有错误数值发布代替完整任务成功。

\subsection{Code as Tools 与统一 ORCA 责任链}
Code as Tools 将任务特定算法放入可审查的代码产物，而不是为每个科学问题增加一个专用求解 Tool。模型可以生成 Python，用于几何操作、有限候选筛选、数据分析或绘图；也可以生成原生 ORCA 输入。OPI 输入、原生输入和薄 SDK 内部请求最终复用受管理 ORCA 执行入口。\ev{E2,E3}

薄 SDK 的职责是请求一次受控科学计算、返回执行回执和产物引用，不隐藏构象搜索、势能扫描或其他任务求解算法。这样可以检查某项成果究竟来自现场代码、既有解析器还是开发者提供的算法。通用工具目录、参数 schema、校验和输出声明来自相同工具定义，避免模型看到的接口与真正执行的接口分离。

代码被允许访问任务输入副本、必要运行库、任务写目录和受控通信接口。访问网络、任意 shell、产品源码及执行许可均不属于生成代码的权限。程序校验决定动作是否可执行；模型或脚本输出的“通过”字段不能替代生产科学检查。

\subsection{目标条件、来源与修复语义}
Request 既保留原文，也记录条件的来源：用户明确要求、默认、继承、推断或自动选择。不同目标可以具有不同环境或电子态，例如同一初始几何的气相与水中能量比较。将这些条件压缩成一个全局设置可能改变科学问题，因此实际执行需要按目标、体系和请求的既定优先级读取条件。

计划修复也必须保持目标身份。一个步骤因 Python 语法或 ORCA 关键词错误而重写时，未改变的目标路线应继续继承；修复不能通过删除原目标来获得形式上的完成。与此同时，显式修改后的完整计划仍需核对依赖和科学条件。最新开发修复针对这类跨层不一致进行统一处理，其后续真实自主表现需要相应冻结实验，本文不在本次历史扩充中重新评价。\ev{E9}

来源校验的目的在于证明值与用户原意相符，而不是要求模型重复抄写整段文本。短引文、原文片段和规范化值之间需要统一表示与映射。无来源、跨消息错绑或明确冲突仍应拒绝；准确短引文作为同一来源的不同表示时，则不应被机械地判为冲突。这一区分直接来自最新真实失败，而不是抽象的提示工程偏好。

\subsection{不可变证据与开放观察}
每次尝试单独保存输入、脚本、标准输出、错误日志和相关产物，初始几何及历史尝试不被覆盖。外部只读引用在消费前核对 hash。读取与执行分离：缺少 JSON 或转换产物时，只读查询报告缺项；转换、分析或重算通过显式工具操作发起。\ev{E1,E3}

生产解析和科学检查沿用已有责任链。生成代码可以从原始输出提取新性质，形成通用观察，但不会由此自动获得 \code{QualifiedOutput}。这种区分允许开放分析，又保持“看见一个字段”和“科学意义被验证”之间的边界。证据索引使原始文件可发现、可有界查询，而不是要求所有内容一次进入模型上下文。该做法与科学数据可发现和可复用的原则相呼应\cite{fair}，但是否达到完整 FAIR 水平仍需要单独评价。

\subsection{隔离、资源与累计预算}
项目本地基准为 4 核、整个计算进程树 1024 MiB 内存、环境计算并发 1，ORCA MaxCore 为每进程 192 MiB。MaxCore 只是 ORCA 内部内存设置，不能替代进程树总内存限制。Linux 后端将任务 Python 及内部 ORCA/MPI 放入同一容器 cgroup，并沿用原环境租约；Windows 和 Linux 路径显式选择并冻结，失败不触发无约束后端回退。\ev{E3}

预算包括模型调用、代码重试、计划修订、内部科学计算和产物用量。对任一预算维度 $k$，令限额为 $B_k$，累计已用为 $U_k$，新动作预约为 $r_k$，执行前至少要求
\begin{equation}
U_k+r_k\leq B_k.
\end{equation}
内部子计算的实际消耗累加到父 Run；暂停、恢复或换标识不清零。执行状态未知时，先对账并保守占用资源，避免重复启动。成本采样具有可见性限制，因而报告保留“已知值”“上界”和“观测下界”的区别。

固定 Linux 环境已测试无网络、只读根文件系统、受控 UID、seccomp 与移除 capabilities 等边界。\ev{E3}这些是特定软件与宿主组合的实际证据，不能推导为任意环境上的安全证明；每 Attempt 磁盘硬配额等限制也仍需披露。

\section{讨论}
\subsection{从局部可执行到自主交付的断层}
结果支持一个有限但清晰的判断：统一执行入口、隔离计算和部分生成代码路径已经获得真实证据；完整跨任务自主性仍有明显断层。早期乙醇正例说明模型可以在特定条件下完成有意义的路线，最新 T3/H1 说明新版本可以产生真实计算，但这些事实不能相互替代。开发阶段、模型、提示和任务暴露程度变化后，需要重新建立完整证据。

失败可分为四类。第一类是语言到契约的映射错误，如有效短引文被重复来源规则拒绝；第二类是已规范化条件未传到执行路由；第三类是修复和产物到目标的绑定丢失；第四类是反馈发现与容量失败，使后续行动缺少必要事实。它们不同于 SCF 不收敛，但同样决定最终科学任务能否完成。将所有失败归为“模型能力不足”或“量子化学难”都不足以指导修复。

\subsection{闭环应由证据驱动，而非由角色数量定义}
AutoDFT 为中间结果影响后续计划提供了方法参照，自主多参考研究则使态身份和任务覆盖成为必要评价维度。本文据此选择在一个循环内保留这些决策职责，通过 Tool 分隔执行权限。该选择符合项目单协调者约束，也有利于观察每次行动的授权和预算来源。

但单协调者并不天然更可靠。若上下文构建重复装入协议、历史正文与证据目录，一个循环同样可能在重要结果返回后失败；若条件 schema 与消费实现不同步，较少角色也不能防止错误。本文没有单 Agent 与多 Agent 的受控对照，因而将这一架构作为经过实现的设计取舍，而非已证明的性能优势。

\subsection{科学资格应随证据增长，不能随文字升级}
对于乙醇，独立 Hessian 和结构复核支持局部结论；生产输出仍保留原有资格状态。对于正己烷，四个单点只支持相应候选子集的电子能比较。对于 HCN，屏蔽张量存在只表明数据生成，尚未完成该任务要求的核对。三者展示了不同证据层次，也说明结果应注明“已执行到哪里、已检查什么、还有什么未知”。

开放观察可以扩展研究范围，但不能成为绕开科学要求的通道。若未来增加激发态、活性空间或更复杂性质，需要局部契约明确态身份、方法适用性、数值检查和参考依据。生成代码的自我声明、LLM 的解释流畅度以及正常退出码都不足以单独承担科学认证。

\subsection{反馈开销与约束复杂度}
资源限额限制最坏消耗，反馈质量则影响有限预算如何被使用。T4 的错误窗口没有及时呈现，使模型在错误文件之间往返；T3/H1 的上下文容量失败又发生在计算已有产出之后。由此可以提出后续可检验假设：统一当前错误入口、保留必要目标和可查询引用、去除已失效正文，有望提高同一预算内的有效行动比例。该假设仍需新冻结候选的真实运行检验，本文没有实测的 token 节省率。

另一方面，约束自身也可能成为失败来源。有效来源被错误拒绝或结构准备被要求提供无关科学条件，会降低可完成性；完全移除来源、条件和预算检查又会失去目标忠实性与执行边界。合理修复应减少重复表达和不一致消费，同时保留实际需求、科学检查、隔离与累计预算。

\subsection{有效性威胁与当前限制}
内部有效性首先受版本变化和开发者参与影响。历史正例、辅助案例和正式冻结测试应单列；v78 离线修复提交不替代新的真实实验。v2 的逐节点批准、v3 的自动确认脚本与固定题目、v4 的生成代码任务具有不同自主边界。外部有效性受任务数量、反复暴露、本地小体系和单一计算环境限制，本文未纳入真实集群证据。

构念有效性取决于指标定义。ORCA 启动、正常结束、观察来源通过和完整目标是不同计数单位；以其中一个代替其他指标会改变结论。成本则受到采样下界、供应商账单缺失和版本差异限制。安全方面，固定容器测试不能证明所有宿主、依赖或恶意脚本下均安全；每尝试磁盘硬配额仍未提供完整覆盖。

统计有效性也有限：七题各一次不足以估计稳定成功概率，四批不同候选的 28 次尝试更不是同版本重复；没有共同任务集和统一资源条件，不能与两篇重点论文的成功率或 MAE 排名。这些限制决定本文应被理解为研究原型的最终阶段报告和失败分析，而非产品成熟度认证。

\section{后续研究与验证方案}
v78/决策 0057 的修复包括统一短引文和值映射、按目标消费科学条件、同逻辑修复继承路线、去重反馈上下文和直接暴露内部 ORCA 失败，已另行提交。\ev{E9}这些变化针对已观察根因；已有离线回放不能把旧批次改判成功，也不能提前证明新版本的实际成本改善。本次报告扩充不对后续新候选作重新验收。

下一步应在修复稳定后冻结产品、提示、配置与评价脚本，按原任务逐项运行并保留全部结果。对每题同时报告计算前停止、实际启动、科学检查、部分完成和完整交付；对进入科学结果阶段的任务建立独立参考或确定性复核。对于扫描，检查实际几何角度、端点和必要图；对于环境比较，检查相同几何与环境条件；对于张量性质，检查单位、坐标和旋转关系。

之后再增加同版本重复和新的未暴露任务，观察可靠性分布，而非持续针对原七题调整后宣布通用。模型与规则的消融应在同任务、同预算下进行，区分代码生成、反馈组织和科学检查的贡献。未来多参考扩展则需先明确活性空间和态身份契约，再以可靠参考子集评价覆盖率和条件误差。上述内容是验证建议，不表示本次已经启动计算或获得新执行授权。

\section{结论}
本文以 BG6022-V4 为核心报告自主量子化学计算的系统设计，并补充 v2/v3 的量化历史。v2 为真实计算链与可重解析科学证据提供基础，v3 展示有限已定义任务上的组合执行、模型参与及有界修复，v4 进一步探索现场生成代码与开放目标。v4 通过七对象模型、唯一决策循环、统一 ORCA 入口、隔离执行和不可变证据建立可审查责任链。各版本成果均按实际方法、人工参与和评测口径保留，不自动继承为后续版本的验收结论。

最新七题产生真实计算而完整目标仍为 0/7，表明计算基础设施的可用性尚未转化为可靠的通用自主交付。来源、条件、修复绑定、上下文和错误证据之间的一致性是当前主要瓶颈。借鉴闭环 DFT 与自主多参考研究，后续进展应以同版本完整任务、独立科学检查、重复试验和新任务证据衡量。报告交付不代表项目能力已验收通过，当前结论与新修复均等待用户验收。
