打通以下本机流程：

```text
自然语言需求
  → 确认分子、目标与条件
  → 自主选择方法、查阅资料、形成计划
  → 生成 Python 和 ORCA 输入
  → 受管理地执行 Python / ORCA
  → 读取结果、修复错误或补充计算
  → 输出分析、文件、证据与验证说明
```

核心验收目标：**同一个冻结版本面对不同计算任务，能够现场生成不同程序完成计算，无需开发者新增科学工具、生产解析器、性质端口或预写解题脚本。**

用户已确认的设计方向：

- 允许执行 Agent 生成的任务 Python 与 ORCA 输入。
- 没有专用科学检查器也可以计算和交付，必须说明验证覆盖与限制。
- 未指定的方法、基组和常规计算步骤由 Agent 选择并说明依据。
- 授权预算内可以修复、补算；关键歧义、改变明确条件或超出许可时才请求用户决定。
- CPU、内存、并发、时限及各类调用预算做成配置。
- 主要入口为自然语言，不要求用户先准备 XYZ、Plan 或计算脚本。

本轮保留单 Agent、七个领域对象、文件存储、统一执行管理和现有本地界面。远程集群、多 Agent 产品架构、数据库迁移、自动安装任意依赖和全部 ORCA 功能保证均不在本轮范围内。

| 能力 | 最小职责 |
| --- | --- |
| 工作区文件读写与发现 | 保存脚本、输入和派生产物；有界读取日志与证据；已有归档不可覆盖 |
| 文档检索与读取 | 查询版本明确的 ORCA、OPI、RDKit 资料，保留出处 |
| 身份查询与结构准备 | 复用现有查询入口；生成代码可调用固定科学库构建和处理结构 |
| `python.execute` | 运行任务代码，记录代码版本、输入、输出、错误与资源 |
| `orca.run` | 校验执行影响与依赖，启动 ORCA，管理预算、取消、收集与对账 |
| 状态与控制 | 复用当前 Run 的查询、暂停、取消、恢复 |

Python 可现场实现搜索、循环、筛选、拟合、解析和绘图。项目不增加 `hexane_search`、`torsion_scan`、`uvvis_solver` 等任务工具。SDK 也不能隐藏这类预写求解流程。

生成代码通过薄 SDK 请求 ORCA；SDK 与直接 `orca.run` 使用同一执行入口。模型和脚本不能直接调用项目内部 Store、CLI 或绕过管理层启动 ORCA。仅靠 Python 层禁用 `subprocess` 不构成隔离。

### 3.2 七对象的承载方式

| 对象 | 本轮承载内容 |
| --- | --- |
| Request | 用户原文、目标、明确条件、自动选择范围、最低证据与交付要求 |
| Plan | 取证路径、步骤、选择理由及后续可能需要的反馈决策 |
| Step | 代码执行、计算、查询或分析；绑定确定的代码和输入版本 |
| Tool | 固定通用实现、参数、影响、校验、预算与输出契约 |
| Run | 单协调者、配置快照、累计用量、尝试和内部计算记录 |
| Result | 执行事实、证据观察、逐项检查、分析产物与目标满足情况 |
| Artifact | 脚本、输入、几何、日志、表格、图片、检查点和原始输出 |

内部计算回执、候选清单和检查项是局部记录，不引入新的领域生命周期或隐藏子 Agent。

### 3.3 结果可信度

- 执行完成、科学检查通过、目标满足和报告生成分别记录。
- 脚本返回的 `passed` 或模型判断不授予科学资格。
- 通用数值记录名称、值、单位、实际条件、源文件/位置/hash、生成脚本 hash 和检查覆盖；缺失信息保持未知。
- 没有专用检查器时，可按请求约定完成带验证说明的交付；用户明确要求的最低科学证据仍须满足，否则为部分完成或证据不足。
- `QualifiedOutput` 继续保留严格含义。旧结果保留原检查版本，不能因新功能上线自动升级。

## 5. 跨任务验收矩阵

### 5.1 科学任务

自然语言以下列目标为准，运行时输入原文须在正式验收前冻结。资源规模由预算约束；不能在看到失败后静默缩小必需目标。

| 编号 | 自然语言任务 | 证明的能力 | 独立核对重点 |
| --- | --- | --- | --- |
| T1 | 生成乙醇结构，选择方法，优化并分析振动频率 | 身份、结构、自动选择、完整计算流程 | 实际输入、结构身份、收敛、频率与结论；缺少专用检查的标记 |
| T2 | 搜索正己烷的低能构象，给出最低候选、能量排名和搜索限制 | 新算法、多候选、多次 ORCA、去重与排序 | 候选来源、失败成员、方法一致性、重复结构和有限搜索边界 |
| T3 | 扫描正丁烷中心二面角，画能量曲线，根据结果决定是否局部加密 | 参数化生成、约束计算、成功反馈决策 | 点位、约束、能量来源；不同观察与无需加密的配对行为 |
| T4 | 计算丙酮若干低能电子激发，列出激发能、振子强度并分析 | 新计算类型、新字段、生成代码解析 | 态编号、单位、原始响应输出；不能以轨道能隙冒充激发能 |
| T5 | 比较同一分子在相同几何和方法下的气相与隐式水环境电子能 | 条件保持、跨结果派生量、解释 | 两次条件、差值及符号；不将电子能差命名为水合自由能 |
| H1/H2 | 冻结后选择的两项未参与开发任务 | 对新需求的泛化 | 禁止只换分子名称复用预写完整流程；按任务提前确定参考和容差 |

五项公开任务加两项保留任务，至少形成 21 组独立正式运行；额外的参考、配对反馈、故障和恢复测试单独计费计时。T1/T2 开发调试结果不替代冻结后的正式运行。

### 5.2 必须覆盖的反例与控制任务

| 场景 | 必须表现 |
| --- | --- |
| 代码语法、库调用或文件错误 | 返回真实诊断，生成有效修改；重复无效修改或预算耗尽时停止 |
| 真实 SCF 失败与修复耗尽 | 至少一例真实失败经真实重跑修复；另例耗尽后保留失败与成本；明确条件不被偷改 |
| 无专用检查器或字段缺失 | 保留原目标，说明检查缺口；不伪造数值或科学通过 |
| 用户明确要求自由能或更高证据 | 电子能或较弱证据不能替代；无法完成时准确标明部分完成 |
| 成功结果反馈 | 不同观察触发不同合理后续动作；充分证据时停止 |
| 只读查询与缺少 JSON | 返回已有事实或缺项，不自动执行 Python、转换或 ORCA；审计写入可以存在 |
| 明确要求绘图或后处理 | 作为有记录的执行；未要求科学补算时 ORCA 启动数为零 |
| 崩溃、启动响应丢失、取消与恢复 | 先对账、无重复启动、累计预算不清零、原始证据不覆盖 |
| 双 Run 及 Python 等待 ORCA | 环境额度有效；总内存受约束；无锁或并发槽死锁 |
| 越界访问、网络或原生执行绕过 | 被真实执行边界阻断，留下诊断；不只依赖提示词或 Python monkeypatch |

默认测试继续离线。真实模型与真实 ORCA 沿用显式开关；允许科学测试不等于开放任意网络或可执行文件。操作系统隔离、后端子进程和真实科学测试分别记录。

## 6. 完成标准与报告格式

### 6.1 必须同时满足的完成标准

- [ ] 从自然语言到代码、真实 ORCA 和分析交付的链路可由产品自行完成。
- [ ] 正式任务之间无需开发者新增工具、生产解析器、性质 schema、任务求解函数或解题提示。
- [ ] 同一冻结候选版本上，7 项任务各完成至少 3 次独立运行，各次均达到预先冻结的目标与独立评分标准。允许预算内自主修复后通过；首次失败、修复和最终失败全部进入统计，保留任务同样计入。
- [ ] 执行、检查和目标状态准确；明确科学条件、原始证据和未知情况未被伪造或降级。
- [ ] 成功反馈再规划、真实失败修复、有界停止、恢复与环境级资源约束都有对应证据。
- [ ] 第 5.2 节的强制边界和故障场景通过；越权执行、证据覆盖、重复启动或把未验证写成科学通过等问题不能用平均成功率抵消。
- [ ] 代码、脚本、输入、输出及版本可追溯；关键结论可独立核对。

三次重复只构成本轮工程验收样本，不构成稳定成功率估计。某次未达到标准时如实报告该任务未通过，不通过删除失败、挑选额外成功运行或事后降低要求来满足门槛。

### 6.2 每个任务的报告内容

1. 用户原文、固定条件、自动选择及依据。
2. 产品版本、模型与程序版本、配置及资料来源。
3. 首次结果、修复过程、最终结果、失败/部分完成/未验证项。
4. 生成脚本、实际输入、原始输出、结构、表格和图的可核验索引。
5. 执行成功、独立评分、科学检查覆盖、目标完成和报告完成的分别判断。
6. 模型调用/token、ORCA 启动与内部工作量、重试、时长和实际资源；未知成本明确标注。

能力结论只覆盖实测任务分布。通过本矩阵可证明在这些任务上具备无需新增工具的计算能力，不直接表述为已经验证 ORCA 大部分功能。
