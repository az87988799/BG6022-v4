# 精确补丁生成新任务文件

`workspace.write` 保留 `{name, content, role}` 的完整文件写入形式，也接受显式 Python 基础 Artifact 与精确替换列表。两种形式互斥；补丁不修改原 Artifact，也不执行 Python。

```json
{
  "name": "repaired.py",
  "role": "python",
  "base": {
    "artifact_id": "已授权基础文件的实际ArtifactID",
    "sha256": "基础文件的完整64位SHA256"
  },
  "edits": [
    {"old": "threshold = 1.0\n", "new": "threshold = 0.5\n"}
  ]
}
```

示例中的身份与 hash 必须替换为实际回执值。`base` 使用原有 CodeRef，语言须为 Python；不接受宿主文件路径、最新文件、模糊匹配或未来未结算文件。

每个 `old` 必须非空并在同一份原文中恰好出现一次；多个片段不能重叠。全部替换位置根据原文确定，新插入文本不会成为后续替换的输入。相邻片段可以替换；删除用空 `new`。单项相同或整体字节不变的补丁均拒绝。最多 16 项替换，每个 `old`/`new` 最多 16384 字符；基础文件和最终文件均须为无 NUL 的 UTF-8 文本，最多 65536 字节。保留未替换内容及换行形式。

程序在预留写入额度前检查基础文件权限、已结算来源、固定 hash 和替换规则。写入时重新读取并核验 hash，防止预检后文件变化；预留后失败仍保留失败回执和已计成本。授权来自 Run 原许可或同 Run 的已结算、验证来源，文件仅带同 Run 身份不构成授权。

成功后返回新的 Artifact ID/hash，原文件与 hash 保留。后续 Python Step 使用新 CodeRef，仍经过原有输入授权、hash、执行隔离、修复和累计预算检查；生成新文件不改变科学资格或旧结果。

离线测试 49 项通过，覆盖完整写入的旧三字段序列化、独立 schema 互斥检查、精确替换、UTF-8 边界、预留前拒绝、读取竞态与后续 CodeRef 校验。合成长脚本案例中，完整写入请求 JSON 为 50468 字节，精确补丁请求为 249 字节，均按 UTF-8 计算；该指标不表示实际模型 token、费用或质量改善。测试没有启动任务 Python、模型或 ORCA。
